# Локалізація текстів у 1С

## Коли застосовувати

- Конфігурація чи розширення має кілька мов (ru, uk, …), а ти пишеш або правиш тексти: повідомлення людині,
  помилки й відповіді API чи AI-агенту, синоніми, заголовки форм і команд.
- Користувач бачить суміш мов або текст не тією мовою: «у російському інтерфейсі прийшло українською» чи навпаки,
  кнопка чи команда форми не перекладена.
- Перед комітом і PR змін у вихідниках 1С.

**Принцип.** Текст для людини йде мовою її сеансу. У коді це `НСтр` з усіма мовами конфігурації, у метаданих і
формах — багатомовний рядок з усіма мовами. Одна мова рядком — вада, навіть коли «так зрозуміліше».

**Спершу з'ясуй, хто читає текст.**

| Читач | Мова | Приклади |
|---|---|---|
| Людина в 1С | мова сеансу, `НСтр` | форма, повідомлення, журнал реєстрації |
| Програма чи AI-агент (API, MCP, обмін) | одна фіксована мова з контракту, без `НСтр` | помилки й підказки API, відповіді інструментів |

Агент — модель. Мова службового тексту на його роботу не впливає, а залежність від сеансу лише ускладнює тести й
поведінку. Фіксована мова — та, що в контракті інтерфейсу. Англійська не містить кирилиці, тож перевірка її не
позначає. Фіксовану кириличну мову позначай коментарем `// без НСтр: текст для агента`.

## Діагностика «не та мова»

Текст прийшов не тією мовою — шукай текст, що **ігнорує** мову сеансу, а не той, що за нею йде.

| Що бачить людина | Причина | Виправлення |
|---|---|---|
| Частина текстів однією мовою, частина іншою | частина написана рядком без `НСтр` | `НСтр` з усіма мовами для всіх |
| Кнопка чи команда форми — ім'я ідентифікатора (`ПроверитьКод` → «Проверить код»); у мові ідентифікатора вада не видна | у команди немає `Title` | `Title` з усіма мовами |
| Синонім об'єкта однією мовою | у `Synonym` бракує `v8:item` мови | додати `v8:item` |

**Ніколи** не лагодь суміш мов, замінюючи `НСтр` рядком однієї мови. `НСтр`, що дав мову сеансу, працює правильно.

## Як писати

```bsl
// Текст зі змінними — СтрШаблон над НСтр, не конкатенація.
Сообщение = СтрШаблон(НСтр("ru = 'Параметр ""%1"": значение не соответствует формату.';
	|uk = 'Параметр ""%1"": значення не відповідає формату.'"), Имя);
```

- Апостроф у тексті подвоюється: `ім''я`.
- Наявний текст лишай дослівно; переклад на інші мови пишеш сам і в звіті просиш людину переглянути його.
- Правиш файл — зберігай його кодування й кінці рядків (вихідники 1С зазвичай UTF-8 з BOM і CRLF). `sed -i` на
  Windows знімає CR; після правки перевір `git ls-files --eol -- <файл>`.
- Не для людини (текст запиту, ключ, ідентифікатор, уривок повідомлення платформи для розпізнавання) — рядок з
  коментарем у тому ж рядку: `// без НСтр: <причина>`.
- Розпізнаєш помилку платформи за уривком її тексту? Платформа пише мовою сеансу. Уривки однією мовою не
  спрацюють в іншій, тож перевір наживо в сеансі кожної мови.

## Перевірка

```bash
pwsh -NoProfile -File "${CLAUDE_PLUGIN_ROOT}/skills/1c-localization/scripts/check-localization.ps1" <корінь> [<корінь> ...]
```

Корінь — тека з `Configuration.xml` і `Languages/` (`cf/src`, `cfe/src`). Ловить: багатомовний рядок без мови,
`НСтр` без мови, фразу для людини поза `НСтр`, команду чи поле форми без заголовка. Код виходу 1, якщо є знахідки.

- Передавай **лише свої корені**. Код вендора дає тисячі знахідок і не твій.
- Без аргументів скрипт бере всі корені під поточною текою, крім `build`, `temp` тощо. Наприкінці він друкує
  підсумок по кожному кореню.
- Скрипт — евристика: шукає кириличну фразу від двох слів із малої літери. Однослівний текст (`"Ехо"`) він не
  бачить. Тож читай свій diff і не вважай «0 знахідок» доказом.
- Правило аналізатора BSL `MultilingualStringHasAllDeclaredLanguages` (Уніка: `unica.check {at}` модуля, скіл `unica:code-diagnostics`) перевіряє
  лише повноту `НСтр`, а не текст поза ним. Повна перевірка «рядок не локалізовано» є лише в 1С:АПК (діагностика 1297).

**CI проєкту.** Скрипт у плагіні — джерело. У репозиторій кладуть копію, бо CI не бачить плагін. Копію не правлять:
міняють скрипт у скілі `v8storagekit:1c-localization` і копіюють заново. Крок CI:
`pwsh -NoProfile -File tools/check-localization.ps1 <свої корені>`.

## Типові помилки

- Текст для людини написано рядком однією мовою. Потрібен `НСтр` з усіма мовами.
- Тексти для агента переведено на `НСтр` «для порядку». Агент отримує суміш мов залежно від користувача, а
  кожну мову треба тестувати окремо. Тексти для агента пиши однією мовою з контракту.
- Пошук знайшов лише неповні переклади, а відсутні заголовки пропустив: команда без `Title` не має жодного
  `v8:item`, тож шукати треба відсутність заголовка.
- «Перевірка чиста» без негативного контролю. Дай скрипту підставний модуль або форму з вадою й переконайся, що він
  її знаходить.
