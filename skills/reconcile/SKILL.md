# reconcile — людина перенесла частину роботи в сховище

Історія гілки задачі `F` лишається цілою: не rebase, не re-derive. Дерево джерела сховище
**заміняє**, а не зливає з ним, — людина кладе у сховище свою версію, можливо взявши лише
частину роботи агента, і merge лишив би в гілці те, чого вона свідомо не взяла (спека
2026-09-17 §5). Прев'ю `adopt` показує ціну заміни заздалегідь: що прийде зі сховища і що
зникне з гілки. Скільки завгодно раундів.

Ланцюжок: onboarding → sync → provision → (робота в Unica) → **reconcile** → finish → verify.

## 1. Передумови

- Поточна гілка — гілка задачі `F` (не головна, не `storage/*`): `git branch --show-current`.
- Робоча копія чиста або зміни закомічені в `F` (`git status --porcelain`).
- Людина сказала, які джерела торкнула (або всі `truth: storage` воркспейсу).

## 2. Кроки

1. **Нові версії зі сховища → дзеркало.** Спершу прев'ю; `-Apply` — **лише на явне прохання**.
   Те, що людина щойно комітила у сховище, — це контекст, а не дозвіл: вона сказала, що зробила,
   а не що робити далі. Показати прев'ю і спитати:
   ```
   pwsh -NoProfile -File "${CLAUDE_PLUGIN_ROOT}/tools/kit.ps1" sync -RepoRoot . -Source <ключ> -Apply
   ```
   Якщо після цього в Windows-копії `pull`/`checkout` падає з «would be overwritten» — це
   перейменування регістром кириличного імені у версії вендора, не пошкодження. Вихід —
   `git fetch` і `git reset --hard origin/<гілка>` (`<гілка>` — поточна, на якій упала команда)
   або свіжий клон, але лише коли `git status` чистий **і** `git log origin/<гілка>..HEAD` порожній
   (інакше reset відкине непушені коміти). **Агент reset не виконує:** показує людині `git status`
   і ці дві перевірки та чекає її рішення (`docs/storage-and-git.md`, «Перейменування регістром»).
2. **База агента — з поточного дерева `F`**: виконати крок, який `sync` надрукував у кроці 1 для
   цього набору («Далі — вирівняти пам'ять раннера …»). На гілці задачі це
   `unica.run {"op":"push","args":{"sourceSet":"<ключ>","force":true},"dryRun":true}` — повне
   завантаження гілки задачі в базу, кеш Уніки участі не бере. Звичайний `push` тут не годиться:
   набір з незміненим деревом гілки він пропускає без звірки покоління (відповідь
   `infobase_state_unverified`) — це й був дефект #25 (у 1.4.0 крок мовчки відповідав `skipped`, і
   прев'ю `adopt` виходило хибно порожнім). Від #25 захищає саме надрукований крок; якщо його таки
   пропущено, діє сітка з `v8storagekit:using-v8storagekit` (`infobase_state_unverified` → `push` з
   `"force":true`). Якщо `sync` нових версій не приніс, кроку він не друкує — база не зрушена, і досить
   звичайного `push`, коли дерево `F` змінювалось. Рядок `ЗУПИНКА: …` наприкінці виводу `sync` —
   зупинка: кроки 3–5 не виконувати, доповісти людині.
   Три приводи для кроку, не один: (а) `canon` переписує дерево з бази, і без свіжого завантаження він
   знищить незакомічене; (б) крок 1 (`sync`) щойно лишив базу у стані версії сховища — це контракт,
   а не збій (спека 2026-09-17 §4); (в) канонізація робить прев'ю кроку 4 **семантичним** — див.
   нижче. Якщо крок таки пропущено, незбережене лежить у `<workPath>/canon-backup/<ключ>-<час>/` —
   `canon` копіює його туди й друкує шлях. Це шлях відновлення, а не привід пропускати крок.
3. **Канонізація дерева агента**:
   ```
   pwsh -NoProfile -File "${CLAUDE_PLUGIN_ROOT}/tools/kit.ps1" canon -RepoRoot . -Source <ключ> -Apply
   ```
   Якщо `canon` змінив файли — закомітити в `F`, не `git commit -am`:
   ```
   git rm -r -q --cached -- <шлях джерела>
   git add -- <шлях джерела>
   git diff --cached --name-only
   git commit -m "canon: дерево у форматі платформи"
   ```
   `git diff --cached --name-only` мусить показати лише шлях джерела. Без `-a` — він не додає нових
   файлів; без `--only` — той воскрешає фантом, коли канон змінив лише регістр імені
   (`docs/storage-and-git.md`, «Перейменування регістром»).

   **Крок не марний, хоч крок 4 і замінить це дерево.** Після переходу на дамп у базі агента
   канон і дамп дзеркала — один формат, тож саме канонізація робить прев'ю `adopt` семантичним:
   у списку «прийде зі сховища» лишається робота людини, а не різниця форматів. Без неї туди
   потрапив би формат Unica — той самий шум, який прибирали зі `verify`, лише перенесений у
   `adopt`. **Раніше цей крок тут був би шкідливим** (канон давав інший формат, ніж дзеркало, і
   додавав би розбіжностей) — причина перевернулась, не зникла.
4. **Прийняти версію сховища в `F`** — прев'ю, потім заміна:
   ```
   pwsh -NoProfile -File "${CLAUDE_PLUGIN_ROOT}/tools/kit.ps1" adopt -RepoRoot . -Source <ключ>
   ```
   Прев'ю називає **три** списки: що **прийде зі сховища**, що **зникне з гілки** — робота
   агента, якої людина у сховище не взяла; показати його людині **до** заміни, бо саме вона
   вирішує долю цієї роботи, — і окремо **лише CR** (зіпсована політика тексту,
   `docs/text-policy.md`). З її згодою — той самий виклик із `-Apply`.

5. **Звіт людині**: що поглинуло сховище (перший список прев'ю) і що лишилось поза ним (другий).
   Порожні всі три — дерево вже збігається зі сховищем, `adopt -Apply` не зробить коміту;
   непорожній лише список «лише CR» усе одно означає, що заміна відбудеться — вона виправить
   і зіпсовану політику тексту. Після `adopt -Apply` база вже вирівняна кроком 2 — звичайний
   `push` Уніки довантажить прийняте дерево.

## 3. Штатні зупинки

- `sync`: див. `v8storagekit:sync` (невідомі автори, недоступне сховище).
- рядок `ЗУПИНКА: …` наприкінці виводу `sync` — зупинка з доповіддю людині, далі не йти.
- `canon`: `Бази агента ще немає … v8storagekit:provision` — спершу `v8storagekit:provision`;
  `База агента воркспейсу '…' не налаштована` — теж `v8storagekit:provision`; `збігається з
  дев-базою людини` — kit не пише в базу людини.
- `adopt`: `Гілки '<ключ>' немає` — дзеркало ще не створено, спершу `kit sync -Source <ключ> -Apply`.

## 4. Межі

Сховище — тільки читання; реплей — лише через `sync`. Kit не пише в базу людини. `-Apply`
(і `sync`, і `canon`, і `adopt`) — лише на явне прохання: те, що людина розповіла про свій коміт
у сховище, проханням не є. У головну гілку тут не зливаємо (звірочні коміти —
`v8storagekit:verify`). Нічого не пушити.
