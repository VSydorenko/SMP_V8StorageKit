# Виміряна поведінка WebSocket у 1С

Умова для всього, якщо не сказано інше: платформа 8.3.27.1644, серверна база, розширення з режимом сумісності
8.3.17, БСП 3.1.7. [В] — виміряно, [К] — так працює код у продукті, [Г] — гіпотеза.

## Сеанси обробників

| Що | Поведінка |
|---|---|
| Хто виконує обробник | Окремий сеанс, застосування «WebSocket», `ИмяПользователя()` — ім'я з `ОткрытьСоединение` або `ИмяПользователяИнформационнойБазы` клієнта; діють ролі й RLS цього користувача, `ПривилегированныйРежим() = Ложь` [В] |
| `ПередПодключением(Клиент)` | У сеансі того, хто викликав підключення [В] |
| Життя сеансу | Закривається після ~20 с простою; наступне повідомлення піднімає новий. Тепле повідомлення ~10 мс, холодний старт 4–12 с, після рестарту служби 1С до ~7 с [В] |
| Ініціатор завершився | З'єднання живе далі [В] |
| Без імені користувача | Порожній `ИмяПользователя()`, `РольДоступна("ПолныеПрава") = Истина` [В] |
| Неіснуючий користувач | TCP відкрито, обробник жодного разу не викликано, помилки немає [В] |
| Заблокований користувач («Вход в программу разрешен» знято) | Сокет відкривається, сеанс не стартує (`_$Session$_.Finish` кожні ~5 с без `Start`), платформа повторює ≥1,5 хв [В] |
| Без стандартної автентифікації | Сеанс стартує й одразу завершується, обробник не викликається, у ЖР нічого [В] |
| Перевірка прав ініціатора | Немає: будь-який серверний код, зокрема без прав на дані й у безпечному режимі, відкриває з'єднання від імені `Администратор` [В] |
| Ключ з'єднання | Глобальний: повторний `ОткрытьСоединение` з ключем живого з'єднання нічого не робить і винятку не кидає — нового сокета сервер не бачить, старе живе; так і з іншого сеансу, і двічі підряд в одному [В, 02.11.2026]. Для каналу користувача — унікальний ключ на відкриття; для постійного каналу — фіксований (захист від дублів) |
| Параметри для обробника | `ПараметрыWebSocketКлиентСоединения.ДополнительныеПараметры` (Структура) → `Соединение.Параметры.ДополнительныеПараметры` у сеансі власника [В] |

## Динамічне з'єднання з фонового завдання (02.11.2026)

Відкрито `ОткрытьСоединение` від службового користувача у фоновому завданні; стан читав інший сеанс; закриття — за
логом сервера.

| Що | Поведінка |
|---|---|
| Завдання завершилось (52 мс) | З'єднання `Открыто` через 0 і 8 с після його кінця [В] |
| Інший сеанс | Бачить з'єднання в `ПолучитьСоединения()` за ключем [В] |
| `Закрыть()` з іншого сеансу | «Закрывается» → за ≤3 с з'єднання немає; сервер бачить `1000` від клієнта [В] |
| Сервер закрив (4408) | У наступному читанні з'єднання немає [В] |
| Обробники в такому з'єднанні | Не міряно: з'єднання відкривали без обробників [Г] |
| Вартість | Фонове завдання з порожньою функцією 41–52 мс; тіло перевірки каналу ~2 мс [В] |

## Режими збою збереженого клієнта (інцидент 29.10–02.11.2026)

| Режим | Поведінка |
|---|---|
| «Зомбі» | Сервер закрив з'єднання за heartbeat (1006), у ЖР бази ні `ПриЗакрытии`, ні `ПриОшибке`; стан `Открыто` 4 і 28 год, жодної спроби [В] |
| Вихідний кадр у «зомбі» | `ОшибкаКанала 10054/995` і `ПриЗакрытии 1005` у ту саму секунду [В, одне спостереження] |
| Тиша | Стан `Закрыто`, `ПодключатьАвтоматически = Истина`, сеанс обробника завершився без `ПриЗакрытии`; ~21 год без спроб. `Подключить()` повернув за ~5 с [В] |
| Невидимий клієнт | В одній базі `ПолучитьКлиентов()` порожній і `НайтиПоКлючу` = `Неопределено` при повних правах, хоча `ПолучитьСоединения()` показує живе з'єднання цього ключа. Причину не з'ясовано [В] |

## Збережений клієнт і стани

| Що | Поведінка |
|---|---|
| Об'єкт метаданих у розширенні | Приймається платформою (`WebSocketClient`, Designer XML 2.20) [В]. Чи приймає його `unica.check` — не перевірялось [Г]; відмова валідатора тут — прогалина валідатора, а не заборона платформи |
| `Predefined = true` / `AutoConnect = true` у метаданих | Не перевірялось [Г]; перевірено `false/false` у метаданих і `ПодключатьАвтоматически = Истина` кодом |
| Властивості стану | `Подключен`/`Состояние` немає; стан — `Клиент.ПолучитьСостояниеСоединения()` [В] |
| «Открывается» | Клієнт між плановими спробами (фізичного сокета немає); відправка в цьому стані піде в НАСТУПНЕ з'єднання [В] |
| «Закрыто» | Після явного закриття чи невдачі; `ОтправитьСообщение` кидає виняток [В] |
| Кадри під час перевідкриття | Доходять у наступний сокет: об'єкт прив'язаний до ключа клієнта. Повторного `ПриОткрытии` на одному сокеті немає [В] |
| На відхиленому TCP (10061) | `ПриОткрытии` не викликається [В] |
| `Подключить()` у «Закрыто» | Підключає за ~1 с [В] |
| `Подключить()` у «Открывается» | Нічого не робить: ні позапланової спроби, ні дубля, навіть при подвійному виклику [В] |
| `Подключить()` на відкритому | Нічого не робить, живе з'єднання не рветься [В] |
| `Записать()` звичайним користувачем | «Недостаточно прав доступа» [В] |
| `Подключить()` звичайним користувачем | Без винятку прав [В] |

## Автоперепідключення збереженого клієнта

Лише коли все гаразд — див. «Режими збою» вище.

| Що | Поведінка |
|---|---|
| Ритм | ≈1 хв (57–67 с), зокрема за коду 10061 і 502 проксі [В] |
| Після рестарту сервера, деплою, рестарту служби 1С | Повернення ≈58–66 с без дій [В] |
| Сходинки паузи | 1 → 4 → 16 хв спостерігались; початок збігся з винятком в обробнику [В спостереження], причина [Г] |
| Після винятку в обробнику | Жодної спроби ≥76 хв [В] |
| Після серії закриттів із `ПриОткрытии` (без винятку назовні) | Жодної спроби ≥5 хв до ручного `Отключить`/`Подключить` [В, одне спостереження] |
| Після явного `Подключить()` | Пауза скидається [В] |
| Динамічні з'єднання | Не перепідключаються; після розриву — `ПриОшибке` (10054) [В] |

## Коди й кадри

| Що | Поведінка |
|---|---|
| `КодЗакрытия` в обробнику | Завжди 1005, незалежно від коду сервера (109 закриттів, зокрема 4400, 1012) [В] |
| `Соединение.Закрыть()` | Коду закриття не приймає [В] |
| Вихідний кадр | 1 MiB − 1 KiB відправлено [В] |
| Вхідний кадр | 1,5 MiB прийнято й оброблено; вище не міряли [В] |
| ping/pong | Платформа відповідає сама за ~1 мс, без виклику обробника і без сеансу [В] |
| TLS | Публічний сертифікат — довіра без налаштувань [В]; приватний CA — ланцюжок на сервері 1С [Г] |

## Безпечний режим і БСП

| Що | Поведінка |
|---|---|
| Безпечний режим розширення | WebSocket працює, зокрема від чужого імені; HTTP-з'єднання заборонені [В] |
| Перехоплення модуля конфігурації в безпечному режимі | Заборонене — див. `v8storagekit:1c-bsp-service-user` [В] |
| Блокування зовнішніх ресурсів БСП | Збережений клієнт не зупиняє — розширення має перевіряти `РегламентныеЗаданияСервер.РаботаСВнешнимиРесурсамиЗаблокирована()` саме [В]. Регламентне завдання, зареєстроване в БСП як «працює із зовнішніми ресурсами», БСП на копії вимикає [К] |
| Оновлення розширення під живим з'єднанням | Старе з'єднання відповідало старим кодом [Г, одне спостереження] — після оновлення перевідкривати |
