# Лінзи

| Лінза | Модель | Питання |
| --- | --- | --- |
| план проти спеки й коду | sonnet (opus для ризикового блоку, бо там пропуск коштує security major) | Чи кожне твердження й якір правдиві? Чи кожну задачу можна виконати в поточному коді? Чи не втрачено щось із рядка блоку спеки? Для кожного механізму, який називає задача (об'єкт, генератор, етап, точка розширення), чи план цитує код, що його підтримує (процедура, сигнатура, об'єкт)? Без цитати — знахідка. |
| безпека й старе покоління | opus — дефекти прав і меж довіри Sonnet пропускає частіше (вимір agent-kit, його ADR-0005) | Чи дані, записи чи підписки переживають закриття, втрату доступу, старе покоління запиту чи даних? Права ролей, гості й анонімні сеанси, обмеження доступу на рівні записів? Чи не витікає секрет чи дані через відповідь, журнал, обмін? Межі обміну й інтеграцій. |
| цілісність даних | opus — пропуск у записі облікових даних чи транзакції псує дані, які потім не відновити кодом | Облікові записи: чи повні на всіх шляхах, зокрема скасування й повтору? Транзакція: чи відкрита на шляху помилки й чи не охоплює зайвого? Блокування: чи є порядок і чи вистачає їх до читання перед записом? Чи не ламає зміна дані, створені попередньою версією? |
| сумісність із вендором | sonnet | Чи план спирається на чужий код (вендор, бібліотека), який зміниться з його оновленням (перехоплення, розширення, копії форм)? Чи цей код справді такий? Чи названо, що робити при оновленні? |
| бюджети | sonnet | Чи кожен бюджет — вимірна умова done-when? Чи дизайн вкладається в нього на заявленому обсязі даних (запит у циклі, запити без параметрів, виклики сервера)? |
| гейт без хибного зеленого | opus — хибний зелений гейту пропускає дефект у кожного, хто на нього покладається | Чи може перевірка стати зеленою без прогону, на порожній множині чи при помилці відбору? Чи гейт ділить код із тим, що перевіряє? |
| виконуваність | sonnet (opus для ризикового блоку, бо там пропуск коштує security major) | Чи названа перевірка справді червоніє? Чи працюють команди? Порядок задач, цикли залежностей. Лише коли раунд 1 знайшов blockers виконуваності. |

Codex — не лінза: він працює лише як необов'язковий скіл `v8storagekit:codex-audit`, якщо на машині налаштовано Codex CLI, і за тригером зі скіла `plan`, «Аудит за ризиком», крок 5.
