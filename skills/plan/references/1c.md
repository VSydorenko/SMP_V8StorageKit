# План у репозиторії 1С

**Завантажуй**, коли пишеш чи аудитуєш план у репозиторії 1С (є `v8storagekit.yaml` чи
`v8project.yaml`). Доповнює `SKILL.md` і `template.md`; там, де розходяться, діє цей файл.

## Драбина перевірок — поле `Сходинка:` кожної задачі

Кожна задача називає найвищу сходинку, яку мусить пройти; нижчі входять автоматично. Нової
сходинки бриф не вигадує — вона з'являється в цьому словнику.

| Сходинка | Що перевіряє |
| --- | --- |
| `check` | статичний аналіз вузла: `unica.check {at}` |
| `push` | source-set завантажується в базу агента |
| `syntax` | синтакс-контроль Конфігуратора для source-set (`v8-runner check`) |
| `yaxunit` | тести YaXUnit одного модуля |
| `acceptance` | паритет з еталоном на живих даних або ручне приймання за переліком сценаріїв |

- Задача, що змінює код BSL, — не нижче `syntax`.
- `syntax` і `yaxunit` діють на закомічений стан.
- Обсяг тестів — політика «лише ключове» (`v8storagekit:1c-yaxunit`): перелік тестів задає план; для
  запиту чи звіту головний доказ — `acceptance`; обв'язку тестами не покривати.

## Розділ «Зміни метаданих»

Іде в план після «Інтерфейси»: таблиця `об'єкт | нове / змінене / запозичене | форми | source-set`.
Переліку об'єктів для захоплення у сховищі в плані немає: людина захоплює все рекурсивно.

## Що робить план 1С виконуваним

- Поведінка платформи й вендора: код дампу конфігурації-власника воркспейсу, `unica:platform-help`,
  предметні скіли Уніки (`unica:bsp-patterns`, `unica:transactions-locks`, `unica:document-posting`
  тощо); цитуй модуль і процедуру.
- Права ролей план не доводить — їх перевіряє виконавець на базі агента у своїй задачі.
- Шапка називає базу агента як спільний ресурс і хто та коли її займає (збирає, тестує); у `shared`
  базу тримає один виконавець за раз.
- Задача, що додає до бази агента ролі, розширення чи налаштування, називає шлях перевірки й коли
  база їх отримує.
- У брифі аудитора: код вендора — у дампі конфігурації-власника воркспейсу.

## Ризик і лінзи аудиту — назви 1С

| Питання класифікатора | У 1С це |
| --- | --- |
| 1, права | ролі, профілі груп доступу БСП, RLS |
| 2, сеанси й ідентичність | службові користувачі ІБ, сеанси, секрети в безпечному сховищі |
| 4, цілісність даних | проведення документів, рухи регістрів, управляемые блокировки, відміна й перепроведення |
| 5, чужий код | перехоплення `&Перед`/`&После`/`&Вместо`/`&ИзменениеИКонтроль`, запозичені форми й процедури конфігурації-власника; чи код такий у дампі |
| бюджети | віртуальні таблиці без параметрів, запит у циклі, виклики сервера |

Лінза «план проти спеки й коду» в 1С ще перевіряє: кожна задача має сходинку; механізм (об'єкт
метаданих, процедура) процитовано з коду через Уніку.
