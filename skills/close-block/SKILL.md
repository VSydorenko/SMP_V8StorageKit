# Закрити блок

Мета: прибрати з репозиторію все, що бреше про поточний стан. Завершений план шкідливий не місцем, а тим, що агент читає його як інструкцію й приземляє скасоване рішення. Зламане посилання чи хроніка «було → стало» роблять те саме. Git тримає історію; документи — стан; GitHub — статус (`track`).

Деталі кроків: [references/steps.md](references/steps.md). Хроніка й мітки — що йде, що лишається: [references/narration.md](references/narration.md). Брифи верифікаторів: [references/verify.md](references/verify.md).

## 0. Ворота власника — спитай до всього

Спершу інвентар: файли блоку в `docs.plans` / `docs.specs` профілю, issue й PR блоку (`track status`). Блок має бути злитий; ні — зупинись. Потім спитай власника **одним повідомленням** (AskUserQuestion, до трьох питань):

1. **Обсяг** — лише плани блоку чи ще й його спеки або частини спек. Жива спека, що досі описує ціль, ніколи не архівується разом із блоком.
2. **Куди йде живий борг** — GitHub issues (типово: `bug` / `idea` / issue блоку у віхі) чи розділ живого канонічного документа.
3. **Списки «Видалено — не шукай»** — хроніка йде завжди; списки токенів, яких більше немає: лишити як заборони в теперішньому часі чи видалити.

## 1. Збери живий борг — до видалення

`doc debt <файли…>` показує незакриті пункти й розділи боргу. Потім прочитай **повністю** кожен файл блоку, а також файли пам'яті блоку та його журнал виконання (`.agents/sdd/<блок>/`, а для блоків, розпочатих до kit, ще й `.superpowers/sdd/<блок>/`, у головному checkout). Борг ховається в усіх: відкладені рішення, відкладені дрібниці, що не покрив димовий прогін, пастки вимірів. Кожен живий пункт стає issue (або ціллю власника), **самодостатнім**: без посилань на те, що буде видалено.

## 2. Знайди кожне посилання — до видалення

`doc refs <шлях…>` — кожне посилання на файли обсягу по всьому репозиторію: документи, код, конфіг; повні шляхи, відносні markdown-посилання, довгі голі імена. `doc history --code -Only '<мітки блоку>'` — мітки блоку в коментарях коду й назвах тестів (`§N` видаленого документа, кодова назва блоку, його фази, задачі, id рішень, номери PR). Вказівник у **живий** документ лишається чинним.

## 3. Звіт власнику — одна таблиця, до будь-якої зміни

`елемент → клас → дія`, один рядок на файл, посилання, мітку, рядок хроніки й файл пам'яті: **delete** · **keep** (чому) · **rewrite** (новий текст) · **issue** (назва). Плюс перелік боргу з назвами issues. Нічого не видаляється й не правиться поза рядками затвердженої таблиці.

## 4. Застосуй (одна гілка, один PR)

1. Спершу створи issues боргу; внеси їхні номери в звіт.
2. `git rm` затверджених файлів. Видали теки журналу виконання блоку (`.agents/sdd/<блок>/` і, якщо є, `.superpowers/sdd/<блок>/` у головному checkout; вони в git-ignore, тож `rm -r`), коли крок 1 перетворив їхній борг на issues. Архів не лишається; `pr-gate cleanup` так само прибирає власний журнал worktree разом із ним.
3. Кожне посилання й мітку виправляй точковою правкою: прибери навігаційну мітку, лиши причину. Ніколи не масовий regex по прозі.
4. Канон від хроніки до стану: `doc history --docs`, таблиця замін у [narration.md](references/narration.md). Заодно звір канон із кодом; суперечність зі специфікацією платформи йде власнику, а не в тихе переписування.
5. Ворота: `doc anchors` ok, `doc refs --dead` ok (або кожен збіг позначено «майбутнє» із задачею, що його створює). <!-- tests: ADR-0004, pending owner discussion --> Форму прогону тестів, якщо вона потрібна для змін лише в документах, називає бриф.

## 5. Пам'ять — після схвалення звіту власником

Класи як у `v8storagekit:kit-onboard`: **delete** (журнали закритого блоку), **pointer**, **keep-as-history**, **move** (знання, потрібне іншим агентам, іде в git-канон — скіл, `CLAUDE.md`, спеку — а не в пам'ять). Живі уроки переписуй без номерів фаз чи PR. `MEMORY.md` і посилання між файлами пам'яті оновлюй у тому ж кроці.

## 6. Змагальна верифікація — обов'язкова

Два незалежні агенти на Opus із брифами з [verify.md](references/verify.md): **безпека diff** (спростувати «правки безпечні»: усе, що змінено поза коментарями й документами, втрачена суть, видалені чинні посилання, вигадані API) і **повнота** (повторити `doc refs --dead`, `doc history`, `ls` кожен згаданий шлях). Opus тут свідомо: це єдина перевірка, що ловить мовчазну втрату суті. Виправ доведене; скажи, що відхилив і чому.

## 7. Закрий

`pr-gate open` (тіло PR: видалені файли й рядки, борг → issues, дефекти, знайдені дорогою, що лишено й чому, результати воріт). Зливає власник. Звіт власнику — одне коротке повідомлення, без переказу кроків.

## Правила

- Ніколи не підіймай дати «остання перевірка» чи «перевірено» у файлі, який лише переформулював.
- Шляхи беруться з профілю (`docs.*`); скіл не тримає назв проєктів.
- Мова кожного файла лишається такою, як кажуть правила проєкту.
