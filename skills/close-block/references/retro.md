# Ретро

Необов'язковий крок закриття блоку (`/v8storagekit:close-block`, крок 8); запускає власник, ретро можна провести й окремо від закриття, за прохання «проведи ретро». Файл — повний зміст кроку.

Коротка ретроспектива, що завершується діями, а не есеєм. Кожен пункт потребує моменту, на який можна показати: цитата, число чи вартість. Сесія за замовчуванням ця; для минулої читай її транскрипт так, як каже [retro-evidence.md](retro-evidence.md).

## 1. Збери докази

- **Поправки власника** — цитуй кожну одним рядком. Рядки з іншої сесії (`[<назва сесії>]`) для виконавця рахуються так само: це інструкції й приймання архітектора.
- **Повторні ручні процедури** — та сама форма команди чи ручна послідовність 3+ разів; назви кількість.
- **Дорога робота** — великі виводи, прочитані повністю, довгі пошуки, переробки, повторні прогони; вартість — `session-cost -Project <репо> -Session <id> -By agent`, коли id відомий.
- **Порушені правила** — скіл, правило проєкту чи kit, яке порушили, і що це коштувало.
- **Інструменти kit** — що допомогло (лишити), чого бракувало, що впало чи було обійдене.

Гладка частина — не пункт, а категорія без доказів лишається порожньою.

## 2. Класифікуй

| Клас | Перевірка | Дія |
|---|---|---|
| Патерн kit | Повторився б в інших проєктах | issue з міткою `pattern` у `VSydorenko/SMP_V8StorageKit` або PR на виправлення до ~50 рядків — [retro-contribute.md](retro-contribute.md) |
| Правило проєкту | Правда лише для цього репозиторію | Пам'ять проєкту (один факт — один файл) або документи проєкту. Кореневі правила (`CLAUDE.md`) лише зі схваленням власником точного тексту |
| Продуктовий пункт | Рішення про те, що будувати | Питання власнику |
| Разове | Не повториться | Відкинь; скажи про це в таблиці |

Форма виправлення:
- Механічна помилка (хибний прапорець, заборонена команда, пропущена перевірка) → скрипт, хук чи перевірка, що падає, бо речення не зупиняє.
- Судження → правило в скілі чи лінзі рецензента, де його читають у потрібний момент.
- Правило, що нічого не змінило в цій сесії, → кандидат на видалення.

Перш ніж щось пропонувати, перевір, що воно нове: `gh issue list -R VSydorenko/SMP_V8StorageKit --state all --search "<ключові слова>"`, `skills/`, `agents/` і `tools/` плагіна, пам'ять проєкту. Розшир наявне замість близнюка.

## 3. Звіт і дії

1. **Запиши пам'ять проєкту зараз**, не питаючи: `~/.claude/projects/<slug>/memory/` (`<slug>` — шлях проєкту, де кожен символ, що не є літерою чи цифрою, замінено на `-`), один факт — один файл, однорядковий вказівник у його `MEMORY.md`. Файл, що вже покриває факт, онови.
2. **Таблиця**, один рядок на пункт:

   | # | Пункт | Доказ | Клас | Дія |
   |---|---|---|---|---|

   Доказ — цитата, число чи вартість, ніколи «часто». Для пунктів пам'яті клітинка «Дія» називає файл і що змінилось.
3. **Що допомогло** — інструменти kit і звички, які лишити, по рядку.
4. **Одне AskUserQuestion** (multiSelect), один варіант на пункт, що потребує власника: кожен issue чи PR kit (назва + рядок), кожна правка кореневого правила (точний текст), кожен продуктовий пункт. Познач рекомендовані.

Потім дій за вибором власника: пункти kit — за [retro-contribute.md](retro-contribute.md), обрані правки кореневих правил. Закінчи тим, що зроблено: посилання на issue й PR, шляхи файлів пам'яті.
