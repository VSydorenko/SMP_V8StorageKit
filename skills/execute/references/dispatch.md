# Що містить виклик виконавця й рецензента

Усе, що вставляєш у виклик, лишається в твоєму контексті до кінця сесії й перечитується щоходу. Справжній виклик SDD сягнув 42 тис. символів, 99 % — вставлена історія (вимір agent-kit).

## Виконавець (`v8storagekit:implementer`)

Виклик містить лише:

1. Одне речення про місце задачі в плані.
2. Шлях до брифу: «прочитай це першим — це твої вимоги, точні значення бери дослівно».
3. Шлях до доповнення `task-N-brief-addendum.md`, якщо воно є (рішення й відповіді, що змінюють бриф).
4. Інтерфейси з попередніх задач, яких бриф знати не може, — назви й типи, по рядку.
5. Покажчик на відкладену знахідку в ділянці, яку торкається задача, якщо така є.
6. Шлях до звіту, BASE з виводу `sdd dispatch` і робочу теку.
7. Режим робочої копії (`workspace.mode`). У `shared`: «базу агента збираєш і тестуєш лише ти, лише кроками, які називає бриф; коміт — `git add <перелік>` + `git commit --only`».
8. Для ризикової задачі: «мутаційні перевірки — лише так, як каже бриф задачі» (див. агента). <!-- tests: ADR-0004, pending owner discussion -->

Не клади: глобальні обмеження (вони в брифі), підсумки попередніх задач, сам план.

Запиши id агента виконавця — раунди виправлень відновлюють його.

## Рецензент задачі (`v8storagekit:task-reviewer`)

1. Шлях до брифу й до звіту.
2. Шлях до пакета, який друкує `sdd review <N>`.
3. Названі ризики цієї задачі (з попереднього сканування чи інваріантів безпеки плану), по рядку.
4. Мінімальні версії платформи з профілю, якщо проєкт їх має.
5. Нагадування: базу агента не збирати й у ній нічого не запускати (мутуючі `unica_apply`, `unica_run` не кликати) — її тримає виконавець; мутаційних повторів у `shared` немає, рецензент пише це в «Cannot verify».
6. Повторне рев'ю: `Mode: re-review`, знахідки дослівно й пакет, який `sdd review <N>` друкує в раунді виправлень (лише diff виправлення).

Без упередження: якщо твій промпт містить «не позначай», «щонайбільше minor» чи «план так вирішив» — видали це: ти намагаєшся уникнути раунду виправлень.
