# Попереднє сканування: ваги й конфлікти

Виконай один раз, перед задачею 1. Пропусти, якщо журнал уже має таблицю (відновлення).

Якщо план дає вагу кожної задачі — бери її. Інакше один `v8storagekit:auditor` на **opus** читає план один раз — Opus тут свідомо, бо вага задає модель і рецензію кожної наступної задачі й хибна вага множиться на весь план — із таким брифом:

```
Lens: preflight — task weights and conflicts. Not an audit of the plan's design.
Plan: <шлях>
Hard rules: <файли правил проєкту з профілю, напр. AGENTS.md, CLAUDE.md>
Return:
1. Table: task | weight (trivial | standard | risky) | why, one line | перевірки задачі (форму прогону називає бриф).
   Перевірки задачі — за зміною: задача без коду (документи, тексти) — лише перевірки документів; задача з кодом — тести зміненого й тих, хто його кличе; повний набір — лише в останній задачі блоку.
   trivial — документи, конфіг, механічне перейменування, бриф має весь код.
   standard — логіка без ризикового сигналу.
   risky — права, ролі, межа довіри, ідентичність і секрети, межі обміну й інтеграцій, запис облікових даних, транзакції, блокування, семантика запитів, парсери, перехоплення чужого коду.
2. Conflicts: задача проти задачі (одна виробляє те, що інша споживає інакше), план проти спеки, план проти жорстких правил.
   Познач кожен: mechanical (контролер виправляє текст плану) чи substantive (розвилка класу B).
3. Mechanisms: для кожного механізму, який називає задача (клас, генератор, етап, точка розширення), код, що його підтримує (об'єкт метаданих, процедура, сигнатура); без цитати — конфлікт.
   Спільний рантайм: задача, що додає до нього об'єкти чи налаштування, мусить назвати шлях перевірки, хто збирає рантайм і коли; рядка немає — конфлікт.
4. Batching: сусідні задачі зі спільними файлами або дрібні правки однієї форми, які один виконавець зробить одним викликом.
Один рядок на задачу; без переказу плану.
```

Запиши таблицю в робочу теку як `preflight.md`. Вагу можна змінити з причиною: `sdd dispatch <N> -Weight <w>` плюс `sdd ruling <N> "weight <w> — чому — вплив на спеку: немає"`.

Суттєві конфлікти → архітектору, одним повідомленням, **до задачі 1**. Механічні → виправ текст плану окремим комітом.
