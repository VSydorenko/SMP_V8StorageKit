# Звіт виконавця, що не DONE

| Статус | Що робиш |
| --- | --- |
| DONE_WITH_CONCERNS | Прочитай застереження. Про коректність чи обсяг → розв'яжи до рев'ю. Спостереження («файл стає великим») → занотуй і рецензуй. |
| NEEDS_CONTEXT | Дай бракуючий контекст у файлі-доповненні й відновлюй того самого виконавця. |
| BLOCKED | Знайди причину: бракує контексту → доповнення, та сама модель; потрібно більше міркувань → свіжий виконавець на opus; задача завелика → розділи її рішенням (ruling); план хибний → ruling класу A чи розвилка класу B. |

Умова зупинки в брифі — нормальний шлях, не збій: виконавець зупинився, нічого не зламавши.

Задача повертається тій самій моделі лише зі зміною. Якщо вона сказала, що застрягла, щось мусить змінитись.

`sdd log <N> blocked|needs-context -Note "…"` для кожного такого статусу. Відновлення того самого виконавця (відповідь у доповненні, після паузи) → спершу `sdd resume <N>`, потім `sdd watch <N>`; свіжий виконавець → `sdd dispatch <N>` (BASE лишається). Без цього спостерігач не відрізнить новий рядок `Status` від старого.

`sdd log` на задачі `complete` лише дописує нотатку; задача лишається `complete`.
