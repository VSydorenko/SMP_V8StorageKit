# Бриф: спайк

**Завантаж, коли** гіпотезу треба довести чи спростувати кодом до рішення.

```markdown
# <сесія>: спайк «<питання>» (<проєкт>)

Architect: сесія `<ім'я>`. Series rules: <шлях>-common.md.

## Question
<гіпотеза як питання>

## Criteria (перевіряються буквально)
| # | Критерій | Так, коли | Метод |
| --- | --- | --- | --- |
| 1 | <…> | <число / результат перевірки> | <перевірка, замір, команда> |
Червоний результат — теж результат. Не підганяй критерій під зелений.

## Step 0 — прецеденти (≤ 2 год)
Що вже існує (бібліотеки, вбудовані механізми платформи, інші конфігурації): взяти /
відхилити / чому.

## Shared interface
<Якщо паралельні спайки ділять інтерфейс: спайк-власник інтерфейсу v0 — <ім'я>;
інші стартують на заглушці з ескіза й зливають його гілку з контрольної точки <X>.>

## Subagent models
Реалізація й виміри: sonnet; аналіз компромісів: opus.

## База агента
Режим `shared`: спайк, що збирає чи тестує базу агента, — один за раз; черговість задає архітектор у брифі.

## Git
Гілка `<гілка>`. Код спайка ніколи не зливається в main. Звіт — окремий PR у main:
таблиця критеріїв із результатами, пропозиція рішення.
- Push: <«PR зі звітом спайка» | «не пушити»>. PR — лише за цим рядком, через `pr-gate open`.

<встав блок із report-format.md>
```
