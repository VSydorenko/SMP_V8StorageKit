# Прийом

**Завантаж, коли** береш роль архітектора для частини чи спеки.

1. Прочитай спеку частини **повністю** сам (`doc <спека>`, далі кожен розділ). Деталі, які
   захищатимеш, мусять бути у твоєму контексті, а не в підсумку агента.
2. Віддай одному агенту (Sonnet) розвідку коду. Бриф: «спека припускає X — що в коді?»
   пунктами; звіт = дельта з якорями (файл + символ), а не переказ. У брифі назви
   інструменти: Уніка (`unica.search` за темою, `unica.resolve`/`unica.view` за логічною
   адресою), код дампу конфігурації-власника для вендора, `doc find` для документів.
3. Перевір сам у коді 2–3 ключові твердження розвідника.
4. Висновок зведення = реальний розмір блоків. Блок у кілька разів більший, ніж думала
   спека → розділи його й запиши поділ у таблицю блоків спеки.
5. Запиши файл стану (шаблон — за ключовим правилом 5 `SKILL.md`): роль, хто вирішує
   розвилки, що зроблено, що далі.
