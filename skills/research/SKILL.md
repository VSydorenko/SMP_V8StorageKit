# Дослідження

Мета: закрити кожне відкрите питання з розмови перевіреними фактами й повною рекомендацією за один прохід. Не припускай — досліджуй.

Контекст — усі попередні повідомлення про відкриті питання (рев'ю, уточнювальні питання, поточне обговорення). Якщо питання не ідентифікуються, спитай власника, які саме.

## 1. Виміряй питання

| Питання | Що робиш |
| --- | --- |
| **Точковий факт** — де живе X, хто викликає Y, на якій версії закріплено Z, чи існує якір плану | Перевір сам. Без субагентів. |
| **Ширше** — як працює ділянка, який із кількох підходів підходить, що справді робить код вендора чи платформа, як це розв'язують інші | Розішли агентів `v8storagekit:researcher`: по питанню кожному, до 5 паралельно, в одному повідомленні. |

Модель дослідника: типово `sonnet`. `opus` — лише для питання, що зважує компроміси або стосується безпеки (права, дані, секрети), і скажи про це в рядку-оголошенні.

Перед розсилкою надішли власнику **один рядок: що досліджуєш і навіщо** (і які питання йдуть на Opus). Потім запускай; поки агенти працюють, запиши те, що вже відомо, замість чекати.

## 2. Джерела, за порядком

1. **Код** — спершу карта, потім істина: Уніка, далі лише прочитане за картою. Див. [references/code-search.md](references/code-search.md).
2. **База людини** — лише читання й лише на явне прохання власника (`kit dump`). База агента не є джерелом фактів про базу людини. Схему й дані не припускай.
3. **Справка платформи й бібліотеки** — `unica:platform-help`, `unica_docs` для версії воркспейсу; для вендора — код дампу конфігурації-власника (`truth: vendor|dump`); для сторонніх бібліотек — інструмент документації (напр. Context7) для **закріпленої** версії.
4. **Готові рішення** — відкритий код, інші конфігурації, вбудовані механізми платформи, прецеденти в мережі. Цитуй URL.

Спека й архітектурні документи проєкту задають напрям: звіряй кожну пропозицію з ними (`doc find` знаходить потрібний розділ).

## 3. Бриф кожному досліднику

Шаблон — [references/brief.md](references/brief.md): усталений контекст, твоя позиція «підтверди чи спростуй», питання власника його словами, що досліджувати, форма звіту. Бриф без усталеного контексту змушує агента заново відкривати його — саме там іде вартість.

## 4. Перевір, потім вирішуй

- Кожен факт, на якому тримається рішення, перевір у першоджерелі сам: рядок коду, код дампу, справка платформи для версії воркспейсу. Висновок дослідника не переказуй як факт.
- «Нічого не знайдено» — не доказ відсутності: перевір регістр, синоніми, словоформи (зокрема рос/укр форми імен 1С), повноту індексу.
- Два звіти розходяться або твоє попереднє твердження було хибним — скажи, яке й чому.

Хто що вирішує: три класи питань, правило 3 скіла `v8storagekit:discuss`.
