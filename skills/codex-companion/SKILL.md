# Codex companion (делегування задач у OpenAI Codex CLI)

Дозволяє викликати **локальний Codex CLI** як окремого агента: він читає поточний репозиторій,
виконує задачу неінтерактивно й повертає фінальне повідомлення. Ти (Claude Code) — оркестратор:
формулюєш задачу, запускаєш Codex, а тоді **переказуєш/резюмуєш його відповідь користувачу**,
явно атрибутуючи її як думку Codex.

> **ОБОВ'ЯЗКОВО перед і після виклику — чотири правила нижче.** Якщо в пам'яті проєкту чи
> користувача є ранбук `codex-audit-runbook.md` — прочитай його теж: він тримає журнал інцидентів
> цієї машини. Ранбука немає — правил нижче досить, а урок збою передай власнику у звіті.
> 1) **локальне репо**: `-Repo <абсолютний корінь>` + `-Sandbox read-only` (read-only блокує мережу
>    → Codex не тягне remote); звіряй `repo:`/`workdir:`/`sandbox=` у виводі щоразу сам;
> 2) **верифікація**: Codex не має контексту чату → після аудиту перевір **кожну** знахідку сам по
>    коду, звіт Codex = гіпотези, не факти;
> 3) **реальний старт**: дочекайся `✔ Codex стартував`; exit 6 (фантом) / 7 (таймаут) — не результат,
>    діагностуй і перезапусти;
> 4) при будь-якому збої — після усунення допиши урок у «Журнал інцидентів» ранбука (коли він є).

## Коли спрацьовувати

Задачу треба делегувати локальному Codex CLI: він підключається до локального репозиторію, виконує роботу
(за замовчуванням read-only: аудит/рев'ю/аналіз) і повертає фінальну відповідь.

Тригери: «передай задачу в кодекс», «делегуй кодексу», «аудит/рев'ю в кодексі», «рев'ю кодексом», «спитай
Codex», «друга думка від Codex», «cross-check / delegate / audit / review with Codex», «Codex companion».

## Як викликати

Один виклик через обгортку (PowerShell). Вона сама знаходить бінар, ставить безпечні дефолти,
перехоплює ЧИСТИЙ результат і друкує його в stdout:

```powershell
& "${CLAUDE_PLUGIN_ROOT}/skills/codex-companion/scripts/codex-delegate.ps1" `
  -Task "<чітко сформульована задача для Codex>" `
  -Repo "<абсолютний шлях до репозиторію>" `
  [-Sandbox read-only|workspace-write] [-Model gpt-5.6-sol] [-Effort low|medium|high|xhigh|max] [-Review]
```

- `-Repo` — за замовчуванням поточна тека; для надійності передавай абсолютний шлях кореня репо.
- `-Review` — використати вбудований `codex exec review` (структурований код-рев'ю по репозиторію);
  добре для «зроби рев'ю останніх змін».
- `-Effort` — глибина міркувань Codex (`medium` за замовчуванням; `high`+ для складного аудиту).

Читай stdout після маркера `----- CODEX RESULT -----` — це і є відповідь Codex.

## Політика режиму (ВАЖЛИВО)

- **read-only (дефолт)** — для аудиту, рев'ю, аналізу, «другої думки». Codex не пише файлів і не
  лізе в мережу. Безпечно, не потребує підтвердження.
- **workspace-write** — лише коли користувач ЯВНО хоче, щоб Codex **змінював код**. Перед цим:
  1) підтвердь намір у користувача; 2) переконайся, що робоче дерево чисте або працюй в окремій
  гілці/worktree; 3) після — покажи `git diff` і дай користувачу вирішити, чи лишати зміни.
- `danger-full-access` — не використовуй без прямого і недвозначного прохання.

## Модель

Завжди передавай `-Model gpt-5.6-sol` (обгортка робить це за замовчуванням). Модель із
`~/.codex/config.toml` (напр. `gpt-5.3-codex`) — вибір користувача для власного/API-використання;
вона може бути **не підтримувана ChatGPT-акаунтом** і зламати виклик. НЕ редагуй `config.toml`.

## Прозорість

Codex надсилає вміст репозиторію в OpenAI під ChatGPT-акаунтом користувача. Це очікувано (сам
концепт делегування), але якщо в репо є чутливі дані — коротко попередь перед першим викликом.

## Обробка результату

- **Верифікуй КОЖНУ знахідку Codex сам** (Read/Grep/збірка/тести) перш ніж передати користувачу як
  факт — Codex не бачив контексту нашого чату й може хибно трактувати нюанси (хибнопозитиви).
- Переказуй українською, стисло, розділяючи: «Codex стверджує X» → «Перевірив: підтверджується /
  хибно, бо…». Ніколи не переказуй звіт Codex дослівно як істину.
- Exit-коди обгортки: `6` — фантомний старт, `7` — таймаут, `5` — без фінального повідомлення.
  Це НЕ результат аудиту: діагностуй (авторизація/модель/мережа), перезапусти, і допиши урок у
  «Журнал інцидентів» ранбука (коли він є).

## Передумови (якщо виклик падає)

- CLI: `npm install -g @openai/codex`; бінар — `%APPDATA%\npm\codex.cmd`.
- Авторизація: `~/.codex/auth.json` (ChatGPT OAuth). Якщо протух — користувач робить `codex login`
  (інтерактивно, через `!codex login`).
- PATH: тека `%APPDATA%\npm` має бути в user-PATH (обгортка все одно резолвить бінар повним шляхом).
