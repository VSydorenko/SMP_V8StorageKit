# Шкала й звіт

**Завантажуй**, коли оцінюєш знахідку чи пишеш звіт рев'ю.

## Серйозність

| Серйозність | Критерій |
| --- | --- |
| `blocker` | зламана поведінка, втрата даних, дірка в доступі, приватна деталь у публічному репо чи задача по суті не виконана |
| `major` | дефект, що проявиться в користуванні чи на наступній фазі; борг, що множиться (другий шлях коду, межа, перетнута «лише цього разу») |
| `minor` | локальна неохайність; дешево виправити, не блокує |

## Впевненість 0–100

| Впевненість | Рівно коли |
| --- | --- |
| 0 | не переживає легкої перевірки, або вже існувало поза diff |
| 25 | можливо справжнє, не підтверджено; стиль, не названий у правилах проєкту |
| 50 | справжнє, але рідкісне чи дрібне поряд з рештою diff |
| 75 | перевірено й дуже ймовірно на практиці |
| 100 | доведено: конкретний вхід, стан чи прогін ламає, або суперечить правилу проєкту чи спеці, показано цитатою правила (file:line) і рядком коду |

**Поріг: нижче 80 знахідка до звіту не потрапляє** — один рядок у «Below threshold».

## Вивід рецензента

```
## Named risks
- <ризик> — confirmed / refuted, якір або прогін

## Findings (confidence ≥ 80)
### [blocker|major|minor] коротка назва — confidence NN [plan-class]
**Where:** file:line і символ (чи розділ документа) — обов'язково; для відсутнього (тест, перевірка) — файл чи задача плану, де воно має бути
**What:** одне-два речення
**Evidence:** фрагмент коду, вхід, що ламає, або вивід прогону
**Fix:** одна конкретна дія

## Below threshold
- назва — причина на півряд

## Seen outside the lens
- по одному рядку; ним володіє інший рецензент

## Not checked
- що лишилось поза межами чи середовищем і хто має це взяти (зокрема: мутація в режимі shared, відсутність Уніки)

LENS: <назва> | RANGE: <base..head> | FINDINGS: N (blocker X / major Y / minor Z) | BELOW: M
```

## Підсумковий звіт для власника

Спершу вердикт: **accept / accept with remarks / return** — одне речення чому. Далі підтверджені знахідки в цьому форматі, кожна з **Where** і вердиктом верифікатора (`CONFIRMED` / `PARTIAL` з упевненістю); потім «спростовано верифікатором: K з N (P %)», нижче порогу, не перевірено.

## Не знахідка

- Стиль, назви, форматування, не названі в правилах проєкту.
- «Варто було б розглянути…» без конкретної дії.
- Переказ diff чи перелік того, на що дивився.
- Старі проблеми поза межами — щонайбільше рядок у «Not checked».
- Твердження зі звіту виконавця, яке ти не підтвердив у коді.

## Два правила для «Fix»

- **Один патерн для ділянки:** зводь її компоненти до одного механізму, а не до ще одного окремого випадку.
- **Без обгорток над обгортками:** працюй через наявні механізми; застарілу абстракцію називай прямо й пропонуй її міграцію.

## Антипатерни

- Рецензувати звіти виконавців замість diff і коду.
- Вірити зеленим тестам без перевірки, що новий інваріант справді може їх уронити (у режимі `shared` мутацію не роблять — назви це в «Not checked»).
- Гарантія в коментарі, жодної в твердженнях.
- Судити прототип за цільовим правилом чи новий цільовий код за конвенцією прототипу.
- Один рецензент на велику фазу: незалежний аудит потім знаходить 3–5 дефектів, а фаза виправлень коштує далеко більше за рев'ю.
- Лінза, яку тут не можна запустити (немає бази, немає Уніки), імітована статичною здогадкою — познач її NOT COVERED.
