# Лінзи

**Завантажуй**, коли рецензуєш крізь лінзу або обираєш лінзи для diff.

Лінзи — різні джерела сигналу, а не виміри якості. Кожна йде окремим проходом, що не бачить інших. Перевірки проєкту для кожної лінзи — у файлі, названому полем профілю `review.criteria`; читай частину для своєї лінзи. Перевірки нижче узгоджені з агентом `v8storagekit:code-reviewer`. Код вендора читай у дампі конфігурації-власника воркспейсу; кого торкається зміна, шукай через Уніку (`unica_search`, `unica_resolve`, `unica_view`), потім `git grep`.

## correctness

Помилки в зміненому коді: `Неопределено`/`NULL`, контекст клієнт/сервер, межі, хибні умови, необроблені гілки, шляхи помилок, `Попытка` без повторного `ВызватьИсключение`, транзакції на шляху помилки (відкрита транзакція після виключення). Читай **лише diff** і мінімум контексту: глибоке занурення дає прискіпливість.

## test-honesty

Лише коли зачеплено тести.

| Перевірка | Сигнал дефекту |
| --- | --- |
| тест упав би, якби код зламався | асинхронний клієнтський тест YaXUnit, зелений за будь-якого коду; «0 сценаріїв»; для нового інваріанта, гейта чи гонки — жодної перевірки, що тест здатний впасти (у режимі `shared` мутацію не роблять: «Not checked») |
| нічого не заглушено заради зеленого | видалене чи послаблене твердження, знижений поріг, файл, виключений з перевірки; пропущений сценарій |
| твердження не вкладені хибно | вкладений `ЮТест.ОжидаетЧто`, що ніколи не виконається |
| тест не задає сам умову, яку міряє | очікуване значення обчислене тією самою формулою, що й код |
| фікстури збігаються з дійсністю | дані й виклики не відповідають реальним метаданим і формам викликів |
| обіцянка в коментарі є в твердженні | коментар каже, що тест тримає X, а твердження X не торкаються |
| тест не заради тесту | дублікат тієї самої поведінки, тест, прив'язаний до реалізації, модуль, що мокає те, що тестує — `minor`; відсутність тесту для косметичної правки — не дефект |
| без годинника стіни | твердження залежить від швидкості машини чи конкуренції |

## drift

Що написано проти того, що робить код: пункти плану не виконано, `[x]` без коду, застарілі твердження в спеках, скілах, README, `AGENTS.md`/`CLAUDE.md`. Починай із дешевих охорон: `doc anchors` і `doc refs`; потім шукай твердження, що брешуть, а не вказують.

## architecture

Розміщення коду по модулях (об'єкт, менеджер, загальний), `&НаКлиенте`/`&НаСервере` і межа виклику сервера, повторне використання, другий шлях коду поряд зі старим («старе + нове»), мертвий код, вкладення в модуль, який планують видалити; межа «розширення ↔ конфігурація», власні об'єкти проти запозичених.

## data-layer

Запити, віртуальні таблиці та їхні параметри, запит у циклі, управляемые блокировки, транзакції, права й RLS, ролі, рухи регістрів, екранування літералів у тексті запиту, інвалідація кешів проти того, що змінилось. Opus — дефекти прав, транзакцій і блокувань Sonnet пропускає частіше (вимір agent-kit, його ADR-0005).

## localization

`НСтр`, тексти кількома мовами: повідомлення людині, відповіді API, синоніми, заголовки форм і команд. Коли змінені тексти для людини, використай скіл `1c-localization`, якщо він є на машині. Лише коли зачеплено тексти.

## vendor-compat

Перехоплення `&Перед`/`&После`/`&Вместо`/`&ИзменениеИКонтроль` коду вендора, що зміниться з оновленням конфігурації-власника; запозичені форми. Чи перехоплена процедура існує в дампі такою, як припущено; що зламається, коли вендор її змінить. Лише коли є перехоплення чи запозичені форми.

## metadata

Цілісність XML: uuid, `ConfigDumpInfo`, політика тексту `docs/text-policy.md` у споживача (кодування, закінчення рядків). Лише коли зачеплено XML метаданих чи форм.

## history

`git log -p` і `git blame` на змінених місцях: що тут уже виправляли й чи не відкочує цей diff виправлення. Цю лінзу забувають найчастіше; жодна інша не дає «це ламалось раніше, ось як виправили».

## Приймальні лінзи

Для `code-reviewer` на прийманні блоку (лінзу й модель називає викликач): лінза, якої не мало рев'ю задач виконавця.

- **Gate honesty** — чи може гейт чи модельний тест бути зеленим при хибному ядрі: код, спільний з еталоном, винятки в інваріантах, недосяжні прапорці дефекту.
- **State after close and the old generation** — що з даними, сеансами, кешами й правами після закриття, відкату, перепідключення, і для рядків, створених попередньою версією.
- **Harm to other sessions on a shared stack** — для 1С: база агента, спільне дерево, чужі незакомічені файли; чистка чи команда, що знищує чужу роботу (`checkout --`, `restore`, `stash`, `clean`), коміт без `--only`, збирання чи тест у базі, яку тримає інша сесія.
- **Tests lost in a move** — переміщений чи розрізаний файл тестів усе ще проганяє старі випадки.
