# Лінзи

**Завантажуй**, коли рецензуєш крізь лінзу або обираєш лінзи для diff.

Лінзи — різні джерела сигналу, а не виміри якості. Кожна йде окремим проходом, що не бачить інших. Перевірки проєкту для кожної лінзи — у файлі, названому полем профілю `review.criteria`; читай частину для своєї лінзи. Перевірки нижче узгоджені з агентом `v8storagekit:code-reviewer`. Кого торкається зміна, шукай інструментами коду проєкту, якщо вони є, потім `git grep`. Репозиторій 1С — також [1c.md](1c.md): лінзи для BSL і метаданих, мовчазні класи дефектів.

## correctness

Помилки в зміненому коді: порожні й невизначені значення, контекст виконання, межі, хибні умови, необроблені гілки, шляхи помилок, проковтнутий виняток, транзакція чи ресурс, що лишились відкритими на шляху помилки. Читай **лише diff** і мінімум контексту: глибоке занурення дає прискіпливість.

## test-honesty

Лише коли зачеплено тести.

| Перевірка | Сигнал дефекту |
| --- | --- |
| тест упав би, якби код зламався | тест, зелений за будь-якого коду; нуль виконаних тестів; для нового інваріанта, гейта чи гонки — жодної перевірки, що тест здатний впасти (у режимі `shared` мутацію не роблять: «Not checked») |
| нічого не заглушено заради зеленого | видалене чи послаблене твердження, знижений поріг, файл, виключений з перевірки; пропущений сценарій |
| твердження не вкладені хибно | вкладене твердження, що ніколи не виконається чи підміняє значення зовнішнього |
| тест не задає сам умову, яку міряє | очікуване значення обчислене тією самою формулою, що й код |
| фікстури збігаються з дійсністю | дані й виклики не відповідають реальним метаданим і формам викликів |
| обіцянка в коментарі є в твердженні | коментар каже, що тест тримає X, а твердження X не торкаються |
| тест не заради тесту | дублікат тієї самої поведінки, тест, прив'язаний до реалізації, модуль, що мокає те, що тестує — `minor`; відсутність тесту для косметичної правки — не дефект |
| без годинника стіни | твердження залежить від швидкості машини чи конкуренції |

## drift

Що написано проти того, що робить код: пункти плану не виконано, `[x]` без коду, застарілі твердження в спеках, скілах, README, `AGENTS.md`/`CLAUDE.md`. Починай із дешевих охорон: `doc anchors` і `doc refs`; потім шукай твердження, що брешуть, а не вказують.

## architecture

Розміщення коду за шарами й модулями, межа клієнт/сервер чи між процесами, повторне використання, другий шлях коду поряд зі старим («старе + нове»), мертвий код, вкладення в модуль, який планують видалити.

## data-layer

Запити та їхні параметри, запит у циклі, блокування, транзакції, права й ролі, запис облікових даних, екранування літералів у тексті запиту, інвалідація кешів проти того, що змінилось. Opus — дефекти прав, транзакцій і блокувань Sonnet пропускає частіше (вимір agent-kit, його ADR-0005).

## localization

Тексти кількома мовами: повідомлення людині, відповіді API, підписи інтерфейсу. Лише коли зачеплено тексти.

## vendor-compat

Зміна, що спирається на чужий код (вендор, бібліотека), який зміниться з його оновленням: перехоплення, розширення, копії. Чи чужий код справді такий, як припущено; що зламається, коли його змінять. Лише коли зміна спирається на чужий код.

## metadata

Цілісність згенерованих і службових файлів: ідентифікатори, кодування, кінці рядків. Лише коли їх зачеплено.

## history

`git log -p` і `git blame` на змінених місцях: що тут уже виправляли й чи не відкочує цей diff виправлення. Цю лінзу забувають найчастіше; жодна інша не дає «це ламалось раніше, ось як виправили».

## Приймальні лінзи

Для `code-reviewer` на прийманні блоку (лінзу й модель називає викликач): лінза, якої не мало рев'ю задач виконавця.

- **Gate honesty** — чи може гейт чи модельний тест бути зеленим при хибному ядрі: код, спільний з еталоном, винятки в інваріантах, недосяжні прапорці дефекту.
- **State after close and the old generation** — що з даними, сеансами, кешами й правами після закриття, відкату, перепідключення, і для рядків, створених попередньою версією.
- **Harm to other sessions on a shared stack** — спільний рантайм, спільне дерево, чужі незакомічені файли; чистка чи команда, що знищує чужу роботу (`checkout --`, `restore`, `stash`, `clean`), коміт без `--only`, збирання чи тест у рантаймі, який тримає інша сесія.
- **Tests lost in a move** — переміщений чи розрізаний файл тестів усе ще проганяє старі випадки.
