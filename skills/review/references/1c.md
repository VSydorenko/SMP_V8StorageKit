# Рев'ю в репозиторії 1С

**Завантажуй**, коли рецензуєш у репозиторії 1С (є `v8storagekit.yaml` чи `v8project.yaml`).
Доповнює `lenses.md` і `SKILL.md`; там, де розходяться, діє цей файл. Агентам рецензентів ці
правила додає хук плагіна — у виклик їх не клади.

## Джерела

- Кого торкається зміна — Уніка (`unica_search`, `unica_resolve`, `unica_view`); `git grep` — лише коли Уніка відповіла помилкою чи `uninitialized`, з причиною в «Not checked».
- Код вендора — у дампі конфігурації-власника воркспейсу.
- Помічники Уніки (`unica:code-review`, `unica:code-diagnostics`) — джерело сигналу для лінзи, не
  заміна їй.
- База агента — спільний рантайм: рецензенти в ній нічого не запускають. Режим `shared` — звичайний
  для 1С, мутації немає.

## Лінзи для 1С

| Лінза | Що додає 1С |
| --- | --- |
| `correctness` | `Неопределено`/`NULL`, контекст `&НаКлиенте`/`&НаСервере`, `Попытка` без повторного `ВызватьИсключение`, транзакція, відкрита після виключення |
| `test-honesty` | YaXUnit: асинхронний клієнтський тест зелений за будь-якого коду; «0 сценаріїв» — не зелене; вкладений `ЮТест.ОжидаетЧто` в `.Равно()`; колір доказу на коміті тесту проти очікування задачі плану; тест понад перелік плану чи на обв'язку (політика `v8storagekit:1c-yaxunit`) |
| `architecture` | модуль об'єкта, менеджера чи загальний; межа виклику сервера; межа «розширення ↔ конфігурація», власні об'єкти проти запозичених |
| `data-layer` | віртуальні таблиці та їхні параметри, управляемые блокировки, RLS і ролі, проведення й рухи регістрів |
| `localization` | `НСтр`; синоніми, заголовки форм і команд; скіл `v8storagekit:1c-localization` |
| `vendor-compat` | перехоплення `&Перед`/`&После`/`&Вместо`/`&ИзменениеИКонтроль` коду вендора, запозичені форми; чи процедура така в дампі конфігурації-власника |
| `metadata` | XML метаданих і форм: uuid, `ConfigDumpInfo`, політика тексту споживача |
| приймальна «harm to other sessions» | база агента: збирання чи тест у базі, яку тримає інша сесія; `push` без `sourceSet` на серверній базі |

## Мовчазні класи дефектів

Синтаксично коректні конструкції, що проходили рев'ю на живому проєкті (#23). Той самий перелік
бере pre-commit перевірка BSL.

| Клас | Лінза | Ознака |
| --- | --- | --- |
| `property-default` | `correctness` | `Свойство(Ключ, Змінна)` без умовчання: за відсутнього ключа чи `null` у JSON — тихо `Неопределено` |
| `json-bool` | `correctness` | значення з розбору JSON у голій умові `Если X Тогда` |
| `client-eventlog` | `correctness` | `ЗаписьЖурналаРегистрации` у клієнтському чи клієнт-серверному модулі |
| `xdto-untyped` | `correctness` | `ФабрикаXDTO.ПрочитатьXML` без типу кореня: фасети XSD не перевіряються |
| `after-signature` | `vendor-compat` | сигнатура `&После` не повторює базову процедуру в `cf/src` посимвольно — платформа не підключає перехоплювач |
| `new-adopted-form` | `metadata` | нова форма з `ObjectBelonging=Adopted`: часто досить перехопити загальний модуль, який форма кличе |
| `dangling-form-uuid` | `metadata` | `uuid` у `Form.xml` запозиченої форми, яких немає ні в розширенні, ні в `cf/src` |
| `temp-doc-ref` | `drift` | коментар коду посилається на тимчасовий документ (план, спека, хеш) |
