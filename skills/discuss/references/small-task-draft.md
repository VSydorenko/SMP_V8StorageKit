# Чернетка малої задачі

Вихід для задачі, достатньо малої, щоб робити без спеки. Чернетка — це тіло GitHub issue в репозиторії проєкту.

## Тіло

```markdown
## Мета
<що змінюється і навіщо, 1–3 речення>

## Готово, коли
- [ ] <спостережний результат>
- [ ] <перевірка, що це доводить; мінімум — лише на логіку й механізми, які справді треба перевіряти>

## Зачіпає
<файли, модулі чи ділянки — як знайдено в коді>

## Ризики
<що може зламатись; вплив на дані, безпеку чи вартість; «немає», якщо нема>

## Поза межами
<чого ця задача не робить>
```

## Кроки

1. Покажи чернетку власнику в тексті ходу з одним AskUserQuestion: створити issue / щось змінити.
2. Після схвалення: `gh issue create --title "<коротке твердження>" --body-file <файл>` у репозиторії проєкту.
3. Нема GitHub remote (`git remote -v` не показує жодного на github.com): запиши чернетку в `docs/tasks/YYYY-MM-DD-<slug>.md`.
4. Дай власнику посилання на issue або шлях до файла.
