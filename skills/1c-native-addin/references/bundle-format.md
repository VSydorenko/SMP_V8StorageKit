# Формат бандла

- `manifest.xml` — контракт платформи: `os`, `arch`, `path`. **Ім'я DLL усередині версіонуй**
  (`…Win64_3_1_3_217.dll`): це розводить версії в каталозі встановлення й знімає залипання
  першого кеша (ключ — ім'я файлу).
- Файли, не перелічені в маніфесті, платформа не розпаковує (наприклад, криптопровайдери, що
  вантажаться динамічно). Це нормально й не дефект.
- `INFO.XML` — формат БСП на **один** драйвер на бандл: результат кладеться у пласку структуру,
  цикл по вузлах `component` не має виходу, тож при кількох вузлах лишається останній. Для
  бандла з кількома класами не годиться; класти не обов'язково.
- Власний файл опису (версія плюс перелік класів із `GetClassNames`) корисний для звірки складу
  збірки, але **не як джерело версії для коду**.
- **Одне символьне ім'я на всю бібліотеку.** Якщо одна DLL реєструє кілька класів,
  підключення робиться раз, а класи створюються як
  `Новый("AddIn." + СимвольноеИмя + "." + Клас)`. Різні символьні імена для класів однієї DLL
  вантажать її повторно.
