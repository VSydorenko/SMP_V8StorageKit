# Діагностика: компонента не підключається або вантажиться стара

## Чим міряти

| Не вірити | Чому | Чим міряти натомість |
|---|---|---|
| `tasklist \| grep`, `sc query \| grep` для процесів 1С | сліпі через кодування консолі: можуть показати «порожньо» при живих процесах | `Get-Process` у `pwsh` |
| «Версія драйвера» на картці драйвера | це оголошене, а не завантажене; оновлюється лише при відкритті форми списку драйверів | «Установленная версия» з `ОписаниеДрайвера` після підключення; sha DLL у каталозі встановлення |
| Рядки журналу реєстрації про відсутність компоненти | шаблони, що друкуються завжди | склад бандла, вивантаженого з Конфігуратора; вміст каталогу встановлення |

Два рядки виглядають як діагноз, а ним не є:

- «Для идентификатора X (версия не указана) в справочнике нет подходящей внешней компоненты.
  Состояние: НеНайдена» (рівень «Информация»): на шляху «з макета» версія жорстко
  `Неопределено`, тож «версия не указана» друкується завжди; порожній довідник — норма.
- «Возможно компонента не предназначена для клиентского приложения …»: шаблон, що друкується
  при будь-якому `Ложь`; про розрядність платформа нічого не стверджує.

Корисне з того ж повідомлення: технічна інформація містить реальне місцезнаходження
(`ОбщийМакет.<ім'я>`) — звідки платформа намагалась брати компоненту.

## Дерево рішень «не підключається»

Іди згори вниз, не перескакуючи.

1. **Що лежить у базі.** Вивантаж макет із Конфігуратора у файл і подивись усередину ZIP
   (`manifest.xml` і власний файл опису). Не покладайся на робочу копію git: вона може
   розходитись із базою.
2. **Що завантажилось.** Каталог встановлення: ім'я файлу й sha. Стара DLL при новому макеті —
   крок 3. Нічого не з'явилось — платформа не дійшла до розпакування.
3. **Живі сеанси.** `Get-Process`: `1cv8`, `1cv8c`, `ragent`, `rmngr`, `rphost`. Закрий усі
   клієнти й Конфігуратори, перезапусти кластер, повтори.
4. **Рестарт допоміг** — причина серверний кеш макетів; далі питання постачання
   (`references/delivery.md`).
5. **Не допоміг** — лише тоді дивись на бандл: маніфест, імена DLL, розрядність
   (`references/bundle-format.md`).

## Що причиною майже ніколи не є

Кожен пункт перевірено вимірами; не повторюй без нової підстави:

- наявність або форма `INFO.XML` у бандлі;
- «зайві» файли в ZIP (бандли вендора 1С несуть по два десятки файлів, включно з `.exe` і `.apk`);
- властивості ZIP-контейнера (метод стиснення, прапори, атрибути);
- структура DLL: імпорти, секції, версія лінкера;
- справність DLL (перевіряється локально `LoadLibraryExW` + `GetClassNames` + `GetClassObject`
  і майже завжди справна);
- антивірус і права на каталог (одна спроба створити там файл);
- версія платформи, якщо її не міняли;
- `/ClearCache`: він не чистить каталог встановлення.
