# Формат проєкту: вивантаження Конфігуратора

Файли метаданих, їхня розкладка й реєстрація для вихідників у форматі вивантаження Конфігуратора (платформа гілки 8.3.27). BSL-код модулів від формату не залежить.

Об'єкти метаданих тестового розширення (модулі, запозичення, перехоплювачі) створює Уніка (`unica.apply`, скіли `unica:meta-add`, `unica:cfe-borrow`, `unica:cfe-patch-method`). Цей документ і шаблони `templates/8.3.27/` — довідка для звірки результату, а не інструкція писати XML вручну.

## Ознаки формату

У корені вивантаження лежить `Configuration.xml`.

## Розташування проєктів

Де лежать вивантаження тестового розширення `Тесты` і вивантаження основної конфігурації (корені з `Configuration.xml`), а також інших розширень — береться з розділу `## Тести YaXUnit` у `CLAUDE.md` проєкту та з `v8project.yaml` воркспейсу. Людину про середовище не питай. Код основної конфігурації й інших розширень шукай і читай через Уніку (`unica.search`, `unica.view`).

Нижче `test/` — каталог вивантаження тестового розширення, `src/` — каталог вивантаження основної конфігурації.

## Розкладка файлів

Метадані об'єкта — файл `[Тип]/[ИмяОбъекта].xml`, модулі — в каталозі `[Тип]/[ИмяОбъекта]/Ext/`. Однаково для `test/` і `src/`.

| Тип об'єкта                          | Каталог модулів                        | Ім'я файлу            |
| ------------------------------------ | -------------------------------------- | --------------------- |
| Загальний модуль                     | `test/CommonModules/ИмяМодуля/Ext/`    | `Module.bsl`          |
| Модуль менеджера документа           | `test/Documents/ИмяДок/Ext/`           | `ManagerModule.bsl`   |
| Модуль об'єкта документа             | `test/Documents/ИмяДок/Ext/`           | `ObjectModule.bsl`    |
| Модуль менеджера довідника           | `test/Catalogs/ИмяСпр/Ext/`            | `ManagerModule.bsl`   |
| Модуль об'єкта довідника             | `test/Catalogs/ИмяСпр/Ext/`            | `ObjectModule.bsl`    |
| Модуль менеджера регістра відомостей | `test/InformationRegisters/ИмяРС/Ext/` | `ManagerModule.bsl`   |
| Модуль набору записів регістра       | `test/InformationRegisters/ИмяРС/Ext/` | `RecordSetModule.bsl` |

Об'єкт є в розширенні (новий чи запозичений), якщо є файл `test/[Тип]/[ИмяОбъекта].xml`.

`ConfigDumpInfo.xml` — службовий файл платформи: не створюй і не правь його, платформа веде його сама.

## Кодування й кінець файлу

Файли мають збігатися з тим, що пише платформа, інакше наступне вивантаження розширення розробником дасть дельту. Закінчення рядків (CRLF/LF) неважливі — їх нормалізує git. BOM і переведення рядка в кінці файлу git не нормалізує: вони мають бути такими, як у таблиці нижче.

| Файл   | Кодування    | Переведення рядка в кінці файлу |
| ------ | ------------ | ------------------------------- |
| `.xml` | UTF-8 з BOM  | немає                           |
| `.bsl` | UTF-8 з BOM  | наявний — не змінюй; новий — будь-який: платформа зберігає як є |

Файли мають бути такими, як їх пише 1С (таблиця вище). Тому:

- наявні файли (`Configuration.xml`, `.xml` і `.bsl` запозичених об'єктів) правь лише через Edit — він зберігає BOM файлу;
- після створення кожного нового `.xml` і `.bsl` виконай команду нижче: вона додає BOM, якщо його немає, і не чіпає файл, якщо BOM уже є. Шляхи в команді відносні й починаються з каталогу вивантаження тестового розширення `test\`: команда працює, якщо поточний каталог — той, у якому лежить `test\`. Інакше підстав абсолютні шляхи:

```powershell
foreach ($f in @('test\CommonModules\[Имя].xml', 'test\CommonModules\[Имя]\Ext\Module.bsl')) { $p = (Resolve-Path -LiteralPath $f).Path; $b = [IO.File]::ReadAllBytes($p); if ($b.Length -lt 3 -or $b[0] -ne 0xEF -or $b[1] -ne 0xBB -or $b[2] -ne 0xBF) { [IO.File]::WriteAllBytes($p, [byte[]](0xEF, 0xBB, 0xBF) + $b) } }
```

## Новий тестовий модуль

```
test/
  CommonModules/
    [ИмяТестовогоМодуля].xml    ← опис модуля (метадані)
    [ИмяТестовогоМодуля]/
      Ext/
        Module.bsl              ← код тесту
  Configuration.xml             ← реєстрація всіх модулів
```

**Перед створенням** — перевір, чи вже існує модуль з таким іменем (`test/CommonModules/[ИмяТестовогоМодуля].xml`). Якщо файл є, модуль уже зареєстрований: не чіпай `.xml` і `Configuration.xml`, працюй лише з `Module.bsl`.

Під час створення нового модуля (метадані й реєстрацію виконує Уніка; нижче — що має вийти):
1. `test/CommonModules/[ИмяТестовогоМодуля]/Ext/Module.bsl`
2. Модуль зареєстровано в `test/Configuration.xml` (розділ «Реєстрація в `Configuration.xml`»).
3. Файл `test/CommonModules/[ИмяТестовогоМодуля].xml`. `{uuidgen}` — унікальний UUID об'єкта метаданих; кожен модуль має свій UUID.

   Значення `ClientManagedApplication` і `ClientOrdinaryApplication` — за правилом контекстів компіляції (`references/compilation-contexts.md`):

   - **ОМ_ (загальний модуль)** — прочитай `src/CommonModules/[ИмяТестируемогоМодуля].xml` (через Уніку) і скопіюй значення `ClientManagedApplication` і `ClientOrdinaryApplication` звідти.
   - **Решта типів (Док_, РС_, Спр_ та ін.)** — завжди `false`/`false` (лише сервер).

   Прапорці контекстів, окрім `ClientManagedApplication`, на прогін не впливають: тести запускаються в тонкому клієнті, контексти зовнішнього з'єднання й звичайного застосунку в ньому не беруть участі. Тому `ClientOrdinaryApplication` копіюється як є, зокрема й у серверного модуля, а `ExternalConnection` завжди `false`. «Виклик сервера» і «Глобальний» — `false`, інакше YAxUnit не вважає модуль тестовим.

   Шаблон для звірки — `templates/8.3.27/common-module.xml` (шлях від кореня скілу `v8storagekit:1c-yaxunit`): `{uuidgen}` → новий UUID, `[ИмяТестовогоМодуля]` → ім'я модуля, `???` → значення з правил вище. Відступи — **табуляція**. BOM і кінець файлу — розділ «Кодування й кінець файлу».

## Запозичення об'єкта для перехоплювача

Перехоплювач — це **adopted**-розширення наявного об'єкта основної конфігурації. Дії залежать від стану об'єкта в розширенні:

- **Об'єкт не запозичений** (немає `test/[Тип]/[ИмяОбъекта].xml`) — XML-метадані (нижче) і реєстрація об'єкта (розділ «Реєстрація в `Configuration.xml`»).
- **Об'єкт запозичений, потрібного модуля немає** (наприклад, є `ObjectModule.bsl`, а потрібен `ManagerModule.bsl`) — створи файл модуля й звір наявний `test/[Тип]/[ИмяОбъекта].xml` із шаблоном: якщо в шаблоні є блок для модуля, що перехоплюється (`{расширяемый-модуль}`), має бути такий самий блок для нового модуля. UUID не змінюй, `Configuration.xml` не чіпай.
- **Модуль є** — метадані й реєстрацію не чіпай.

### Загальний принцип побудови XML

Структура XML перехоплювача будується на основі `src/[Тип]/[ИмяОбъекта].xml`:

1. **Кореневий тег** (`<CommonModule>`, `<Document>`, `<Catalog>`, `<InformationRegister>`) — новий UUID.
2. **`<InternalInfo>`** — скопіювати блок `<xr:GeneratedType>` із src, **замінивши всі UUID (TypeId і ValueId) на нові**; структура (імена, категорії, порядок) лишається точно такою самою. Решта вмісту `<InternalInfo>` — як у шаблоні.
3. **`<Properties>`** — мінімальний набір: `<Name>`, `<Comment/>`, `<ObjectBelonging>Adopted</ObjectBelonging>`, `<ExtendedConfigurationObject>{uuid кореневого тега з src}</ExtendedConfigurationObject>`. Для документів додатково порожній `<RegisterRecords/>`, для регістрів відомостей — `<InformationRegisterPeriodicity>` і `<WriteMode>` із src. Порядок властивостей — як у шаблоні.
4. Загальні модулі не мають `<xr:GeneratedType>` ні в src, ні в test — `<InternalInfo>` як у шаблоні.
5. **`<ChildObjects/>`** — у довідника, документа й регістра відомостей одразу після `</Properties>` порожній `<ChildObjects/>`; без нього збірка падає («ожидаемое ChildObjects»). У загального модуля цього тега немає.

UUID — для документа чи довідника зазвичай потрібно 11, для регістра 15.

### Шаблони запозичених об'єктів

Для звірки — шаблони з `templates/8.3.27/` (шлях від кореня скілу `v8storagekit:1c-yaxunit`), у них усі пункти вище вже враховано:

| Тип об'єкта        | Шаблон                             | Потрібно UUID |
| ------------------ | ---------------------------------- | ------------- |
| Загальний модуль   | `common-module-adopted.xml`        | 1             |
| Довідник           | `catalog-adopted.xml`              | 11            |
| Документ           | `document-adopted.xml`             | 11            |
| Регістр відомостей | `information-register-adopted.xml` | 15            |

Підстановки:

- `{новый-uuid}` — кожне входження замінюється **своїм** новим UUID (кореневий тег, усі `TypeId` і `ValueId`);
- `{uuid-из-src-xml}` — UUID кореневого тега з `src/[Тип]/[ИмяОбъекта].xml`;
- `[ИмяМодуля]` / `[ИмяСправочника]` / `[ИмяДокумента]` / `[ИмяРегистра]` — ім'я об'єкта, як у src (зокрема в атрибутах `name` блоків `<xr:GeneratedType>`);
- `???` — значення з src: у загального модуля `ClientManagedApplication`, `ExternalConnection`, `ClientOrdinaryApplication`, `ServerCall`; у регістра відомостей `InformationRegisterPeriodicity`, `WriteMode`;
- `{расширяемый-модуль}` (якщо є в шаблоні) — ім'я модуля, що перехоплюється (`ObjectModule`, `ManagerModule`, `RecordSetModule`); якщо модулів кілька — повтори блок, що його містить, для кожного.

## Реєстрація в `Configuration.xml`

Додається в `<ChildObjects>` файлу `test/Configuration.xml` серед тегів того самого типу тег, що відповідає типу об'єкта. Місце рядка:

- усі теги цього типу (всередині групи) уже впорядковані за алфавітом — встав за алфавітом: без урахування регістру, `_` раніше за цифри, цифри раніше за латиницю, латиниця раніше за кирилицю;
- не впорядковані — встав у кінець групи тегів цього типу, кілька нових — у порядку створення (так новий об'єкт додає й сам Конфігуратор).

Наявні рядки не переставляй. На завантаження й вивантаження порядок не впливає.

```xml
<ChildObjects>
    ...
    <!-- группа по алфавиту -->
    <CommonModule>ОМ_Колеровка</CommonModule>
    <CommonModule>[ИмяТестовогоМодуля]</CommonModule>
    <CommonModule>ОМ_МерныеТоварыВызовСервера</CommonModule>
    ...
</ChildObjects>
```

```xml
<CommonModule>ИмяМодуля</CommonModule>
<!-- или -->
<Document>ИмяДокумента</Document>
<!-- или -->
<Catalog>ИмяСправочника</Catalog>
<!-- или -->
<InformationRegister>ИмяРегистра</InformationRegister>
```

Adopted-об'єкти реєструються так само, як нові, — просто за іменем, без спеціальних атрибутів.

## Чекліст формату

- [ ] Файл створено в `test/CommonModules/[Имя]/Ext/Module.bsl`
- [ ] Створено файл метаданих `test/CommonModules/[Имя].xml` з унікальним UUID
- [ ] Модуль зареєстровано в `test/Configuration.xml` (у `<ChildObjects>`; місце рядка — за правилом розділу «Реєстрація в `Configuration.xml`»)
- [ ] Перехоплювач (якщо об'єкт запозичено вперше): XML побудовано за шаблоном (у довідника, документа, регістра є `<ChildObjects/>`) і об'єкт зареєстровано в `test/Configuration.xml`; якщо до вже запозиченого об'єкта додано модуль — його `.xml` звірено із шаблоном
- [ ] Усі створені `.xml` і `.bsl` починаються з BOM, `.xml` — без переведення рядка в кінці (розділ «Кодування й кінець файлу»)
