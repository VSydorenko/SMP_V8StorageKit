# Тестові дані в YAxUnit

Доступ: `ЮТест.Данные()` — повертає модуль `ЮТТестовыеДанные`.

---

## КонструкторОбъекта — створення об'єктів ІБ

```bsl
ЮТест.Данные().КонструкторОбъекта("Вид.Имя")
```

Підтримує довідники, документи, ПВХ, регістри відомостей (не підпорядковані регістратору). Плинний інтерфейс.

### Заповнення реквізитів

| Метод | Опис |
|-------|------|
| `Установить(ИмяРеквизита, Значение)` | Конкретне значення реквізиту |
| `УстановитьРеквизиты(Структура)` | Кілька реквізитів зі Структури |
| `Фикция(ИмяРеквизита, РеквизитыЗаполнения, ОграничениеТипа)` | Випадкове валідне значення (примітивні — випадкове, посилальні — новий об'єкт, перелічення — випадкове значення) |
| `ФикцияРеквизитов("Рекв1, Рекв2")` | Випадкові значення для кількох реквізитів (рядок через кому або Масив) |
| `ФикцияОбязательныхПолей()` | Заповнити всі поля з «Перевірка заповнення = Видавати помилку» |
| `ФикцияНезаполненных(ИменаРеквизитов)` | Випадкові значення для незаповнених реквізитів |
| `ФикцияНезаполненныхИсключая(ИменаРеквизитов)` | Усі незаповнені, крім указаних |

### Табличні частини

| Метод | Опис |
|-------|------|
| `ТабличнаяЧасть(ИмяТЧ)` | Перемкнутися на табличну частину |
| `ДобавитьСтроку(ЗначенияРеквизитов)` | Додати рядок (параметр — Структура, опційно) |
| `Объект()` | Повернути контекст конструктора на шапку (після роботи з ТЧ) |
| `ДанныеСтроки()` | Дані поточного рядка ТЧ |

`ТабличнаяЧасть`/`Объект` лише перемикають, куди потрапляють наступні `Установить`/`ДобавитьСтроку`/`Фикция`. На `Записать` цей вказівник не впливає — запис завжди йде по всьому об'єкту (шапка + усі ТЧ). Тому `Объект()` потрібен **лише** тоді, коли після ТЧ знову заповнюєш реквізити шапки або перемикаєшся на іншу ТЧ. **Перед `Записать()` він зайвий** — не додавай його:

```bsl
// ✅ Записать сразу после строк ТЧ — Объект() не нужен
ЮТест.Данные().КонструкторОбъекта("Документ.ВнутреннийЗаказ")
    .ТабличнаяЧасть("Товары")
        .ДобавитьСтроку(Новый Структура("Размещение", ЗаказПоставщику))
    .Записать( , Истина);

// ✅ Объект() нужен: после ТЧ возвращаемся в шапку
ЮТест.Данные().КонструкторОбъекта("Документ.ЗаказКлиента")
    .ТабличнаяЧасть("Товары")
        .ДобавитьСтроку(Новый Структура("Товар, Количество", Товар, 10))
    .Объект()
        .Установить("Комментарий", "Заполнили ТЧ, потом шапку")
    .Записать( , Истина);
```

### Запис

| Метод | Опис |
|-------|------|
| `Записать(ВернутьОбъект, ОбменДаннымиЗагрузка)` | Записати. `Истина` — повернути об'єкт, інакше — посилання. Другий параметр: `Истина` — запис з `ОбменДанными.Загрузка = Истина` |
| `Провести(ВернутьОбъект)` | Записати й провести документ |
| `ДобавитьЗапись(ОбменДаннымиЗагрузка)` | Записати й повернути конструктор (для ланцюжка записів) |
| `НовыйОбъект()` | Створити об'єкт без запису в БД |
| `ДанныеОбъекта()` | Дані об'єкта у вигляді Структури |

Об'єкт для юніт-тесту без запису в БД (перевірка заповнення, обробники об'єкта в пам'яті) створюй через `КонструкторОбъекта(...)...НовыйОбъект()`, а не через `СоздатьЭлемент()` / `СоздатьДокумент()` менеджера: конструктор заповнює реквізити тими самими `Установить` / `Фикция`, транзакція не потрібна.

### Додатково

| Метод | Опис |
|-------|------|
| `УстановитьСсылкуНового(Значение)` | Задати UUID посилання (УникальныйИдентификатор або Строка) |
| `УстановитьДополнительноеСвойство(ИмяСвойства, Значение)` | Довільна властивість, що не є реквізитом |

**Правило:** використовуй `Фикция("Реквизит")` замість `Установить("Реквизит", ЮТест.Данные().СоздатьЭлемент(...))`.

## КонструкторДвижений — створення рухів документа

```bsl
ЮТест.Данные().КонструкторДвижений(Документ, ИмяРегистра)
```

Створює рухи документа. Працює з регістрами накопичення, бухгалтерії й розрахунку (вони завжди підпорядковані регістратору), а також з регістром відомостей — але лише якщо той підпорядкований регістратору (наприклад `ЦеныНоменклатуры`). `ИмяРегистра` — рядок; допустимо як повне ім'я (`"РегистрНакопления.ТоварыНаСкладах"`), так і коротке (`"ЦеныНоменклатуры"`). `Документ` — регістратор (посилання або об'єкт). Плинний інтерфейс.

Для регістра відомостей, **не** підпорядкованого регістратору, використовуй `КонструкторОбъекта` (див. вище).

```bsl
// Регистр сведений, подчиненный регистратору (ЦеныНоменклатуры)
Регистратор = ЮТест.Данные().СоздатьДокумент("Документы.УстановкаЦенНоменклатуры");
ЮТест.Данные().КонструкторДвижений(Регистратор, "ЦеныНоменклатуры")
    .ДобавитьСтроку()
        .Установить("Период", Период)
        .Установить("ТипЦен", ТипЦен)
        .Установить("Номенклатура", Номенклатура)
        .Установить("Цена", Цена)
.Записать();
```

| Метод | Опис |
|-------|------|
| `ДобавитьСтроку(ЗначенияРеквизитов)` | Додати запис (Структура, опційно) |
| `Установить(ИмяРеквизита, Значение)` | Значення реквізиту поточного запису |
| `УстановитьРеквизиты(Структура)` | Кілька реквізитів |
| `Фикция(ИмяРеквизита, РеквизитыЗаполнения, ОграничениеТипа)` | Фіктивне значення |
| `ФикцияРеквизитов("Рекв1, Рекв2")` | Фіктивні значення для кількох |
| `ФикцияОбязательныхПолей()` | Обов'язкові реквізити запису |
| `ФикцияНезаполненных(ИменаРеквизитов)` | Незаповнені реквізити |
| `ФикцияНезаполненныхИсключая(ИменаИсключений)` | Усі незаповнені, крім указаних |
| `Записать(ОбменДаннымиЗагрузка)` | Зафіксувати рухи |
| `ДанныеСтроки()` | Дані поточного запису |
| `Данные()` | Дані всього набору записів |

За замовчуванням період = дата документа. Можна задати свій: `Установить("Период", Дата)`.

## Посилання як значення без створення об'єкта

Якщо тесту потрібне посилання лише як значення для порівняння (а не реальний запис у БД), використовуй `ПолучитьСсылку()`:

```bsl
Адрес = Справочники.Адреса.ПолучитьСсылку();
```

Це дешевше за `КонструкторОбъекта(...).Записать()` — об'єкт не створюється, транзакція не потрібна. Підходить, коли тестований код лише порівнює передане значення з реквізитом (наприклад, `ГДЕ Т.АдресОбъекта = &АдресОбъекта`). Або коли, крім посилання, з об'єкта нічого не потрібно, або коли звернення до об'єкта немає.

### Дати

```bsl
ЮТест.Данные().СлучайнаяДата()
ЮТест.Данные().СлучайноеВремя()
ЮТест.Данные().СлучайнаяДатаВБудущем(Количество, Единица)   // "часа", "дня", "месяца"

ЮТест.Данные().СлучайнаяДатаДо(Дата, Количество, Единица)
```

**Фіксовану дату задавай літералом, а не конструктором `Дата(...)`** — літерал читається краще й не плодить попередження про «магічні числа»:

```bsl
// ❌ Плохо — конструктор с набором чисел
ДатаИсходная = Дата(2021, 05, 10, 09, 50, 00);

// ✅ Хорошо — литерал 'ГГГГ-ММ-ДД чч:мм:сс'
ДатаИсходная = '2021-05-10 09:50:00';
```

**Виняток — порожня дата:** `Дата(1, 1, 1)` залишай конструктором. Це усталена практика, читається простіше за літерал `'0001-01-01'`.

## Видалення тестових даних

База агента спільна: тест не спирається на наявні в базі дані, а дані, які пише, пише лише в транзакції на рівні тесту (`ВТранзакции()`); подробиці — розділ «Спільна база агента» в `SKILL.md` цього скілу.

### Транзакції (відкіт усіх змін)

```bsl
ЮТТесты.ДобавитьТест("ИмяТеста").ВТранзакции()       // конкретный тест
ЮТТесты.ДобавитьТестовыйНабор("Набор").ВТранзакции()  // набор
ЮТТесты.ВТранзакции()                                  // все тесты модуля
```

Обгортається: тест + `ПередКаждымТестом`/`ПослеКаждогоТеста`. Дані з `ПередВсемиТестами` НЕ відкочуються. Для клієнтських тестів ігнорується.

### Механізм видалення

```bsl
ЮТТесты.ДобавитьТест("ИмяТеста").УдалениеТестовыхДанных()
ЮТТесты.ВТранзакции().УдалениеТестовыхДанных()   // совместно
```

Запам'ятовує всі створені через API об'єкти. Видаляє дані з клієнта. НЕ працює для даних, створених не через API або всередині тестованого коду.
