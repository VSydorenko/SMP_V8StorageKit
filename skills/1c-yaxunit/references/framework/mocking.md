# Мокування з Мокито

## Три фази тестування

1. **Навчання** — налаштування поведінки методів
2. **Прогін** — виконання тестованого коду з активними моками
3. **Перевірка** — аналіз статистики викликів

**Де створювати тестові дані:**

- **до `Мокито.Обучение`** — якщо під час створення даних мок спрацьовувати не має: виконується реальний код, виклики в статистику не потрапляють;
- **після `Прогон()`** — якщо під час створення даних потрібна реакція моку: виклики потраплять у статистику, враховуй їх у `КоличествоВызовов` або відсікай умовами на параметри;
- **між `Обучение` і `Прогон()` — нічого**: мокований метод там не виконується, а повертає службову структуру Мокито.

```bsl
// ❌ Плохо — данные создаются посреди обучения
Мокито.Обучение(Справочники.Номенклатура)
    .Когда("ЦенаПоУмолчанию").Вернуть(100);
Товар = ЮТест.Данные().КонструкторОбъекта("Справочник.Номенклатура").НовыйОбъект();
// если заполнение вызывает ЦенаПоУмолчанию, оно получит не 100 и не реальную цену,
// а служебную структуру Мокито: обучение еще не закончено
Мокито.Прогон();
```

Після `Мокито.Проверить` тестований код не викликай: виклики мокованих методів знову перехоплюються й не виконуються.

## Навчання (Training)

### Точка входу

```bsl
Мокито.Обучение(Объект)
Мокито.Обучение(Объект, Ложь)    // дообучение: прежние настройки мока объекта сохраняются
```

`Объект` — спільний модуль, менеджер (`Справочники.X`, `Документы.X`, `РегистрыСведений.X`), об'єкт або посилання.

Другий параметр `СброситьСтарыеНастройки` за замовчуванням `Истина`: повторне `Обучение` того самого об'єкта забуває всі його попередні налаштування. Щоб додати правила до вже налаштованого об'єкта, передай `Ложь`.

### Вказівка методу

```bsl
.Когда("ИмяМетода")                         // по имени строкой
.Когда("ИмяМетода", МассивПараметров)        // с условиями на параметры
.Когда(Модуль.Метод(Парам1, Парам2))         // через реальный вызов (во время обучения вызовы возвращают информацию о вызове)
```

### Реакції

| Метод | Опис |
|-------|------|
| `.Вернуть(Значение)` | Повернути значення. Можна ланцюжком для послідовних викликів |
| `.ВыброситьИсключение(Текст)` | Викинути виняток |
| `.Пропустить()` | Пропустити виконання методу |
| `.ВыполнитьМетод()` | Виконати реальний метод (перевизначення моку для конкретних умов) |

### Спостереження

```bsl
.Наблюдать("ИмяМетода")                     // наблюдать без изменения поведения
.Наблюдать("ИмяМетода", МассивПараметров)    // наблюдать с условиями на параметры
```

### Фіналізація

```bsl
.Прогон()                                    // завершить обучение, активировать моки
```

## Ланцюжок навчань кількох об'єктів

```bsl
Мокито
    .Обучение(Модуль1)
        .Когда("Метод1")
            .Вернуть(Значение1)
    .Обучение(Модуль2)
        .Когда("Метод2")
            .Вернуть(Значение2)
    .Прогон();
```

---

## Ланцюжок повернень (послідовні виклики)

```bsl
Мокито.Обучение(Интеграция)
    .Когда("ВыполнитьЗапрос")
        .Вернуть(1)     // 1-й вызов
        .Вернуть(2)     // 2-й вызов
        .Вернуть(3)     // 3-й и все последующие
    .Прогон();
```

## Кілька методів одного об'єкта

```bsl
Мокито.Обучение(РегистрыСведений.КоэффициентыСезонностиТоварныхЗапасов)
    .Когда("ДобавитьЗапись")
        .Пропустить()
    .Наблюдать("ДобавитьЗапись")
.Обучение(ЦелевыеТоварныеЗапасы)
    .Когда("ПолучитьКоэффициентыСезонности")
        .Вернуть(Коэффициенты)
.Прогон();
```

## Параметри-умови

| Метод | Пріоритет | Опис |
|-------|-----------|------|
| Конкретне значення | 100 | Точний збіг |
| `Мокито.Параметр(Предикат)` | 90 | Предикатна умова |
| `Мокито.ЧисловойПараметр()` | 10 | Будь-яке число |
| `Мокито.СтроковыйПараметр()` | 10 | Будь-який рядок |
| `Мокито.ТипизированныйПараметр(Тип)` | 10 | Параметр указаного типу |
| `Мокито.ЛюбойПараметр()` | 0 | Будь-яке значення |

За збігу кількох умов виграє варіант із **найбільшою сумою пріоритетів параметрів**. За рівності — перший зареєстрований.

```bsl
Мокито.МассивПараметров(Парам1, Парам2, ...)  // создать массив параметров для условий
```

**Правила:**
- Без параметрів = відповідає ВСІМ викликам
- Часткові параметри = перевіряються лише вказані, решта ігнорується

## Перевірка (Verification)

```bsl
Мокито.Проверить(Объект)
    .КоличествоВызовов("ИмяМетода")      // все вызовы метода; далее по цепочке .Равно(N), .Пусто() и т.д.
    .Вызовы("ИмяМетода")                 // возвращает массив записей вызовов, каждая с .Параметры
```

Другим параметром `КоличествоВызовов` і `Вызовы` приймають масив умов на параметри, ті самі, що в `Когда` / `Наблюдать` (див. «Параметри-умови»). Враховуються лише виклики, що підпадають під умови:

```bsl
Мокито.Проверить(РегистрыСведений.ЦеныНоменклатуры)
    .КоличествоВызовов("ПолучитьЦену", Мокито.МассивПараметров(Номенклатура, Мокито.ЛюбойПараметр()))
    .Равно(1);
```

## Область застосування навчання

| Навчання через | Методи менеджера | Методи об'єкта |
|----------------|------------------|----------------|
| **Менеджер** | Так | Для ВСІХ об'єктів цього типу |
| **Об'єкт** | Ні | Лише для цього конкретного об'єкта |
| **Посилання** | Ні | Для об'єктів із цим посиланням |

## Обмеження

- Працює лише для **методів конфігурації** (через `&Вместо`)
- НЕ може мокувати: вбудовані методи платформи, методи розширень, зовнішніх обробок/звітів
- НЕ може виконувати довільну логіку під час виклику методу
- НЕ може модифікувати параметри методу — як покривати гілку, що залежить від зміни параметра, див. `references/writing.md`, розділ «Гілка, що залежить від зміни параметра мокованим методом»

> Потрібно створити новий файл-перехоплювач або додати метод `&Вместо` в наявний? → читай `references/interceptors.md`.

## Коли застосовувати Мокито

- Метод звертається до менеджера довідника/документа/регістра
- Метод викликає зовнішній HTTP-сервіс
- Потрібно перевірити кількість/параметри викликів залежності
- Тест без моку вимагав би створення реальних даних у БД (повільно, крихко)

## Коли Мокито не потрібен

- Тестований метод працює лише з переданими параметрами (чиста функція)
- Інтеграційний тест, де потрібна реальна БД (познач тест тегом "Интеграционный")

## Реальні приклади з проєкту

### Заглушка спільного модуля

```bsl
Мокито.Обучение(КолеровкаПовтИсп)
    .Когда("ЭтоКолеровка")
        .Вернуть(Истина)
    .Прогон();
```

### Заглушка менеджера регістра відомостей

```bsl
Мокито.Обучение(РегистрыСведений.НастройкиОпределенияУслугиКолеровка)
    .Когда("НайтиУслугуКолеровки")
        .Вернуть(Ожидание)
    .Прогон();
```

### Заглушка менеджера довідника

```bsl
Мокито.Обучение(Справочники.Номенклатура)
    .Когда("НайтиНоменклатуруПоКоду")
        .Вернуть(ОписаниеТоваров)
    .Прогон();
```

### Заглушка менеджера документа

```bsl
Мокито.Обучение(Документы.ЗаказПокупателя, Ложь)   // Ложь - дообучение, см. «Точка входа»
    .Когда("ПолучитьДоступныеОбъектыПроектныхПродажПоОписанию")
        .Вернуть(Новый Массив())
    .Наблюдать("ПолучитьДоступныеОбъектыПроектныхПродажПоОписанию")
    .Прогон();
```

### Спостереження + перевірка кешування

```bsl
Мокито.Обучение(КолеровкаПовтИсп)
    .Наблюдать("ЭтоКолеровка")
    .Прогон();

КолеровкаПовтИсп.ЭтоКолеровка(Справочники.Номенклатура.Доставка);
КолеровкаПовтИсп.ЭтоКолеровка(Справочники.Номенклатура.Доставка);

Мокито.Проверить(КолеровкаПовтИсп)
    .КоличествоВызовов("ЭтоКолеровка")
        .Равно(1);
```

### Ланцюжок навчань кількох об'єктів із Пропустить і Наблюдать

```bsl
Мокито
    .Обучение(РегистрыСведений.КоэффициентыСезонностиТоварныхЗапасов)
        .Когда("ДобавитьЗапись")
            .Пропустить()
        .Наблюдать("ДобавитьЗапись")
    .Обучение(ЦелевыеТоварныеЗапасы)
        .Когда("ПолучитьКоэффициентыСезонности")
            .Вернуть(Коэффициенты)
    .Прогон();
```

### Множинне навчання одного модуля (різні задачі)

```bsl
Мокито.Обучение(Колеровка)
    .Когда("НайтиУслугуКолеровкиПоВидуКолеровки")
        .Вернуть(Справочники.Номенклатура.ПустаяСсылка())
    .Прогон();

Мокито.Обучение(Колеровка, Ложь)   // Ложь — дообучение: заглушка выше сохраняется
    .Наблюдать("НайтиУслугуКолеровкиПоВидуКолеровки")
    .Прогон();
```
