# Теги в YAxUnit

Теги — механізм групування й фільтрації тестів під час запуску. Тег можна повісити на **модуль**, **тестовий набір** або **окремий тест** — обирай рівень, який точніше описує область. Скільки тестів писати, задає план; цей текст — лише форма тесту.

Два способи задати теги:
- **`.Тег("Один")`** — ланцюжком, по одному
- **Параметр `ТегиСтрокой`** в `ДобавитьТест` / `ДобавитьТестовыйНабор` — через кому: `"Интеграционный, Критичный"`

## Тег проєкту/ініціативи

Ідентифікатор задачі береться з плану чи брифу. Якщо він є (задача, проєкт, SRS тощо), став його тегом — він дає змогу запустити лише тести за цим тегом. Немає ідентифікатора — тест без проєктного тега, **без питання** людині.

Проєктний тег має найнижчий пріоритет під час ухвалення рішень про структуру — **не повинен бути критерієм для переробки всієї структури тестів**.

## Рівні тегування

Став тег на рівні, де він точно описує **всі** елементи нижче. Якщо поставити тег вище, ніж потрібно, він поширюється на тести, для яких неактуальний, — фільтрація за ним притягне зайве. **Не дублюй тег на кожен тест, якщо він уже стоїть на наборі чи модулі.**

**На модулі** — коли тег актуальний для всіх тестів модуля:

```bsl
// Все тесты модуля интеграционные и относятся к одному проекту
ЮТТесты
    .Тег("srs-148")
    .Тег("Интеграционный")
    .ВТранзакции()
    .ДобавитьТестовыйНабор("РС_Пример_ММ: запись")   // тег модуля действует на все наборы
        .ДобавитьТест("ЗаписьСохраняетДанные")
        .ДобавитьТест("ЗаписьПерезаписываетСуществующую")
    ;
```

**На тестовому наборі** — коли тег актуальний для всіх тестів набору, але не для всього модуля:

```bsl
// Набор "Запись" — все интеграционные; набор "Валидация" — юниты; теги разные → на наборе
ЮТТесты
    .ДобавитьТестовыйНабор("РС_Пример_ММ: запись", "srs-571, Интеграционный")
        .ВТранзакции()
            .ДобавитьТест("ЗаписьСохраняетДанные")        // тег унаследован от набора
            .ДобавитьТест("ЗаписьОбновляетСуществующую")  // тег унаследован от набора
    .ДобавитьТестовыйНабор("РС_Пример_ММ: валидация", "srs-148")
        .ДобавитьТест("ПроверкаЗаполненияВозвращаетОшибку")
    ;
```

**На окремому тесті** — коли тег актуальний лише для конкретного тесту:

```bsl
// Внутри набора тесты смешанные: один юнит, один интеграционный → тег только на нужный тест
ЮТТесты
    .ДобавитьТестовыйНабор("РС_Пример_ММ: поиск и запись")
        .ДобавитьТест("ПоискВозвращаетПустойРезультат", , "srs-100")       // юнит
        .ДобавитьТест("ЗаписьСохраняетДанные", , "srs-100, Интеграционный")
            .ВТранзакции()
    ;
```

### Наявний модуль: тег іншої задачі на рівні модуля

Якщо в наявному модулі на рівні модуля стоїть проєктний тег іншої задачі, новий набір успадкує його, і фільтрація за чужим тегом притягне твої тести. Перенеси цей тег на набори, до яких він належить, а свій проєктний тег постав на новий набір. Решту реєстрації наявних тестів не змінюй.

```bsl
// ❌ Было: тег srs-100 на модуле - новый набор srs-200 получит его по наследству
ЮТТесты
    .Тег("srs-100")
    .ДобавитьТестовыйНабор("ОМ_Пример: старый аспект")
        .ДобавитьТест("СтарыйТест")
    .ДобавитьТестовыйНабор("ОМ_Пример: новый аспект", "srs-200")
        .ДобавитьТест("НовыйТест")
    ;

// ✅ Стало: каждый проектный тег - на своем наборе
ЮТТесты
    .ДобавитьТестовыйНабор("ОМ_Пример: старый аспект", "srs-100")
        .ДобавитьТест("СтарыйТест")
    .ДобавитьТестовыйНабор("ОМ_Пример: новый аспект", "srs-200")
        .ДобавитьТест("НовыйТест")
    ;
```

Видали лише виклик `.Тег(...)`: якщо в рядку, окрім нього, нічого немає — рядок цілком, якщо в тому самому рядку є інші виклики ланцюжка (`ЮТТесты.Тег("srs-100").ВТранзакции()`) — лише `.Тег(...)`, решту викликів залиш. Відступи решти рядків ланцюжка не змінюй — у diff має потрапити лише перенесений тег. Новий набір додавай з тими самими відступами, що й в наявних наборів модуля.

Теги, які описують усі тести модуля, включно з новими (наприклад, `"Интеграционный"`, коли нові тести теж інтеграційні), залиш на рівні модуля.

## Типові теги

| Тег              | Призначення                                              |
| ---------------- | -------------------------------------------------------- |
| `srs-NNN`        | Ідентифікатор задачі (задача, проєкт, SRS тощо)          |
| `Интеграционный` | Тест працює зі справжньою БД, файлові операції тощо      |
| `Компонентный`   | Компонентний тест (кілька модулів разом)                 |
