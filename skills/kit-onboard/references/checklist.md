# Чекліст підключення

Кроки A–D нічого не змінюють.

## A. Скан (лише читання)

- [ ] Відомо `git status` проєкту; запиши незакомічені файли інших сесій — ти їх ніколи не чіпаєш.
- [ ] `kit-scan` у корені проєкту → збережи таблицю (вона основа звіту).
- [ ] Розділ `Kit version` у `kit-scan`: актуально, перше підключення чи відставання з кроками `V1…Vn` → пройди їх, як каже абзац **Оновлення** скіла.
- [ ] `kit-setup -DryRun` → збережи різниці.
- [ ] Код: вхід — Уніка (`unica.view {}`); `v8project.yaml` на місці й профіль його не дублює. Уніки на машині немає → запиши це як факт для звіту (агенти шукатимуть `git grep`).
- [ ] Залишки superpowers: `docs/superpowers/*` (спеки, плани, handoff), `.superpowers/sdd/` (журнали — читаються на місці, не переносяться), `superpowers:*` у `CLAUDE.md`, проєктних командах і пам'яті.
- [ ] Користувацькі скіли, які проєкту не потрібні → кандидатний перелік `skillOverrides` для звіту.
- [ ] Глосарій (`docs.glossary`) і тека ADR (`docs.adr`) існують? Якщо ні, а в проєкті є спеки → збери терміни й рішення (крок 6 скіла, частина «збери»; лише читання).
- [ ] Розділ скану про місця поза репозиторієм: кожна звичайна тека — рядок **move** із надрукованою командою `mkdir -p … && mv <тека> <репо>/.agents/private/<ім'я>`; спершу зазирни всередину (що тримає, дата найновішого файла) і перевір `session-board` на сесію, що там працює. Рядок git worktree — **leave**: його ніколи не переміщують і не створюють заново — `pr-gate cleanup` прибирає його, коли блок закінчується. З наявними worktree більше нічого не роблять.

## B. Класифікуй

- [ ] Кожен рядок **дублікат / прототип**: відкрий файл; клас remove · keep-knowledge · keep + kit issue; для keep-knowledge назви ціль (поле профілю чи файл проєкту).
- [ ] Кожен рядок **superpowers**: replace (частина kit, яку називає `kit-scan`) · remove (частини kit немає за рішенням власника) · keep (запланована частина kit — її issue). Документи й журнали superpowers — клас read-in-place / keep / delete зі скіла.
- [ ] Кожен рядок **пам'яті** і перелік «лише застарілі шляхи»: pointer · delete · keep-as-history · move-to-profile. Текст pointer = один рядок на інструмент чи поле профілю + політика, що лишається. Окремо пам'ять про процедури, які тепер робить kit (адаптації SDD «без worktree / без паралельних виконавців у спільній базі», «субагенти не комітять», «коміти лише точково», «прогін лише зачепленого» тощо): що kit тепер каже сам (`v8storagekit:execute`, режим `shared`) → pointer; що лишається специфікою проєкту → keep.
- [ ] **Індекс пам'яті**: файли, яких бракує в `MEMORY.md`, і посилання на відсутні файли.
- [ ] Дивись далі скану: кореневі правила, що описують процедуру, яку робить інструмент kit (злиття, запуски рев'ю, цикли очікування).

## C. Профіль

- [ ] `workspace.mode`: `shared` для 1С-репозиторію з базою агента (`v8project.yaml`, провізована база), `worktree` без бази.
- [ ] `pr`: `base` (головна гілка), `mergeMethod` (історія + власник), `afterMerge` (перевірки після злиття, якщо є).
- [ ] <!-- tests: ADR-0004, pending owner discussion --> Розділ профілю про тести — лише так, як скаже власник; без нього не вигадуй рівнів і прогонів.
- [ ] `docs`: справжні теки спек, планів і документів; теки скілів.
- [ ] `research.corpus`: глоби документів, що існують.
- [ ] `review.criteria` — файл предметних критеріїв проєкту (якщо їх перенесено з ручного рев'ю); `review.exclude` та інші розділи лише з фактів.
- [ ] Секрети й значення машини — у git-ignored `.agents/kit.profile.local.json`, ніколи в закомічений профіль.

## D. Звіт власнику (до будь-якої зміни)

- [ ] Таблиця `елемент → клас → дія` для кожного рядка B.
- [ ] Кожен рядок `V` у `Kit version`: apply · done · n/a · owner, із дією (скіл: **Оновлення**).
- [ ] Кожен рядок **move** з його командою `mv` і тим, що тримає тека (розмір, дата найновішого файла); рядки worktree названо **leave**.
- [ ] JSON профілю, питання власнику позначено.
- [ ] Вивід `kit-setup -DryRun`.
- [ ] Дослівний новий текст кожної правки `CLAUDE.md` і проєктних команд: спеки за скілом `v8storagekit:spec`; віхи лише в GitHub (`v8storagekit:track`); один рядок «план — `v8storagekit:plan`, виконання — `v8storagekit:execute`, PR — `pr-gate`, спека — `doc <файл> §N`, терміни — глосарій, рішення — ADR». Кожне посилання `superpowers:*` у кореневих правилах → відповідний скіл `v8storagekit:*` (таблиця в known-duplicates.md).
- [ ] Чернетка глосарію, перелік ADR і питання власнику (крок 6 скіла, частина «звіт»), якщо крок A нічого не знайшов.
- [ ] Власник схвалив (цитата схвалення).

## E. Застосуй (одна гілка, один PR у проєкті)

- [ ] `kit-setup` (налаштування, `.gitignore`, скелет профілю) і заповнений профіль.
- [ ] Видалення й переноси keep-knowledge точно як схвалено.
- [ ] Переміщення тек точно як схвалено — вони поза git, тож роби їх після коміту `kit-setup`, що кладе `.agents/private/` у `.gitignore`; перед кожним `mv` знову `session-board` і дата найновішого файла; там працює сесія → стоп і спитай. Ніколи не `mv` git worktree.
- [ ] Правки кореневих правил точно як схвалено.
- [ ] Глосарій, ADR і переписування спек як схвалено — один коміт на спеку (крок 6 скіла, частина «пиши»).
- [ ] Останній коміт: `"kit": { "version": "<версія плагіна>" }` у `.agents/kit.profile.json`, коли закрито кожен рядок `V`; `kit-scan` тоді каже `up to date`.
- [ ] PR відкрито `pr-gate open`; зливає власник.
- [ ] Пам'ять: pointer, видалення, переноси як схвалено; `MEMORY.md` оновлено в тому ж кроці.

## F. Користувацькі скіли

- [ ] `skillOverrides` записано в `.claude/settings.json` для скілів, які обрав власник.

## G. Закрий

- [ ] Один рядок власнику: посилання на PR, видалене, скорочені пам'яті, що лишилось власнику.
