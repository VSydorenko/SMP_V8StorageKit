# ADR

**Завантаж, коли** рішення вагоме (див. §2 скіла) або змінюється прийнятий ADR.

## Файл

`<docs.adr>/NNNN-<slug>.md`. Нумерація наскрізна на весь проєкт: найбільший наявний номер + 1. Одне рішення — один файл.

```markdown
# ADR-NNNN: <рішення одним рядком>

Status: proposed | accepted <дата> | superseded by ADR-MMMM
Supersedes: ADR-KKKK            ← лише коли замінює інший
Decided by: owner | architect
Spec: <шлях спеки §N, де рішення видно як стан>

## Context
<Сили: яка проблема, яке обмеження, що робить код сьогодні.
Два–шість речень.>

## Decision
<Що вирішено — як правило, яке читач може перевірити.>

## Why
<Причини, що перемогли. Факти з file:line, URL або пакет@версія.>

## Rejected
- <варіант> — <чому ні, одним рядком>

## Consequences
<Що стає легшим, що важчим, що не можна «виправляти» пізніше, бо воно навмисне.>
```

## Правила

- Вагоме = важко відкотити, АБО неочевидне без контексту, АБО справжній компроміс; плюс кожне рішення, яке ставили власнику. Решта — дрібні рішення: стан у спеці, причина в повідомленні коміту.
- Прийнятий ADR за змістом не правлять. Лише описки й посилання. Змінене рішення — новий ADR із `Supersedes:`; статус старого міняють у тому самому коміті.
- Спека посилається на ADR (`ADR-NNNN`) там, де рішення видно; «чому» не повторює.
