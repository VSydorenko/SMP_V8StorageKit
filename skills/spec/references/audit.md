# Аудит спеки

**Завантаж, коли** пишеш бриф агентам `spec-auditor` або зважуєш їхні знахідки.

## Лінзи

| Лінза | Що шукає |
| --- | --- |
| **integrity** | суперечності між розділами; залишки замінених правил; інваріант без перевірки; блок без «готово, коли»; інтерфейс без рівно одного блоку-власника або такий, що його використовує блок, який не вказав його в «залежить від»; термін глосарію з іншим значенням; вагоме рішення без ADR; твердження, яке автор плану може реалізувати більше ніж одним способом |
| **truth** | кожне фактичне твердження про наявний код, схему й бібліотеки — перевірене в коді (Уніка, потім `git grep`), у дампі конфігурації-власника для коду вендора, у справці платформи (`unica:platform-help`, `unica_docs`) для версії воркспейсу; чи можна це збудувати в поточному коді так, як написано |
| **security** | лише те, що спека додає чи змінює: права, ролі й RLS, межі обміну даними та інтеграцій, секрети, руйнівні операції, часткові оновлення («що, як клієнт надішле лише частину масиву»), втрата даних при збої, незворотні міграції |

## Бриф для одного аудитора

```
Lens: <integrity | truth | security>
Spec: <шлях(и)>   Glossary: <шлях>   ADR: <тека>
Round: <1 | N>. Для N: аудитуй лише цей diff — <команда git diff або файл>;
known accepted findings: <перелік, щоб їх не повідомляли знову>
Project context: <2–3 рядки: стек, де лежить код, режим workspace.mode>
```

Аудитори лише читають: базу агента не збирають, у ній нічого не запускають і мутуючих інструментів Уніки не кличуть.

## Шкала знахідок

- **Severity**: blocker (план не можна написати, або він збудує не те / втрата даних чи безпеки) · major (план, імовірно, піде хибно) · minor (ясність).
- **Confidence** 0–100; аудитор повідомляє лише ≥ 80.
- Кожна знахідка: `§N + цитата`, чому це дефект, виправлення.

## Правило зупинки

0 блокерів і 0 security major → стоп (зазвичай 2–3 раунди). Решта знахідок іде в план як відомі проблеми. Раунд N+1 бачить лише diff виправлень раунду N.
