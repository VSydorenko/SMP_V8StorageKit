# Шаблон спеки

**Завантаж, коли** пишеш нову спеку або перебудовуєш наявну.

Заголовки пронумеровані, щоб автори планів могли просити `doc <файл> §N`. Дві таблиці лишай навіть із одним рядком.

```markdown
# <Напрям>: <що будуємо>

Issue: #<N> — статус живе в GitHub (`track`), не в цьому файлі
Glossary: <шлях> · ADR: ADR-N, ADR-M · Parent: <оглядова спека, якщо це частина>

## 1. Goal

<Два–п'ять речень: проблема, для кого, що істинне після роботи.
Продуктове «чому» — тут; технічне «чому» — в ADR.>

## 2. Out of scope

- <чого читач міг би чекати, але тут не будується, і де воно живе>

## 3. Blocks

| Block | Scope | Done when | Depends on |
| --- | --- | --- | --- |
| B1 <назва> | <що будує блок; файли/ділянки> | <спостережна перевірка: тест, команда, поведінка> | — |
| B2 <назва> | … | … | B1 (`<інтерфейс>`) |

## 4. Interfaces

| Interface | Kind | Owner block | Consumers | Defined in |
| --- | --- | --- | --- | --- |
| `<ім'я>` | API / таблиця / подія / тип / файл / env | B1 | B2, B3 | §5.1 |

Кожен інтерфейс має рівно один блок-власник. Власник визначає й змінює; споживачі лише використовують.

## 5. Blocks in detail

### 5.1 B1 <назва>

<Стан: дані, поведінка, правила, випадки помилок, інваріанти. Кожен інваріант називає
перевірку, що його тримає (мінімум: лише на логіку й механізми, які справді треба
перевіряти). Посилання ADR-N там, де читач спитає «чому».>

### 5.2 B2 <назва>

…

## 6. Security and data integrity

<Права, ролі, RLS, межі обміну даними, секрети, руйнівні операції, випадки часткових
оновлень («що, як клієнт надішле лише частину масиву»). Порожній розділ — напиши
«немає» і чому.>

## 7. Open questions

| # | Question | Class | Blocks | Recommendation |
| --- | --- | --- | --- | --- |
| OQ-1 | <одне питання> | product / irreversible | B2, B6 (або «none») | <відповідь і причина одним рядком> |

<Лише питання до власника. Технічні питання вирішуєш сам. Питання, що не блокує жодного
блоку, сюди не йде — воно в беклог проєкту. Відповідь власника стає ADR (якщо вагома) або
станом у §5, а рядок видаляють.>
```



## Оглядова спека + часткові (понад ≈ 50 КБ)

- **Оглядова спека**: §1 Goal, §2 Out of scope, §3 Blocks (усі блоки напряму), §4 Interfaces (усі міжчастинні інтерфейси), далі перелік часткових спек з одним рядком на кожну.
- **Часткова спека**: рядок заголовка `Parent:`, власний детальний розбір блоків (§5), безпека (§6), відкриті питання (§7). Її інтерфейси до інших частин — рядки таблиці оглядової, не копії.
