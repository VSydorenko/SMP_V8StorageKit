# Службовий користувач ІБ з розширення методами БСП

Користувача створює **обробник оновлення БСП**, а не перший вхід, не регламентне завдання і не клієнтський
перехоплювач. Розширення реєструється в БСП як бібліотека, і БСП сама кличе його обробник у штатному оновленні ІБ.
Створення — **через елемент довідника `Пользователи` з фіксованим посиланням**: БСП сама створює користувача ІБ
за `ОписаниеПользователяИБ`. Голий `ПользователиИнформационнойБазы.СоздатьПользователя()` не підходить.

Виміряно на 8.3.27.1644 і БСП 3.1.7 (BAS МБ / УНФ). На іншій редакції БСП звір сигнатури експортів бібліотеки.

## Коли застосовувати

- розширенню чи конфігурації 1С на БСП потрібен технічний (службовий) користувач ІБ, що має з'явитися сам після встановлення — для інтеграції, WebSocket-клієнта (скіл `v8storagekit:1c-websocket-client`), фонових з'єднань;
- користувача треба зробити невидимим і без інтерактивного входу;
- обробник оновлення БСП із розширення «не викликається» або оновлення падає з «Метод объекта не обнаружен (ПередОбновлениемИнформационнойБазы)».

Тригери: «служебный пользователь», «технічний користувач», «створити користувача ІБ кодом», «ОписаниеПользователяИБ», «ПриДобавленииПодсистем», «обробник оновлення розширення».

## Рецепт

1. **Реєстрація бібліотеки.** Позич `ОбщийМодуль.ПодсистемыКонфигурацииПереопределяемый` (скіл `unica:cfe-borrow`;
   решта модуля не змінюється) і перехопи `&После("ПриДобавленииПодсистем")`:
   `МодулиПодсистем.Добавить("<МодульБиблиотеки>")`.
2. **Модуль бібліотеки** (загальний, серверний, не привілейований) має:
   - `ПриДобавленииПодсистемы(Описание)`: `Описание.Имя` (унікальне ім'я бібліотеки — під ним БСП веде версію у
     `ВерсииПодсистем`; з іменем розширення збігатися не мусить) і `Описание.Версия`;
   - `ПриДобавленииОбработчиковОбновления(Обработчики)`: один обробник з `Версия = "*"`,
     `НачальноеЗаполнение = Истина`, `РежимВыполнения = "Оперативно"`;
   - **шість порожніх експортів**, які БСП кличе на кожній бібліотеці: `ПриОпределенииРежимаОбновленияДанных`,
     `ПередОбновлениемИнформационнойБазы`, `ПослеОбновленияИнформационнойБазы`,
     `ПриПодготовкеМакетаОписанияОбновлений`, `ПриДобавленииОбработчиковПереходаСДругойПрограммы`,
     `ПриЗавершенииПереходаСДругойПрограммы`. Сигнатури копіюй з [references/templates.md](references/templates.md), не з пам'яті: БСП кличе їх
     з певним числом параметрів.
3. **Версія** — з метаданих, рівно чотири частини (`0.1.0.5`):
   `Метаданные.ОбщиеМодули.<МодульБиблиотеки>.РасширениеКонфигурации().Версия`. Не пиши її рядком.
4. **Обробник** ідемпотентно доводить користувача до потрібного стану (код — [references/templates.md](references/templates.md)):
   - елемент `Пользователи` за **фіксованим GUID**: `ПолучитьСсылку` → `УстановитьСсылкуНового`, `Служебный = Истина`;
   - `Пользователи.НовоеОписаниеПользователяИБ()` із полями `Действие = "Записать"`, `Имя`, `ПолноеИмя`,
     `АутентификацияСтандартная = Истина`, `ПоказыватьВСпискеВыбора = Ложь`, `ЗапрещеноИзменятьПароль = Истина`,
     `Роли` (`БазовыеПраваБСП` і власна роль розширення). Власна роль дає рівно те, що читає й пише код, який
     виконується від імені службового, і нічого з даних обліку. Створюється скілом `unica:role-edit`;
   - **випадковий пароль, який ніде не зберігається**, — лише для нового користувача;
   - `Объект.ДополнительныеСвойства.Вставить("ОписаниеПользователяИБ", Описание)` і `Объект.Записать()`, але лише
     коли щось відрізняється.
5. **Право** `Администрирование` — перевірка на вході й виняток; привілейований режим не потрібен.
6. **Встановлення адміністратором:**
   - розширення без «Безопасный режим», із «Защита от опасных действий»;
   - після встановлення й кожного оновлення один запуск від користувача з правом `Администрирование`:
     `1cv8c ENTERPRISE /S <сервер>\<база> /N <адмін> /C ЗапуститьОбновлениеИнформационнойБазы`
     (для файлової бази `/F <каталог>`). Можна й зі стартера, з тим самим `/C` у додаткових параметрах запуску.
7. **Індикатор у формі.** Поки користувача немає, форма показує попередження «запустіть базу з `/C …`» і недоступна.
   Перевірка — `ПользователиИнформационнойБазы.НайтиПоИмени` у привілейованому режимі, бо звичайний користувач
   список не бачить.

## Чому саме так — виміряні факти

| Факт | Наслідок |
|---|---|
| Зміна лише версії розширення оновлення ІБ **не запускає**; БСП порівнює версію основної конфігурації | Тригер — `/C ЗапуститьОбновлениеИнформационнойБазы`, а не «при оновленні розширення» |
| Без шести експортів оновлення падає: «Метод объекта не обнаружен (ПередОбновлениемИнформационнойБазы)» | Заглушки обов'язкові, хоч і порожні |
| Версія не з чотирьох частин — виняток у `ОбщегоНазначенияКлиентСервер.СравнитьВерсии` | Формат `a.b.c.d`; рядок у коді розходиться з метаданими після підняття версії |
| У безпечному режимі розширення перехоплення модуля конфігурації заборонене («расширение модуля запрещено…») | Бібліотека БСП — лише без безпечного режиму |
| Без стандартної автентифікації сеанс від імені користувача стартує й одразу завершується, обробник не викликається, у ЖР нічого | `АутентификацияСтандартная = Истина` + випадковий пароль |
| Без елемента довідника БСП не авторизує користувача («не найден в справочнике») | Створюй через довідник, не через `ПользователиИнформационнойБазы` |
| Сеансу від імені користувача, який запускає платформа (WebSocket, `ИмяПользователяИнформационнойБазы`), пароль не потрібен | Пароль не зберігай ніде: ні в безпечному сховищі, ні в константі |
| З параметром оновлення БСП ставить монопольний режим навіть для «Оперативно» | Попереджай: на час оновлення база монопольна |

## Типові помилки

| Помилка | Правильно |
|---|---|
| Створювати користувача з `ПриНачалеРаботыСистемы`, регламентного завдання чи першого входу адміністратора | Обробник оновлення бібліотеки БСП і запуск з `/C` |
| Вважати, що БСП не кличе обробники з розширення | Кличе, якщо модуль доданий у `ПриДобавленииПодсистем` і має всі експорти |
| Шукати свого користувача за найменуванням чи іменем | Фіксований GUID елемента довідника; ім'я лише як запасний пошук користувача ІБ |
| Писати пароль у безпечне сховище, константу чи код | Випадковий, одноразовий, ніде не зберігається |
| Знімати «Защита от опасных действий» | Знімати лише «Безопасный режим» |
| Давати службовому роль `Администрирование` чи `ПолныеПрава`, як у зразках БСП | `БазовыеПраваБСП` і власна роль з мінімумом прав |
| Записувати користувача на кожному оновленні | Порівняти ролі й прапорці; писати лише при відмінності |

## Пастки тестів і розробки

- Повна перезбірка розширення (`fullRebuild`) знімає ролі розширення з користувачів ІБ. Після кожної перезбірки
  тестів чи продукту — окремий крок, що ідемпотентно повертає ролі.
- Стан «щойно встановлене» для перевірки: видалити користувача ІБ, потім елемент довідника з
  `ОбменДанными.Загрузка = Истина` і `Удалить()`. Фіксоване посилання повернеться тим самим.
- Тести, що кличуть обробник налаштування, змінюють живу базу. Знімок і відновлення стану, а для живого каналу —
  перевірка наскрізним викликом наприкінці.

Не виміряно: чи працює створення користувача шляхом БСП у безпечному режимі розширення. Не покладайся на це.
