# Ранбук Codex

Команда `codex-audit` (команда процесу плагіна, довідка — `codex-audit -Help`) запускає Codex у
штатному режимі CLI й перевіряє, що аудит справді відбувся. Цей файл — що налаштувати на машині, як
писати промпт і що означає кожна відмова.

## Налаштування машини

1. Codex CLI: `npm i -g @openai/codex`; вхід — `codex login`. Команда бере справжній `codex.exe` з
   пакета npm, а не обгортку `codex.cmd`: `cmd.exe` ламає лапки в аргументах.
2. Секція `codex` машинного профілю kit — `~/.config/v8storagekit/profile.json` (проєкт може
   перекрити її в `.agents/kit.profile.local.json`):

   ```json
   { "codex": { "model": "<модель>", "reasoningEffort": "high" } }
   ```

   `model` і `reasoningEffort` обов'язкові: типове зусилля деяких моделей — `low`, і знахідок помітно
   менше. Необов'язкові — `sandbox` (`read-only`), `windowsSandbox` (`unelevated`), `bin`,
   `extraArgs`, `timeoutMinutes` (30), `maxPromptBytes`.
3. Перевірка: малий git-репозиторій з файлом-маркером, промпт «процитуй маркер», локальний профіль
   з `"reasoningEffort": "low"` — `codex-audit` має дати `1 file(s) read`.

## Чому штатний режим

- `--ignore-user-config` — особистий `~/.codex/config.toml` (типова модель, зусилля, плагіни,
  MCP-сервери) для аудиту — шум і зайва вартість. Наслідок на Windows: губиться й ключ
  `windows.sandbox`, і read-only пісочниця відмовляє кожному читанню — тому команда передає його
  явно (`windowsSandbox`).
- `--ephemeral` — сесія не зберігається.
- `--output-schema` — звіт стає JSON (`files_read`, `findings[]`), а не прозою.
- `--json` — потік подій. Аудит справжній, лише коли немає подій помилки, є `turn.completed`, є
  завершена команда з кодом 0, що читає шлях у дереві, і кожен шлях з `files_read` існує.

## Класи збоїв при коді виходу Codex 0

| Що бачимо | Причина | Що ловить |
| --- | --- | --- |
| знахідка «не можу прочитати файли», `files_read` порожній | пісочниця відмовила читанню («blocked by policy» у `codex.log`) | немає команди читання в подіях → код 3 |
| звіту немає | модель недоступна акаунту, помилка API | подія `error` / `turn.failed` → код 3 |
| запуск висить чверть години | промпт питає про зовнішню поведінку бібліотек → вебпошук | заборона вебпошуку в промпті (дописує команда); тайм-аут вбиває дерево процесів |
| висить широкий промпт | одне питання на весь план | вузькі зрізи по черзі |
| переказ без знахідок | формат знахідки не задано | схема звіту: порожній `findings` = знахідок немає |

## Промпт

- Вузько: кілька конкретних питань, лише факти з репозиторію. Ширину дає кількість зрізів, а не
  один широкий промпт; зрізи — по черзі: на машині один Codex за раз (замок).
- Формат знахідки й заборону вебпошуку команда дописує сама.
- Не вбудовуй у промпт те, що є в дереві: Codex читає його сам.

## Після запуску

- Звір кожну знахідку з кодом сам; власнику — лише звірений вердикт.
- Тека запуску — `<приватна тека профілю>/codex/<час>-<ім'я>/`: `prompt.md`, `events.jsonl`,
  `codex.log`, звіт, `status.json`. Вона приватна й не комітиться.
