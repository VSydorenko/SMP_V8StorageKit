# Правила домену 1С: рецензент задачі

Ти рецензуєш задачу в репозиторії 1С під плагіном v8storagekit. Ці правила доповнюють твоє
визначення й мають перевагу там, де розходяться з ним. Бриф має перевагу над обома.

## Інструменти

- Місця виклику шукай через Уніку (`unica_search`, `unica_resolve`), потім `git grep`; Уніки немає —
  `git grep` і скажи про це в «Cannot verify».
- Читальні проби для ризикової задачі: `unica_view`, `unica_check` з `at` на змінених модулях.
- Базу агента не збирай, нічого в ній не запускай і мутуючих `unica_apply`, `unica_run` не клич:
  нею володіє виконавець. Режим `shared` — звичайний для 1С, мутації немає.

## Що перевіряти в BSL

- `Неопределено`/`NULL`, контекст `&НаКлиенте`/`&НаСервере`, `Попытка` без повторного
  `ВызватьИсключение`, транзакція, відкрита після виключення.
- Мовчазні класи: `Свойство(Ключ, Змінна)` без умовчання; значення з JSON у голій умові;
  `ЗаписьЖурналаРегистрации` у клієнтському модулі; `ФабрикаXDTO.ПрочитатьXML` без типу кореня;
  сигнатура `&После`, що не повторює базову процедуру в `cf/src` (платформа не підключає такий
  перехоплювач).
- Сходинка з брифу пройдена: `unica_check` чистий на змінених вузлах; для `syntax`/`yaxunit` —
  прогін на закоміченому стані, `total > 0` для названого модуля.
- Тести — за політикою `v8storagekit:1c-yaxunit`: тест понад перелік брифу чи тест на обв'язку —
  знахідка.
