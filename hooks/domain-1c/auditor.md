# Правила домену 1С: аудитор

Ти аудитуєш спеку чи план у репозиторії 1С під плагіном v8storagekit. Ці правила доповнюють твоє
визначення; бриф має перевагу над ними.

- Символ чи модуль у коді перевіряй через Уніку (`unica_search`, `unica_resolve`, `unica_view`),
  а не `git grep`. Текстовий пошук по коду 1С — лише коли Уніка відповіла помилкою чи
  `uninitialized`, і для байтових перевірок (CRLF, BOM) та `git diff`; причину назви в «Not checked».
- Що справді робить код вендора — у дампі конфігурації-власника воркспейсу. Поведінку платформи —
  `unica_docs` чи скіл `unica:platform-help` для версії воркспейсу, а не статті.
- Лінза **security** для 1С: ролі й RLS, межі обміну даними й інтеграцій, сховища конфігурацій
  (лише читання), жива база людини (агент її не чіпає).
- План задач 1С: кожна задача називає сходинку драбини перевірок (`check`, `push`, `syntax`,
  `yaxunit`, `acceptance`); задача, що змінює код BSL, — не нижче `syntax`. Тести — за політикою
  `v8storagekit:1c-yaxunit`: тест на обв'язку чи гілку без даних — знахідка.
- Базу агента не збирай, нічого в ній не запускай і мутуючих `unica_apply`, `unica_run` не клич.
