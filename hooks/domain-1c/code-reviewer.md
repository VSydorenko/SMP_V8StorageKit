# Правила домену 1С: рецензент коду

Ти рецензуєш код 1С у репозиторії під плагіном v8storagekit. Ці правила доповнюють лінзи твого
визначення й мають перевагу там, де розходяться з ним. Бриф має перевагу над обома.

## Інструменти

- Кого торкається зміна, шукай через Уніку: `unica_search`, `unica_resolve`, `unica_view` (виклики,
  визначення, модуль за логічною адресою), а не `git grep`. Текстовий пошук по коду 1С — лише коли
  Уніка відповіла помилкою чи `uninitialized`, і для байтових перевірок (CRLF, BOM) та `git diff`;
  причину назви в «Not checked».
- Помічники Уніки (`unica:code-review`, `unica:code-diagnostics`) — джерело сигналу, не заміна
  лінзі.
- Код вендора читай у дампі конфігурації-власника воркспейсу.
- Базу агента не збирай, нічого в ній не запускай і мутуючих `unica_apply`, `unica_run` не клич.

## Лінзи для 1С

- **correctness** — `Неопределено`/`NULL`; контекст `&НаКлиенте`/`&НаСервере`; `Попытка` без
  повторного `ВызватьИсключение`; відкрита транзакція після виключення. Мовчазні класи:
  - `property-default` — `Свойство(Ключ, Змінна)` без умовчання: за відсутнього ключа чи `null` у
    JSON змінна тихо стає `Неопределено`;
  - `json-bool` — значення з розбору JSON у голій умові `Если X Тогда` (може прийти рядком, числом,
    `Неопределено`);
  - `client-eventlog` — `ЗаписьЖурналаРегистрации` у клієнтському чи клієнт-серверному модулі;
  - `xdto-untyped` — `ФабрикаXDTO.ПрочитатьXML` без типу кореня: фасети XSD не перевіряються.
- **test-honesty** — асинхронний клієнтський тест YaXUnit зелений за будь-якого коду; «0
  сценаріїв» — не зелене; вкладений `ЮТест.ОжидаетЧто` в `.Равно()`; колір тесту на коміті тесту
  проти очікування задачі плану. Політика — `v8storagekit:1c-yaxunit`: тест понад перелік плану чи
  тест на обв'язку — знахідка.
- **architecture** — розміщення коду по модулях (об'єкт, менеджер, загальний), межа виклику
  сервера; межа «розширення ↔ конфігурація», власні об'єкти проти запозичених.
- **data-layer** — віртуальні таблиці та їхні параметри, управляемые блокировки, RLS і ролі, рухи
  регістрів.
- **localization** — `НСтр`; для текстів для людини — скіл `v8storagekit:1c-localization`.
- **vendor-compat** — перехоплення `&Перед`/`&После`/`&Вместо`/`&ИзменениеИКонтроль` коду вендора,
  що зміниться з оновленням конфігурації-власника; запозичені форми. Мовчазний клас
  `after-signature`: сигнатура перехоплювача `&После` не повторює базову процедуру в `cf/src`
  посимвольно (`Знач`, умовчання) — платформа такий перехоплювач не підключає, без помилки.
- **metadata** — uuid, `ConfigDumpInfo`, політика тексту споживача (кодування, кінці рядків).
  Мовчазні класи:
  - `new-adopted-form` — нова форма з `ObjectBelonging=Adopted`: часто досить перехопити загальний
    модуль, який форма кличе;
  - `dangling-form-uuid` — `uuid` у `Form.xml` запозиченої форми, яких немає ні в розширенні, ні в
    `cf/src`.
- **drift** — `temp-doc-ref`: коментар коду посилається на тимчасовий документ (план, спека, хеш).
- **harm to other sessions** — база агента як спільний рантайм: збирання чи тест у базі, яку
  тримає інша сесія; `push` без `sourceSet` на серверній базі агента.

## Мутація

Режим `shared` — звичайний для 1С: мутації немає (немає ізольованої копії й бази агента). Напиши
це в «Not checked».
