# Пілот kit 1.6.0 під Unica 0.16 — бриф і журнал

Бриф для сесії-тестера. Тестер **нових рішень не приймає**: розбіжність з брифом чи спекою — зупинка й сирий вивід
контролеру (сесія `smp-v8storagekit-c8`) або архітектору (`unica-016-adaptation`).

- Плагін: `v8storagekit@smp-v8storagekit-016` **1.6.0**, локальний маркетплейс
  `~/.claude/local-marketplaces/v8storagekit-1.6.0-add2103` (знімок гілки `feature/unica-0.16` на `add2103`).
- Уніка — збірка зі спеки §1 (`unica@unica` 0.16.0), раннер 0.18.x з неї.
- Спека: `docs/superpowers/specs/2026-11-19-unica-016-adaptation-design.md` (останній коміт), план — `docs/superpowers/plans/2026-11-19-unica-016-adaptation.md`.
- Відкат плагіна: `claude plugin uninstall v8storagekit@smp-v8storagekit-016` → `claude plugin install v8storagekit@smp-v8storagekit`
  (GitHub-маркетплейс, 1.4.0) → нова сесія.

## Межі

- Сховища конфігурацій — лише читання. База людини — лише читання. Серверні бази агента — лише з окремого дозволу власника.
- `-Apply` — лише за явним проханням людини в сесії пілоту. Підрядки `лиценз`/`ліценз`/`license`/`HASP` у виводі платформи — зупинка й доповідь.
- Без `git checkout --`/`restore`/`stash`/`clean`. Нічого не пушити.
- Репозиторій-споживач і гілку пілоту обирає власник. Залишки пілоту 1.5.0 у BankExchange (гілка `pilot/kit-1.5.0`, `build/ib-pilot`) —
  прибирання за його рішенням.

## Пункти пілоту (кожен — запис у журнал нижче: умови, команда, сирий вивід, висновок)

1. **Перехід «1.4.0 → 1.6.0»** (`skills/onboarding/references/upgrades.md`) на живому споживачі — від початку до кінця, без знань поза текстом.
   Окремо: злиття власного `CLAUDE.md` споживача з шаблоном; прибирання старого проєктного хука (`kit check` має його назвати).
2. **Хук плагіна в живій сесії** (Windows):
   - сесія в корені споживача — «Стан сховищ» рівно один раз;
   - сесія в підтеці споживача — контекст + попередження «Уніка бачитиме лише цей воркспейс»;
   - сесія в проєкті не про 1С — тиша, без помилки в транскрипті;
   - якщо є можливість — машина/профіль без Git Bash (оболонка хука PowerShell): чи є помилка в транскрипті; кандидат виправлення —
     `shell: "powershell"` (рішення архітектора — лише якщо вимір покаже помилку).
3. **`sync -Apply` → крок `push force:true`**: Уніка питає людину «Перезаписать базу «origin»…»; згода — база вирівняна;
   відмова — `cancelled`, агент зупиняється з доповіддю, не повторює.
4. **Поставка вендора (клієнт з основною конфігурацією на підтримці)**: після `pull force:true` набору `CONFIGURATION` з поставкою —
   чи лишився `.kit-bin-sha1` у `Ext/ParentConfigurations/` (спека §4.2 п.18, [гіп] «pull стирає позначку»). Рецепт зупинки
   («видаліть теку `Ext/ParentConfigurations/` → `pull force` → `kit supply-marker -Apply`») — пройти й записати результат.
5. **`CONFIGURATION` у сховищі поводиться як розширення** (§4.2 п.3, твердження власника): токен після `UpdateCfg`, рівність байтів
   дзеркала й `pull` Уніки на одній платформі.
6. **Канон `pull force:true` на серверній базі агента** — рівність байтів з дзеркалом (§4.2 п.12, [гіп]). Лише з дозволу власника.
7. **`provision`** на файловій базі: бази немає → кроки; наявна тека → зупинка «видаліть дві теки»; пам'ять раннера без бази →
   зупинка; kit нічого не видаляє.
