## 2. Мета / Архітектура / Спека

**Мета.** Закрити чотири дрібні дефекти, знайдені рев'ю перенесення в Rust і `adopt`: хибні знахідки й мовчання
`check` на ненормалізованих шляхах, залежність процесів `kit.exe` від оточення й межі стелі, невідомий ключ бази
агента, роздута резервна копія `adopt`.

**Архітектура.** Одна функція Rust зводить шлях до форми для порівняння; її вживають `check` і `hooks`. Процеси
`kit.exe` дочитують хвіст каналів після виходу й шукають `taskkill.exe` системним викликом. `GitProblem` несе один
рядок. `adopt` фільтрує записи резервної копії тим самим фільтром поставки, що й копіювання дзеркала.

**Спека:** §5.2.1–§5.2.5; безпека — §6.

## 3. Глобальні обмеження

- Наявні тести лишаються зеленими: Rust-ворота (`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`,
  `cargo test`) і Pester `-Only` змінених модулів та їхніх викликачів.
- Кожен тест, що закриває пункт, мусить червоніти без виправлення; виконавець показує це в звіті (прогін на коді без
  виправлення чи мутація словами з результатом).
- `bin/kit.exe` у комітах гілки до задачі 4 не змінюється. Фікстура (`Copy-KitTools`) бере `bin/kit.exe` робочого
  дерева, тож для Pester чорною скринькою виконавець кладе туди локальну `cargo build --release` (старий файл —
  убік, `mv`) і не стейджить її; `KitExe.Tests.ps1` на такій збірці червоний — так і має бути до задачі 4. Перед
  кожним комітом контролер звіряє, що `bin/kit.exe` не в індексі.
- Нових залежностей крейта немає: системний виклик — через `extern "system"`, як у `rust/src/session_start.rs`.
