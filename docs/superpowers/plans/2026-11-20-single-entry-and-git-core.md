## 2. Мета / Архітектура / Спека

**Мета.** Фаза 1 переходу на Rust (спека §0, D6): один вхід `kit.exe` з прозорою передачею неперенесених команд PowerShell-диспетчеру; один контракт кодів `0–4` для обох мов; ядро git у Rust; хук старту сесії без `pwsh` у чужих проєктах; порт `session-board`; закомічений бінарник із запобіжником застарілості.

**Архітектура.** bin/kit.exe розбирає `kit <команда> [аргументи]`. Перенесену команду виконує сам; решту передає `tools/kit.ps1` (злиття нинішніх `kit.ps1` і `kit-process.ps1`, без param-блоку) токенами в `KIT_ARGV`. Ядро git — модуль `git` крейта; поза ним Rust git не запускає. PowerShell-код заморожено, крім D1/D3 і дефектів (D4).

**Спека:** §0 рішення й заміри спайку, §1 навіщо, §2 D0–D8, §3 інваріанти, §4 поза обсягом, §5 питання (виміряно в §4 плану), §6 ризик, §7 процес.

## 3. Глобальні обмеження

- Залежності крейта — лише `serde_json` (як у заготовки: профіль, файл сесій, JSON хука й `KIT_ARGV`). Кожна нова — з обґрунтуванням у коміті й на затвердження архітектора.
- Кожен коміт, що змінює `rust/`, несе перезібраний bin/kit.exe (`release`); Pester ходить лише в закомічений бінарник, не збирає.
- Перевірка задачі: `cargo test` (коли зачеплено `rust/`) і Pester `-ExcludeTag Integration -Only <зачеплені>`; повний Pester без `Integration` — один раз, у T7.
- PowerShell: нових обгорток git не додавати; поза D1/D3 — лише дефекти, кожен з тестом.
- Поза обсягом (§4 спеки): `session-check` і решта команд, логіка `sync`/`verify`/`adopt`, `Integration`, #50, кросплатформна поставка.
- **Рішення власника 2026-11-21 (старт виконання).** (а) Заготовки спайку на машині виконання немає: T2–T5 пишуться з нуля за спекою `e2ce6fa`; «з заготовки» в задачах означає «за спекою», а не перенос коду. (б) Пороги часу T1, T2 і T4 вимірюються заново на машині виконання: виконавець **до** своїх змін знімає базовий вимір (та сама проба, та сама кількість прогонів, медіана) і рахує поріг тією самою формулою від свого числа; абсолютні стелі для нового Rust-шляху (T2 `≤ 50 мс`, T4 `≤ 100`/`≤ 150 мс`) лишаються, а перевищення на цій машині — не підгонка, а статус `DONE_WITH_CONCERNS` з числами. Умова виміру (ОС, CPU, навантаження) — у звіті.
- **Тулчейн на машині виконання:** `~/.cargo/bin` не в `PATH` оболонки — додати на час сесії (`export PATH="$HOME/.cargo/bin:$PATH"`); лінкер (`rust-lld` + xwin) налаштовано в `~/.cargo/config.toml` машини, у репозиторій не комітиться.

## 6. Інтерфейси

- **Вхід:** `kit <команда> [аргументи]` = bin/kit.exe. Перенесені команди: `session-board`, прихована `session-start`. Решта — передача диспетчеру. Обгортки `bin/<команда>` (Bash) і `bin/<команда>.ps1` кличуть `kit.exe <команда>`; перелік команд процесу — `tools/commands/process-commands.txt` (без `session-board` після T5).
- **Розбір:** форма `ConvertFrom-KitArguments` (`-Ім'я значення`, `-Ім'я:значення`, `-Прапорець[:true|false]`, `-Help`/`--help`, `--ім'я` → код `2`) — однакова в Rust (`cli`) і PowerShell.
- **Передача:** `KIT_ARGV` (Р2); stdin/stdout/stderr успадковані; код диспетчера — код `kit.exe`.
- **Коди (D3):** `0` так; `1` зупинка; `2` помилка виклику; `3` не перевірено; `4` виконано, є наступний крок. Перший рядок stderr помилки — `<команда>: ERROR …`.
- **Ядро git (D4/D4а):** `git::run(repo, args, stdin, allow_fail)` → `{code, stdout, stderr}` або помилка з дослівним stderr; `git::start(repo, args)` → потоковий процес; `git::export_tree`. Завжди `-c core.quotepath=false`, `GIT_TERMINAL_PROMPT=0`, оточення успадковане.
- **Споживачі:** репозиторії-споживачі — через `CHANGELOG.md`, `templates/CLAUDE.md`, скіли. Інших блоків, що ділять ці інтерфейси, немає.
