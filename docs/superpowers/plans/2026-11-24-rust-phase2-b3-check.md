# План B3 «`kit check`» — фаза 2 переходу на Rust (#53)

## 1. Шапка

- **Статус:** на прийманні архітектора (сесія `smp-v8storagekit-4c`).
- **Якорі після X:** модуль `config` — після B1 #113 (гілка `issue-113-b1-config`; інтерфейси — план B1 §5). `runner`,
  `unica` — у `main` (`dab8dfe`, PR #117). Стартує після злиття B1 і PR #116 (`cargo fmt`, версія 2.0.0).
- **Режим робочої копії:** `worktree` (профіль `.agents/kit.profile.json`), гілка від `origin/main` через `pr-gate start 53 <ім'я>`.
  Спільного рантайму немає: справжні раннер, сховище й база агента не потрібні — фальшиві реєстр, раннер і синтетичні
  репозиторії (`New-KitFakeRepo`).
- **Хто збирає `kit.exe`:** виконавець задачі, `tools/build-kit-exe.ps1`; бінарник і зміна `rust/` — одним комітом.
- **Заборони:** `tools/commands/check.psm1` і `session-check.psm1` не змінюються ні на байт (рішення архітектора 2026-11-24:
  `check.psm1` лишається бібліотекою PowerShell `session-check` до B4). Інший PowerShell змінюється лише у файлах спеки §5.0 і
  тестах. Файли B1 (`config`) — лише читати; потрібна зміна — розвилка архітектору.

## 2. Мета / Архітектура / Спека

**Мета.** `kit.exe check` виконує всі 26 перевірок у Rust без PowerShell, дає `check` як функцію для B4 і виправляє дефекти
PowerShell-версії, а не відтворює їх (принцип власника 2026-11-24: «краще, а не паритет»; правило серії 5).

**Архітектура.** Модуль `check` крейта (нова тека rust/src/check): каркас звіту (знахідки в порядку виконання, «не перевірено»,
підсумок, код) і групи перевірок окремими файлами — машина (Уніка, раннер), маніфест і воркспейси, git-стражі (ignore,
індекс, атрибути, регістр), джерела (поставка, сховище, `storage/*`, ім'я розширення), локальні файли воркспейсу, хуки.
Читання git — лише ядро `git` (ADR-0014 п. 5), раннер — лише `runner` (ADR-0019), конфігурація — лише `config` (B1).
Спільні з PowerShell-командами функції (спека §5.0) переносяться в Rust, їхні PowerShell-копії лишаються.
`main.rs` виконує `check` сам; диспетчер `check` більше не отримує.

**Спека.** `docs/superpowers/specs/2026-11-23-rust-phase2-session-check-design.md` §3 (рядок B3), §4 (рядки `kit check`,
`check` як функція), §5.0, §5.3, §6. ADR-0014 (п. 4, 5, 7), ADR-0018, ADR-0019, ADR-0020.

## 3. Глобальні обмеження

- Нових залежностей немає без рішення архітектора.
- `cargo fmt` перед кожним комітом (після #116), `cargo clippy --all-targets -- -D warnings`, `cargo test` — зелені в кожній
  задачі зі зміною `rust/`.
- Версія кожного PR — patch лінії 2.0.x (правило серії 9): запис `CHANGELOG.md` і розділ
  `skills/onboarding/references/upgrades.md`.
- Ідентифікатори перевірок (26, спека §5.3), маркери `[-]/[!]/[i]`, шапка `kit check — <корінь>` і підсумок — як зараз.
  Тексти — як зараз, крім рядків таблиці §4 «Відомі відмінності».
- Секрети: інваріант спеки §6 (пароль не друкується; рядок підключення — лише ключі з відомого переліку, правило серії 5;
  значення YAML, що не пройшли перевірку, — не друкуються; текст `serde`/`serde_yaml` — ні). Чужий текст (stderr git,
  повідомлення раннера) друкується дослівно, як зараз (§6 «Вивід раннера»).
- Порівняння рядків і порядок — ординальні; порядок джерел і дев-баз — як у файлі (правило серії 6).
- Наявні тести лишаються зеленими: `cargo test`, Pester `Check.*`, `Secrets`, `Kit`, `KitExe`, `SessionCheck.*`,
  `SessionStartHook` (останні два — ще проти PowerShell `session-check`).

## 5. Інтерфейси

**Дає** (споживач — B4; сигнатури фіксуються зараз, імена полів — виконавця):

- `check::Options { workspace: Option<String>, source: Option<String>, registry: PathBuf, runner: Option<PathBuf> }`.
- `check::run(ctx: &config::Context, opts: &Options) -> Result<Report, UsageError>`; `Err` — лише рішення 3 (ім'я поза
  маніфестом, код 2). `Report { findings: Vec<config::Finding>, not_checked: Vec<String>, code: i32 }`, код за рішенням 2.
- `check::print(&Report, root: &Path)` — текстовий вивід як зараз.
- `check::MACHINE_STATE_CHECKS: &[&str]`.
- Перенесені спільні функції (спека §5.0) — у модулях за змістом (`git`-читання гілок і атрибутів, `storage_branch`,
  `supply`, `hooks`), щоб B4 і фаза 3 брали їх звідти: гілка існує / unborn / на головній, інваріанти `storage/*`,
  `Get-KitTreePaths` + `Get-KitCaseCollisions`, `Test-GitTextPolicy`, стан і рецепт поставки, `Test-KitGitHooks`,
  `Test-KitLegacySessionHook`. PowerShell-копії лишаються (їх кличуть `sync`, `verify`, `adopt`, `install-hooks`).

**Бере:** `config::preflight(.., Mode::Check)`, `select_sources`, `agent_base`, `agent_base_collisions`,
`local_has_dev_infobase_line`, `connection::parse`, `credentials_recipe` (B1); `unica::installation`, `unica::unica_verdict`,
`unica::runner_verdict`, `runner::version` (B2); ядро `git`.

секрету fail-closed (рішення 2), збій читання файла — код 3, userinfo шляху, фальшивий `pwsh` у фікстурі, таблиця звірки з

`kit.ps1 check`. Раунд 2 (Opus, diff): 1 security major (тест дозволів пропускав `pwsh -File tools/kit.ps1 …:*`), 2 major
(тест коду 3 штовхав до послаблення стража; `server` з кодом 3 — вічний шум) — виправлено. Зона дозволів далі давала нові
