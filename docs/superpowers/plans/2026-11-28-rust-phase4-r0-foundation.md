# План блоку R0 — основа процесу в Rust (фаза 4, #55)

## Шапка

- **Статус:** чернетка на прийманні. Приймає архітектор (сесія `smp-v8storagekit-cd`); продуктові питання — через
  нього (OQ-1, OQ-2 спеки).
- **Спека:** `docs/superpowers/specs/2026-11-28-rust-phase4-process-design.md`, рядок R0 §3, деталі §5.1; ADR-0025.
- **Якорі після X:** помічник контракту команди (`cli`), мутації ядра `git` (`fetch`) і форма переліку перенесених
  команд у `Invoke-KitCommand` — **після злиття Ф3-B1** (блок «Основа» спеки фази 3,
  `docs/superpowers/specs/2026-11-28-rust-phase3-storage-design.md` §3–§4, #54). Задачі 2 (крім перевіреного
  профілю), 3, 4, 5 на них не спираються й можуть іти раніше; задачі 1, 6, 7 і перевірений профіль задачі 2 — лише
  після злиття Ф3-B1 і злиття `origin/main` у гілку. Реєстр задачі 1 бере ті команди фази 3, що злиті на той час.
- **Режим робочої копії:** `worktree`; гілка `issue-55-rust-phase4`, копія `.worktrees/55-rust-phase4`
  (`pr-gate start 55 rust-phase4`). Один PR на блок; спека й ADR фази 4 їдуть у ньому ж.
- **Спільні ресурси:** бази агента немає. `-Full` — по черзі між сесіями ночі через замок
  `full-run.lock` у теці виводу `.agents` головного checkout (спільні правила ночі, п. 2). `bin/kit.exe` на машині без MSVC —
  лише шлях CI (`CLAUDE.md`, «Збірка `kit.exe` і Rust»); локальні збірки `cargo` — лише для власних тестів.
- **Заборони:** код команд процесу (`tools/commands/*.psm1`, `tools/lib/Kit*.psm1`) не переносити — це R1–R6;
  модулі фази 3 (`git` мутації, `path_safety`, `cli`) не змінювати — розвилка йде архітектору.

## Мета / Архітектура / Спека

**Мета.** Дати решті блоків фази 4 спільні частини крейта й закрити два питання для людини: корінь репозиторію
одним способом (`-C`, #93) і рядок оновлення хука, що збігається з `kit-scan` (коментар власника в #55).

**Архітектура.** `rust/src/main.rs` — реєстр команд замість гілок `is_command` і зняття `-C` до розбору;
`rust/src/profile.rs` — нові функції профілю; нові модулі `version`, `markdown`; розширений `gh`; хук
`session_start.rs` бере стан версії з `version`. Pester: фікстура `Invoke-KitCommand` дістає гілку команд процесу.
Документація: скіли й шаблони — правило `-C`.

**Спека.** §3 (рядок R0), §4 (інтерфейси R0), §5.1.1–5.1.7, §6.3; ADR-0025 пп. 3–6.

## Глобальні обмеження

1. Ворота Rust (`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`) зелені на кожному
   коміті з кодом. Pester ходить лише в закомічений `bin/kit.exe`, а новий бінарник з'являється лише в задачі 7
   (CI): тому перевірки задач 1–6 — тести крейта, зокрема інтеграційні в `rust/tests` на `CARGO_BIN_EXE_kit`.
   Pester-перевірки нової поведінки (`-C`, хук, гілка фікстури) задачі 1–6 лише описують, а проганяє задача 7 після
   бінарника CI. Між комітами з кодом і задачею 7 запобіжник `KitExe` «бінарник = джерело» червоний — так і має
   бути (`CLAUDE.md`, шлях CI). `-Full` — лише задача 7.
2. Нові модулі — без паніки на вхідних даних (ADR-0021 п. 5): помилка розбору — значення, не `panic`.
3. Нова залежність — лише `regex` (ADR-0025 п. 3), з обґрунтуванням у коментарі `rust/Cargo.toml`.
4. Кожна нова перевірка має контроль, на якому червоніє (глобальний `CLAUDE.md`, «Вимір і висновок»).
5. Поведінка перенесених команд фаз 2–3 не змінюється, крім прийому `-C`.

## Інтерфейси

**Дає** (власник — R0, спека §4): `-C`; реєстр команд; функції профілю (головний checkout, обов'язкове поле,
шлях усередині репозиторію — код `3`, тека `.agents/<ім'я>` з `.gitignore`, шар-джерело значення, перевірений
профіль, сирий проєктний шар); замок машини; модуль `version` (розбір `CHANGELOG.md` з проблемами, версії, стан, кроки); модуль `markdown`; модуль `gh`
(«недоступно» / збій / 404 / стеля, stdin, `GH_REPO`); гілку процесу фікстури `Invoke-KitCommand`.

**Бере:** від фази 3 — помічник контракту кодів (`<команда>: ERROR …`, `next:`) модуля `cli`, рядки її команд для
реєстру й примітив мутації git (для `fetch` перевіреного профілю); ядро `git` — читальні запити (`rev-parse`,
`ls-remote`, `show`).

## Інваріанти безпеки

Поверхня — читання файлів, зміна поточної теки процесу й читання перевіреного профілю (`ls-remote`, `fetch` одного
рефа без оновлення локальних гілок, `show`). Іншого запису в репозиторій чи git блок не додає.

5. **Перевірений профіль не обирається ні профілем, ні локальними рефами.** Ціль і коміт — лише з відповіді
   `ls-remote --symref origin HEAD`; `pr.base` з будь-якого шару й `refs/remotes/origin/*` їх не змінюють.
   Перевірка — тест на голому origin з клоном і контролями, на яких червоніє реалізація «ціль чи коміт з локальних
   рефів»: (а) `pr.base` у локальному шарі вказує на гілку задачі з іншим профілем; (б) у клоні
   `git remote set-head origin <гілка задачі>` і `git update-ref refs/remotes/origin/main <коміт задачі>` — функція
   однаково повертає профіль коміту, який назвав origin; (в) на голому origin `symbolic-ref HEAD` переведено на іншу
   гілку — функція йде за ним.
6. **«Не прочитано» ніколи не стає порожнім профілем.** Тест на кожен шлях: збій `ls-remote`; origin без `HEAD`;
   збій `fetch`; коміту немає після `fetch`; збій `show`; не-JSON на коміті — «не прочитано». Контроль: файлу на
   коміті немає — порожній профіль. Дефект: будь-який збій зведено до порожнього профілю (так робить
   PowerShell-версія зі збоєм `show` — відома відмінність).

1. **`-C` не діє на хуки й приховані підкоманди.** Перевірка: `kit.exe session-start -C <тека>` і
   `kit.exe runner-exec -C …` поводяться як без `-C` (токени — звичайні аргументи / відмова), робоча тека хука —
   з `CLAUDE_PROJECT_DIR`. Дефект, на якому червоніє: зняття `-C` до вибору команди з реєстру.
2. **`-C` на неіснуючу теку — код `2`, команда не запускалась.** Перевірка: маркер фальшивого `pwsh` для
   диспетчерської команди відсутній. Дефект: `set_current_dir` збій проковтнуто й команда пішла з поточної теки.
3. **Шлях усередині репозиторію.** Абсолютний, `..`, `.`, порожній сегмент — код `3`. Дефект: перевірка лише
   `..` на початку.
4. **Паніка — сталий текст без даних** для нових модулів (наявний `panic_hook`); вхід з невалідним UTF-8 чи
   глибокою вкладеністю Markdown не панікує.
