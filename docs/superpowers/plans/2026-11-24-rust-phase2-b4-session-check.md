# План B4 «`kit session-check` і хук» — фаза 2 переходу на Rust (#53)

## 1. Шапка

- **Статус:** на прийманні архітектора (сесія `smp-v8storagekit-4c`).
- **Якорі після X:** модуль `check` і перенесені функції — після B3 (план `2026-11-24-rust-phase2-b3-check.md`); `config` —
  після B1 #113. Стартує після злиття B3.
- **Режим робочої копії:** `worktree`, гілка від `origin/main` через `pr-gate start 53 <ім'я>`. Спільного рантайму немає:
  сховища — синтетичні теки з `1cv8ddb.1CD` і `data/objects`, `data/pack` (як у `SessionCheck.*`), раннер і реєстр — фальшиві.
- **Хто збирає `kit.exe`:** виконавець задачі, `tools/build-kit-exe.ps1`; бінарник і зміна `rust/` — одним комітом.
- **Заборони:** формат відбитка сховища (`build/session-check/<ключ>.json`, схема 1) і його запис (`StorageImprint.psm1`,
  `sync`) не змінюються — фаза 3. `session-check` нічого не пише.

## 2. Мета / Архітектура / Спека

**Мета.** `kit.exe session-check` виконує команду в Rust, а хук `session-start` кличе його дочірнім процесом без `pwsh`; модулі
`check.psm1` і `session-check.psm1` видалено. Дефекти PowerShell-версії виправлено (принцип власника «краще, а не паритет»).

**Архітектура.** Модуль `session_check` крейта: префлайт `Mode::Lenient` → `check::run` (B3) → на кожне джерело
`truth: storage` один узгоджений знімок (вершина дзеркала, головна гілка, `origin/<гілка>` — SHA, прочитані один раз) →
відбиток сховища чи евристики активності → сигнал → друк у міру готовності. Перенесені спільні функції: активність сховища,
читання й звірка відбитка, відставання від `origin`, `remote-only`, крок відновлення, трейлер `Storage-Version`, реєстр кроку
`next:`. Хук `session_start.rs` запускає `current_exe() session-check -RepoRoot <корінь>`.

**Спека.** `docs/superpowers/specs/2026-11-23-rust-phase2-session-check-design.md` §3 (рядок B4), §4 (рядки
`kit session-check`, відбиток), §5.0, §5.4, §6. ADR-0014 (п. 4, 7).

## 3. Глобальні обмеження

- Нових залежностей немає без рішення архітектора. `cargo fmt`, `cargo clippy --all-targets -- -D warnings`, `cargo test` —
  зелені в кожній задачі зі зміною `rust/`. Версія — patch лінії 2.0.x, запис `CHANGELOG.md`, розділ `skills/onboarding/references/upgrades.md`.
- Імена сигналів (`NewInStorageReason`) — наявні плюс `partial-read` (рішення 2); поля й порядок полів JSON, форма верхнього
  рівня (масив і на успіху, і на помилці `check`), кроки `next:` — як зараз. Текст — як зараз, крім відомих відмінностей §4.
- Байти, які kit порівнює (відбиток проти диска), — значеннями точно як PowerShell: час — цілі 100-нс тики UTC, розміри —
  `i64`, без допуску; обхід сховища — та сама множина файлів, що бачить PowerShell `sync` (рішення 4).
- Без мережі: жодного `git fetch` (тест `GIT_TRACE`, як зараз). Без запису: тест «нічого не змінює й не створює тек».
- Секрети — інваріант спеки §6 для виводу `session-check` і контексту хука.

## 5. Інтерфейси

**Дає:** CLI `kit session-check` (параметри як зараз: `-RepoRoot`, `-Workspace`, `-Source`, `-AsJson`,
`-InstalledPluginsPath`, `-RunnerPath`; невідоме ім'я воркспейсу чи джерела — код 2, як у B3 рішення 3); перенесені функції
(`storage_activity`, читання відбитка, `origin_gap`, `remote_only`, `restore_mirror_step`, `last_storage_version`, кроки
`next:`) — для фази 3.

**Бере:** `check::run`, `check::MACHINE_STATE_CHECKS`, `check::Options` (B3); `config::preflight(.., Mode::Lenient)`,
`select_sources` (B1); ядро `git`; `proc::kill_tree`.
