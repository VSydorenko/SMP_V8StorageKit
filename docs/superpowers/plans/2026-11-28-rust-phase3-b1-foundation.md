# План B1 «Основа» — фаза 3 переходу на Rust (#54)

Статус: чернетка на прийняття архітектором (`smp-v8storagekit-cd`).
Спека: `docs/superpowers/specs/2026-11-28-rust-phase3-storage-design.md` §3 (рядок B1), §4, §5.0, §5.1, §6; ADR-0023.
Якорі після: злиття B1 #152 у `main` (цільовий коміт — задача 0); PR спеки #155.
Робоча копія: `workspace.mode = worktree`, `.worktrees/54-rust-phase3`, гілка блоку `issue-54-b1-foundation` від `main`
після злиття #152 і #155. Спільного рантайму (бази 1С) немає. Спільні ресурси машини: прогін `-Full` — за замком-текою
`full-run.lock` у `.agents/out` головного checkout (правило 2 спільних правил ночі); `bin/kit.exe` — лише з CI (MSVC на машині немає).
Код — лише після сигналу архітектора.

## Мета

Дати командам фази 3 модулі, на яких вони стоять, — без перенесення жодної команди. Після блоку в крейті є
помічник контракту команди, безпечний робочий шлях і єдине місце рекурсивного видалення, мутації ядра `git` з
комітом дзеркала, запуск платформи закритим переліком команд, стан робочого дерева, тексти кроків Уніки, фальшива
платформа й чотири нові лексичні запобіжники. PowerShell-код не змінюється, крім фікстур тестів.

## Архітектура

Нові модулі крейта: `path_safety`, `v8`, `worktree_state`, `unica_step`; розширення наявних `cli` (помічник
контракту) і `git` (мутації). Тестові бінарники: `fake-v8` (фальшива платформа) поруч із наявним `fake-runner`;
збираються лише `cargo build`/`cargo test`, у `bin/` не потрапляють. Pester отримує фальшиву платформу збіркою
`cargo build --bin fake-v8` у фікстурі. Фальшивий раннер Pester (`fixtures/runner/v8-runner.cmd`) віддає на
`platforms` шлях фальшивої платформи з файла фікстури в робочій теці.

## Глобальні обмеження

- Контракт ядра `git` не змінюється (ADR-0014 п. 5, ADR-0021 п. 3): три відповіді, буквальний pathspec, повні рефи,
  `GIT_NO_LAZY_FETCH=1`; нові функції — обгортки в модулі `git`.
- `config` не змінюється (межа з фазою 4, спека §4). Канонічні шляхи для перетину баз лишаються в
  `config::agent_base`; `path_safety` їх не вживає (спека §5.1).
- Нових залежностей крейта немає. Атрибути файлів Windows — `std::os::windows::fs::MetadataExt`; SHA-1 вже є в
  `supply`.
- Модуль без споживача в цьому блоці — `#[allow(dead_code)]` лише там, де clippy інакше червоніє, з коментарем
  «споживач — B2–B5».
- PowerShell-копії (`PathSafety.psm1`, `TreeBackup.psm1`, `UnicaStep.psm1`, `V8.psm1`) не чіпаються: їх ще кличуть
  команди PowerShell.
- `rust/` змінюється в кожній задачі з кодом, тож запобіжник «бінарник = джерело» червоний, доки CI не перезбере
  `bin/kit.exe`; бінарник — окремим комітом наприкінці блоку (задача 8).

## Інтерфейси

Дає (споживачі — B2–B5, фаза 4 для `cli` і `path_safety`):

- `cli`: звіт команди (код, кроки, зупинки) і друк хвоста; пріоритет коду; наявний `cli::parse` без змін.
- `path_safety`: тип безпечного робочого шляху, дві функції створення, рекурсивне видалення.
- `git`: коміт дзеркала, push лише fast-forward, fetch з тишею мережі, `worktree remove --force` (лише з безпечним
  шляхом); решта мутацій (`add`, `rm --cached`, `reset`, `merge-tree`, …) — через наявний `run` у блоках-споживачах.
- `v8`: пошук платформи (корені — аргумент), запуск Конфігуратора, `CREATEINFOBASE` без заміни наявної, ліцензія,
  зайнята база, лапка в паролі; результат — код і текст лозу.
- `worktree_state`: брудні записи (`git status --porcelain -z`), невидима робота з режимом «усе дерево похідне», текст
  зупинки.
- `unica_step`: `unica.run` рядок, крок вирівнювання (`push force` чи `blocked` з рецептом поставки), тексти
  кроків, зупинок і `next:`.
- Тестові: `fake-v8`, розширений `fake-runner` (Rust) і `v8-runner.cmd` (Pester) з `platforms` → фальшива платформа;
  фікстура Pester `Get-KitFakePlatform` (ім'я — на розсуд виконавця) і масив перенесених команд.

Бере: `config` (Secret, база агента, вибір джерел), `supply` (стан поставки для кроку вирівнювання), `storage_branch`,
`case_guard`, `proc` — наявні, без змін.

## Інваріанти безпеки

| # | Інваріант | Перевірка, що ловить дефект |
| --- | --- | --- |
| I1 | Рекурсивне видалення — лише безпечний робочий шлях | лексичний запобіжник (2) червоніє на `remove_dir_all` поза `path_safety` і поза `#[cfg(test)]`; контроль — синтетичний файл-фікстура сканера з таким викликом |
| I2 | Посилання дорогою — відмова, крім власної теки; межа перевіряється лексично | Rust-тест: junction на компоненті воркспейсу з ціллю поза репозиторієм → відмова; той самий шлях без junction → прийнято (контроль); тест падає, якщо перевірку переписати на розкриті шляхи |
| I3 | Видалення не заходить у посилання | Rust-тест: вкладений junction у теці, що видаляється, — ціль цілa після видалення |
| I4 | `V8KIT_SYNC` бачить лише процес коміту дзеркала | лексичний запобіжник (3); Rust-тест коміту дзеркала з хуком `pre-commit` із `templates/githooks`: коміт у `storage/*` проходить; той самий коміт звичайною функцією — відхилено хуком (контроль) |
| I5 | Push — лише fast-forward | Rust-тест на справжньому bare-origin: розійдена гілка → відмова git, origin не змінився; refspec без `+` будує функція, викликач рядка refspec не передає |
| I6 | Платформу запускає лише `v8`; команд запису в сховище в крейті немає | лексичні запобіжники (1) і (4) з контролями |
| I7 | Конфігурацію вантажать лише в базу під `build/` | тип у сигнатурі (рішення 1); тест компіляції не потрібен — `trybuild` не додаємо; рев'ю перевіряє сигнатури |
| I8 | Пароль не друкується | маркерний тест: маркер пароля сховища й бази в аргументах запуску фальшивої платформи — немає в stdout, stderr, `Display`, `Debug` помилки `v8`; позитивний двійник — маркер у журналі фальшивої платформи присутній як ознака «задано», не значенням |
| I9 | Ліцензія 1С — зупинка | Rust-тест: фальшива платформа пише в лог рядок з `HASP` → помилка з текстом зупинки; без рядка — успіх (контроль) |
| I10 | `CREATEINFOBASE` не замінює наявну базу | Rust-тест: наявна тека з файлом → відмова до запуску платформи, журнал фальшивої платформи порожній |

## Задача 1 — помічник контракту команди

Модуль `cli` (чи підмодуль): звіт команди з кодом, кроками й зупинками; друк хвоста; пріоритет коду 1 > 4 > 0;
перший рядок stderr `<команда>: ERROR …` — наявний `fail` у `main.rs` переходить на помічник, поведінка `check` і
`session-check` не змінюється.
Done-when: Rust-тести — `next:` лише за кроку й без зупинки; зупинки друкуються останніми й пригнічують `next:`;
пріоритет на суміші; наявні тести `check`, `session-check`, `config_preflight_cli` зелені.
Перевірка: `cargo test`; Pester `-Only Check.Codes,SessionCheck.Codes,ProcessCli`.

## Задача 2 — `path_safety`

Тип безпечного робочого шляху, дві функції створення за правилами `Assert-SafeWorkPath`/`Assert-KitBuildPath`
(спека §5.1), рекурсивне видалення за `Remove-KitDirectory` (повтори, `ReadOnly`, відсутня тека — тиша, файл —
відмова, посилання не відвідуються). Кожне правило — Rust-тест, що червоніє без правила; кожен `It` з
`PathSafety.Tests.ps1` про ці дві функції — у таблиці журналу «`It` → Rust-тест» (PowerShell-тест лишається:
модуль живий).
Done-when: I2, I3 зелені з контролями; тест помилки читання атрибутів — відмова (fail-closed) через шов функції
читання метаданих у тестовій збірці; `cargo clippy -D warnings` зелений.
Перевірка: `cargo test`.

## Задача 4 — фальшива платформа й фальшивий раннер

переліком — код помилки; наявні тести з `v8-runner.cmd` зелені.
Перевірка: `cargo test`; Pester `-Only StorageReport,Runner,KitFixtures` плюс новий тест фальшивої платформи.
