# План B1 «Конфігурація» — фаза 2 переходу на Rust (#53)

## 1. Шапка

- **Статус:** на прийманні архітектора (сесія `smp-v8storagekit-4c`). Автор — сесія плану B1/B2.
- **Якорі після X:** немає; план спирається на `origin/main` `3aaa0fd`.
- **Режим робочої копії:** `worktree` (профіль `.agents/kit.profile.json`); гілка від `origin/main` через
  `pr-gate start 53 b1-config`. Спільного рантайму (бази агента, стенда) блок не має.
- **Хто збирає `kit.exe`:** виконавець задачі на цій машині (MSVC є), `tools/build-kit-exe.ps1`. Кожна задача
  зі зміною `rust/` закінчується збіркою поставки й комітом `bin/kit.exe` разом із джерелом одним комітом.
- **Заборони:** файли B2 не чіпати (`rust/src/runner*`, `rust/src/unica*`, `tools/lib/Runner.psm1`,
  `tools/check-environment.ps1`). PowerShell-код не змінюється (спека §5.0); новий Pester-файл паритету — єдина
  нова PowerShell-частина, її вимагає сама спека §5.1. Запису накладки немає.
- **Спільні з B2 файли:** `rust/src/main.rs`, `rust/src/lib.rs`, `rust/Cargo.toml`, `rust/Cargo.lock`, `bin/kit.exe`.
  Блок, що зливається другим, вливає `origin/main` у свою гілку (merge, без rebase), розв'язує конфлікт у
  джерелах, перезбирає `bin/kit.exe` збіркою поставки й комітить його разом із розв'язанням.

## 2. Мета / Архітектура / Спека

**Мета.** Модуль `config` крейта `kit` читає маніфест, накладку, `v8project.yaml` і `v8project.local.yaml`,
розбирає рядок підключення, визначає базу агента й робить префлайт у трьох режимах — з тими самими
знахідками й текстами, що PowerShell. Прихована підкоманда друкує контекст префлайту JSON-ом без секретів
для тесту паритету.

**Архітектура.** Тека rust/src/config (її й кожен підмодуль створюють задачі 1–3) — бібліотечний модуль (`pub mod config` у `lib.rs`): `yaml` (читання
файла в дерево `serde_yaml::Value`), `manifest`, `overlay`, `v8project`, `connection`, `agent_base`,
`preflight`. Файли розбираються деревом і перевіряються вручну, без `#[derive(Deserialize)]`: так тексти
помилок збігаються з PowerShell, а значення з файла не потрапляють у помилки `serde`. Паролі й сирі рядки
підключення живуть у типах без `Display`, і їхній `Debug` не друкує значення. Прихована підкоманда
`config-preflight` у `main.rs` лише серіалізує результат API.

**Спека.** `docs/superpowers/specs/2026-11-23-rust-phase2-session-check-design.md` §3 (рядок B1), §4 (рядки
`config`, знахідка, прихована підкоманда префлайту), §5.0, §5.1, §6. ADR-0014 (п. 5, 7), ADR-0018.

## 3. Глобальні обмеження

- `serde_yaml` — точно `=0.9.34` (у `Cargo.lock` `0.9.34+deprecated` поверх `unsafe-libyaml 0.2.11`, ADR-0018);
  інших нових залежностей немає. `serde_json` — без фічі `preserve_order`: вона змінила б порядок ключів у
  наявному JSON-виводі крейта.
- Дефект PowerShell, знайдений під час переносу, Rust виправляє, а не відтворює (правило власника 2026-11-23,
  ADR-0014 п. 7). Кожен такий випадок — рядок «відома відмінність» у цьому плані й у тілі PR; паритет на ньому —
  класом, не текстом. Сумнів, чи це дефект, — розвилка архітектору.
- Еталон поведінки — PowerShell на поточному `origin/main` (рішення 1). Тест паритету кличе живу
  PowerShell-копію в дереві, тож еталон завжди той, що поруч.
- Розбір не панікує на жодному вході (`panic = "abort"` у релізі: паніка — текст у stderr, а хук вклеює stderr
  у контекст сесії; повідомлення паніки цитує дані — зріз рядка не на межі символу друкує сам рядок). Два рівні
  (інваріант §6). Перший, на одному шляху для всього `kit.exe`: `std::panic::set_hook` на початку `main` друкує
  сталий текст `kit: ERROR внутрішня помилка` без payload і місця. Другий, для модуля `config`:
  `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::indexing_slicing, clippy::string_slice,
  clippy::panic, clippy::unreachable, clippy::todo, clippy::unimplemented, clippy::arithmetic_side_effects)]`;
  на даних із файлів не вживати й методів, що панікують поза лінтами (`str::split_at`, `String::insert`/`remove`/
  `drain`/`split_off`, `Vec::remove`/`insert`/`swap`, `assert!`). `cargo clippy --all-targets -- -D warnings`
  проганяє `tools/build-kit-exe.ps1` перед `cargo test` (той самий файл кличе CI), а `rust/rust-toolchain.toml`
  отримує `components = ["clippy"]` — так лінти тримає кожна майбутня збірка поставки, а не лише виконавець B1.
- Модуль `config` не запускає зовнішніх процесів (git, раннер, `pwsh`): запобіжник `git_guard.rs` лишається
  зеленим без нових записів `ALLOWED_DYNAMIC`.
- Шляхи у виводі й контексті — як `[IO.Path]::GetFullPath` (лексично); перетини баз і пам'яті раннера — лише
  через канонічну форму, як `Get-KitCanonicalPath`: розкриття junction/symlink по компонентах (`fs::read_link`,
  ліміт стрибків той самий), зняття `\\?\`, `\\?\UNC\`, `\??\`, fail-closed на нечитаному атрибуті.
  `fs::canonicalize` не вживати. BOM на початку файла відкидається, як `Get-Content -Encoding UTF8`.
- Ключі YAML-мап і значення `truth` порівнюються без регістру: PowerShell тримає дерево в
  `OrderedDictionary` (вимір 2026-11-23: `Contains("version")` на `Version:` — `True`), а `-notcontains`,
  `switch` і `-eq` нечутливі до регістру. Там, де PowerShell пише `-cne`/`-ceq`, — з регістром.
- Наявні тести лишаються зеленими: `cargo test` і `-Only` змінених зон. `cargo clippy --all-targets -- -D warnings`
  зелений — умова готовності кожної задачі зі зміною `rust/` (у таблиці задач — «clippy `-D warnings`»).

Кожна фікстура корпусу несе в метаданих очікувані перевірку (`manifest`, `overlay`, `workspace`, `source`) і початок тексту; тест спершу стверджує їх на PowerShell-боці — фікстура, яку PowerShell приймає чи відхиляє іншим класом, дає червоне, а не «покритий клас». Решту виконавець міряє тим самим способом і додає у відповідність; невиміряний вид — корпус паритету покаже розбіжність. | немає |
| 7 | Значення YAML → рядок — одна функція `ps_string` над деревом, де кожен скаляр уже прочитано як рядок (`text_tree`): поле дає ВИХІДНИЙ текст скаляра (`1.10`, `0123`, `true`, `yes`), `null`/`~`/порожнє — порожній рядок; правил PowerShell `[string]` (`True`/`False`, число без крапки, список через пробіл, ім'я типу .NET) немає. Список чи мапа на місці скаляра (`version`, `name`/`type`/`path` source-set, `storages.*`, усі скалярні поля) — відмова без значення (KD-3, KD-5): PowerShell кастить без перевірки, і корпус несе ці випадки як відомі відмінності. |
| 8 | Обидва режими поблажливого префлайту й суворий — одна функція з `Mode`; суворий режим повертає першу знахідку error як зупинку (`Err`), поблажливі — повний контекст. | немає |

Дозволені ключі: Srvr, Ref, File.», так само для «'=' у значенні», «порожнє значення» й «двічі» на невідомому ключі. PowerShell друкує будь-яке ім'я з сирого рядка (`Srvr=a;Ref=pa;ss=word` → «невідомий ключ 'ss'»), а Rust цей дефект виправляє. Порядок перевірок — контракт: частини зліва направо, перша помилка зупиняє, `usr`/`pwd` відмовляють раніше за «невідомий ключ». PowerShell-копія не змінюється (§5.0). | 10 | Хук паніки (`set_hook`, §3) діє на весь `kit.exe`, не лише на `config`: невиловлена паніка будь-якої команди друкує сталий текст замість повідомлення паніки. Це зміна поведінки лише на дефекті (паніка й так завершує процес з `abort`), тож у межах ADR-0014 п. 7. Крок clippy у `tools/build-kit-exe.ps1` — зміна рецепта збірки, не PowerShell-коду kit (§5.0 його не заморожує). | §5.0: речення про `tools/build-kit-exe.ps1` (внесено в PR плану) |

### Відомі відмінності від PowerShell

Закритий перелік: кожна фікстура корпусу `config-bad` з `#@ parity: class` посилається рядком `#@ decision: KD-<n>` на один
із записів нижче. Перелік ідентифікаторів у тесті (`tools/tests/fixtures/ConfigParitySetup.ps1`, `$script:KnownDifferences`) —
джерело правди для гейта; нерозпізнаний ідентифікатор чи його відсутність — червоне. Нова відмінність починається з
запису тут і в тесті, потім фікстура.

| Ідентифікатор | Що робить PowerShell | Що робить Rust і чому | Джерело рішення |
|---|---|---|---|
| KD-1 | Помилка розбору YAML (синтаксис, дубль ключа) вклеює текст YamlDotNet — а в ньому ключі й значення файла. | Лише файл і місце (рядок, колонка); тексту парсера немає (спека §6, секрети в ключах і значеннях). | спека §6; рішення 5 цього плану |
| KD-2 | Файл із кількома YAML-документами: перший береться, решта мовчки відкидається. | Відмова з місцем другого `---`. | рішення архітектора 2026-11-23, доповнення задачі 1 |
| KD-3 | Скаляр у рядковому полі перетворюється (`0123` → `123`, `1.0` → `1`, `true` → `True`); `version: 1.0` приймається як 1. | Вихідний текст скаляра або відмова: `1.10`, `0123`, `true` лишаються як написано; `version: 1.0` відхиляється (з ключа джерела `0123` вийшла б гілка `storage/123`). | рішення архітектора 2026-11-23, доповнення задачі 1 |
| KD-4 | YAML-тег (`!t x`) у значенні чи ключі: тег мовчки знімається. | Відмова «YAML-тег (`!…`) у рядку N, колонці M не підтримується — приберіть тег»; ні тегу, ні значення текст не цитує. | рішення архітектора 2026-11-24 |
| KD-5 | Список чи мапа на місці скаляра кастується в рядок (`a b`, ім'я типу .NET) або дає текст з іменем типу. | Відмова без значення в усіх скалярних полях («має бути скалярним значенням»; `version` — «має бути числом»). | рішення архітектора 2026-11-24 |
| KD-6 | Помилка рядка підключення друкує будь-яке ім'я ключа з сирого рядка (`невідомий ключ 'ss'`). | Ім'я — лише з відомого переліку (`srvr`, `ref`, `file`, `usr`, `pwd`), інакше без імені; те саме для «'=' у значенні», «порожнє значення», «двічі» і «непарні лапки». | рішення 9; Ruling задачі 2 |
| KD-7 | `File=` з префіксом пристрою (`\.\`, `\?\`, `\??\`), адмінський ресурс `\хост\X$`, ціль посилання не абсолютна чи від кореня/диска: звірка баз не відмовляє. | Відмова «kit не може довести, що база агента не збігається з базою людини»: fail-closed (принцип «kit ніколи не пише в базу людини»). | ADR-0014 п. 7; доповнення задачі 2; Ruling задачі 2 |
| KD-8 | Порядок імен у тексті («Є: …», DT-INF) — `Sort-Object` за культурою машини, дедуплікація за нею. | Незалежний від культури: нижній регістр ординально, при рівності — вихідні рядки; дедуплікація за тим самим правилом. | рішення архітектора 2026-11-24 |
| KD-9 | Запис `sources` маніфесту без значення друкує ім'я ключа (`джерело 'X' має бути мапою`). | Ім'я не друкується (запис без `:` — ключ, у якому міг опинитись секрет): «запис №N без значення». | спека §6; фінальне рев'ю B1 |

Перевірено й не відмінність: `infobases.origin.dbms` не мапою (скаляр, список) — PowerShell теж вважає «не задано»
(`-is [IDictionary]`), Rust — `dbmsSet: false`; паритет текстом.

**Прийняті обмеження** (не відмінності): квадратичний розбір глибокої flow-вкладеності (100 КБ — 14,5 с, 400 КБ — 39 с;
рішення архітектора — без межі розміру, стеля хука); межа лексичного сканера `git_guard` (обчислений рядок в аргументах
оболонки — рішення архітектора 2026-11-23, варіант 3); `\<локальний хост>\<ресурс>` на локальну теку лексично не
відрізнити від мережевого ресурсу.
## 5. Інтерфейси

**Дає** (споживачі: B3, B4, спека 1С B2 `kit step`, фаза 3 #54). Сигнатури фіксуються зараз і в B3/B4/фазі 3
не змінюються; імена полів — виконавця, склад — тут.

- `config::Mode { Strict, Lenient, Check }`.
- `config::Finding { level: Level, check: String, message: String }`, `Level { Error, Warn, Info }` — як
  `New-KitFinding`.
- `config::preflight(repo_root: &Path, mode: Mode) -> Result<Context, PreflightStop>`: у всіх режимах `Err` —
  корінь не існує чи не git-репозиторій (`Resolve-V8RepoRoot`, поза `$fail` і в PowerShell, текст як зараз); у
  `Strict` ще й перша помилка; інакше `Lenient`/`Check` — `Ok`, `Context.ok` і `Context.findings` — як
  `$ctx.Ok`/`Findings`. `PreflightStop { check: Option<String>, message }`: `check` порожній для кореня.
- `Context`: корінь, шлях маніфесту й накладки, `Option<Manifest>` (немає, коли маніфест не прочитано — як
  `$null` у PowerShell), `Option<Overlay>`, вид і мітка продукту (`Option`), головна гілка (типово `main`),
  `Vec<Workspace>`; `Workspace`: шлях, повний шлях, `V8Project` (source-set-и, `workPath`, `providers`
  як дерево), `Vec<Source>`; `Source`: ключ, `truth`, тип, воркспейс, шляхи, шлях сховища, користувач,
  `Secret` пароля, `dump.from`, гілка `storage/<ключ>`.
- `config::select_sources(&Context, workspace: Option<&str>, source: Option<&str>, truth: &[Truth]) ->
  Result<Vec<&Source>, String>` — як `Select-KitSources`.
- `config::agent_base(&Context, &Workspace) -> Result<Option<AgentBase>, String>` — як `Resolve-KitAgentBase`;
  `agent_base_collisions(&Context, &Workspace)`, `workspace_needs_agent_base(&Workspace)`,
  `agent_base_missing_message(ws: &str)` — як однойменні PowerShell-функції.
- `config::local_has_dev_infobase_line(workspace: &Workspace) -> bool` — лише ознака: у
  `v8project.local.yaml` є рядок, що починається з `devInfobase:` (сирий текст, не YAML). Знахідку `local-audit`
  з її умовою (`check.psm1`, гілка `elseif` після перевірки «база агента й накладка») формує B3, не B1.
- `config::connection::parse(&RawConnection) -> Result<Connection, ConnectionError>` — як
  `ConvertFrom-V8Connection`; `assert_secret_quote_free(&Secret, origin: &str)`.
- Читання накладки віддає типи, з яких фаза 3 зможе записати базу агента; сам запис у B1 не реалізується.
