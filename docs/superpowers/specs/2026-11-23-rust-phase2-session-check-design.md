# Перехід на Rust, фаза 2: `check`, `session-check`, конфігурація й раннер

Issue: #53 — статус живе в GitHub (`track`), не в цьому файлі
Glossary: `docs/GLOSSARY.md` · ADR: ADR-0014, ADR-0018, ADR-0019 · Parent: —

## 1. Goal

Команди `kit check` і `kit session-check` виконує `kit.exe` без PowerShell. Разом із ними в Rust
переходять читання конфігурації (маніфест, накладка, `v8project.yaml`), префлайт і запуск раннера. Після
фази хук старту сесії в репозиторії 1С не запускає `pwsh`. Наступні споживачі отримують готові модулі:
блок B2 спеки 1С (`kit step`) — запуск раннера й контекст воркспейсу, фаза 3 (#54) — конфігурацію й префлайт.
Поведінка обох команд — та сама, крім винятків ADR-0014 п. 7.

## 2. Out of scope

- Команди, що пишуть: `sync`, `verify`, `adopt`, `provision`, `dump`, `supply-marker`, `install-hooks` —
  фаза 3 (#54). Вони лишаються в PowerShell зі своїми копіями спільних функцій (§5.0).
- Запис відбитка сховища (`Write-KitStorageImprint`) і запис накладки (`Save-KitOverlayAgentBase`) — фаза 3;
  фаза 2 відбиток і накладку лише читає.
- Команди процесу (`sdd`, `pr-gate`, `doc`, …) — фаза 4 (#55).
- Команда `kit step` — блок B2 спеки `2026-11-20-1c-specificity-design.md`; фаза 2 дає їй модулі (§4).
- `tools/check-environment.ps1` лишається PowerShell-скриптом; вердикти версій бере з `kit.exe` (§5.2).
- Зміна поведінки `check` чи `session-check` понад винятки ADR-0014 п. 7.

## 5. Blocks in detail

### 5.0 Спільні правила фази

- **Порядок переносу** — ADR-0014 п. 7: Rust-команда → наявні Pester-тести команди зелені проти `kit.exe`
  як чорна скринька → еталон виводу PowerShell на фікстурах знято до видалення модуля → модуль команди
  прибрано. Байти, які kit порівнює чи хешує, не змінюються.
- **Цільова поведінка** `check` і `session-check` — поведінка PowerShell-версії на **цільовому коміті** `main`
  `e25ae14` (злиття гілки `feature/onboarding-target-state`, PR #105); еталон і приймальні тести беруться з
  нього. Зміна PowerShell-версії після цільового коміту — задача 0 відповідного плану. Така зміна вже є:
  #109 (ADR-0020) змінив текст двох повідомлень про `kitVersion` у `Manifest.psm1` і `Preflight.psm1`
  (`v8storagekit.version` замість `kit.version`); еталон для них — поточний `main`.
- **Спільні функції.** Функцію, яку кличе ще й PowerShell-команда, що лишається після фази, переносять у Rust, а
  її PowerShell-копію лишають, доки її кличе хоч одна така команда. Перелік на дату спеки (неповнота переліку —
  не дозвіл: авторитетний — `grep -rlw <функція> tools/commands tools/lib`):
  `Select-KitSources`, `Resolve-KitAgentBase`, `New-KitAgentBaseMissingMessage`, `Find-KitAgentBaseCollisions`,
  `Test-KitPathsOverlap`, `Get-KitRunnerMemoryPath`, `Test-KitOnMainBranch`, `Test-KitBranchExists`,
  `Get-KitStorageBranchLastVersion`, `Test-KitRemoteOnlyMirror`, `Get-KitRestoreMirrorStep`,
  `Get-KitStorageActivity`, `Get-KitOriginGap`, `Test-GitTextPolicy`,
  `Get-KitTreePaths`, `Get-KitCaseCollisions`, `Get-KitSupplyState`, `Get-KitSupplyRecipe`, `Test-KitSupplyDescribed`,
  `Get-KitSupplyRelativePath`, `Get-V8CredentialsRecipe`, `Test-KitGitHooks`, `Test-KitLegacySessionHook`,
  `Invoke-KitGitProcess`, `Reset-KitNextStep`, `Register-KitNextStep`, `Write-KitNextStepLine`, `Invoke-KitPreflight`
  (диспетчер кличе його для кожної команди сховища; команди процесу йдуть без префлайту).
  Однаковість копій тримають наявні тести PowerShell-функцій, тест паритету B1 і, для `Get-KitStorageActivity`,
  окремий тест паритету активності сховища: відбиток пише PowerShell (`sync`), а порівнює Rust (§5.4), тож форма
  часу й розмірів мусить збігатися побайтно.
- **Виняток зі спільних функцій — запуск раннера:** копії немає, PowerShell кличе `kit.exe` (ADR-0019).
- **PowerShell заморожено** (ADR-0014 п. 7). У фазі змінюються лише: `Runner.psm1` (запуск через `kit.exe`),
  `check-environment.ps1` (вердикти через `kit.exe`), фікстура тестів `Invoke-KitCommand` (команди фази — через
  `kit.exe`), видалення модулів двох команд і їхніх рядків у `tools/lib/module-order.txt`, якщо вони там є.
  Маршрут `check` і `session-check` у `kit.exe` — зміна Rust; диспетчер `tools/kit.ps1` цих команд більше не
  отримує. Префіксне правило дозволів `.claude/settings.json` на виклик `check` через диспетчер `tools/kit.ps1`
  власник прибрав 2026-11-23, ще до фази: префікс пропускав без запиту `-RunnerPath` і `-InstalledPluginsPath`
  з довільним файлом, а `check` запускає раннер за цим шляхом (§6). B3 додає один дослівний рядок
  `Bash(bin/kit.exe check)` — без шаблонів і параметрів (рішення власника разом зі спекою).
- **Фаза нічого не пише** у репозиторій, сховище чи базу: лише тимчасові файли виводу дочірніх процесів, які
  прибирає сама. Виняток — убивство на стелі хука (`taskkill /F`): тоді тимчасові файли лишаються; у них лише
  вивід `--version` раннера й git, без секретів. Тримає це наявний тест «`session-check` нічого не змінює й не
  створює тек» проти `kit.exe`.
- **Зовнішні процеси фази**: git — через ядро `git` (ADR-0014 п. 5); раннер — через `runner` (ADR-0019);
  `taskkill` — наявне вбивство дерева на стелі; новий самозапуск `kit.exe session-check` з хука (§5.4) — новий
  запис переліку дозволених динамічних запусків у `rust/tests/git_guard.rs`. `pwsh` лишається лише для
  передачі команд, які ще не перенесено.

### 5.1 B1 Конфігурація

- **YAML** — `serde_yaml` (ADR-0018). Контракт читання як у `Read-KitYaml`: файл, що не розбирається, порожній
  обов'язковий файл чи корінь не мапа — помилка з іменем файла; порожній необов'язковий файл (`-AllowEmpty`) —
  порожня мапа. Порядок ключів зберігається (читання як `ConvertFrom-Yaml -Ordered`): від нього залежить порядок
  джерел і знахідок у виводі.
- **Маніфест `v8storagekit.yaml` і накладка `v8storagekit.local.yaml`** — власні типи з тими самими правилами,
  що `Read-KitManifest` і `Read-KitLocalOverlay`: обов'язкові ключі, форма шляху сховища, невідомий ключ —
  помилка. Старий рядок `kitVersion:` — залежно від режиму префлайту (нижче): у суворому й поблажливому —
  помилка з рецептом, у режимі `check` — окрема знахідка, а решта маніфесту розбирається.
- **`v8project.yaml` і `v8project.local.yaml`** — деревом (ADR-0018 п. 2): kit бере лише source-set-и (ім'я, тип,
  шлях), запис `infobases.origin` (`connection`, `user`, `password`, `dbms`) і поля своєї політики.
  Політику `Get-V8ProjectConfigProblems` (стара `infobase:`, `providers` = `designer`, форма `infobases`)
  застосовують до **обох** файлів. Знахідка `local-audit` про `devInfobase` лишається перевіркою сирого тексту
  `v8project.local.yaml` (рядок, що починається з `devInfobase:`), як зараз, а не розбором YAML.
- **База агента** воркспейсу (`Resolve-KitAgentBase`): вид (файлова чи серверна), шлях, наявність `1Cv8.1CD`;
  перетини баз і пам'яті раннера між воркспейсами (`Find-KitAgentBaseCollisions`, канонічні шляхи).
- **Рядок підключення** (`ConvertFrom-V8Connection`): `File=`/`Srvr=`+`Ref=`, облікові дані; пароль із
  лапкою — відмова (`Assert-V8SecretQuoteFree`). Помилки розбору не містять значень (правило §6).
- **Префлайт** — три режими, як `Invoke-KitPreflight -Mode`: `Strict` (перша помилка — зупинка з кодом 1;
  команди сховища), `Lenient` (усі помилки стають знахідками, контекст — наскільки вдалося зібрати;
  `kitVersion` у маніфесті — зупинка на знахідці `manifest`; так його кличе `session-check`) і `Check` (як
  `Lenient`, але `kitVersion` — окрема знахідка error `kit-version`, а решта маніфесту розбирається; так його
  кличе `check`). Вибір джерел за `-Workspace`/`-Source`/`-Truth` — як `Select-KitSources`.
- **Тест паритету** (у кожному з трьох режимів): на кожній фікстурі `tools/tests/fixtures/manifest-*.yaml`, на
  зразках `templates/v8storagekit.yaml.example`, `templates/v8storagekit.local.yaml.example` і
  `templates/v8project.yaml.example` і на синтетичних
  репозиторіях `New-KitFakeRepo` контекст і знахідки Rust-префлайту дорівнюють PowerShell-префлайту.
  Rust-бік — прихована підкоманда префлайту: JSON із контекстом і знахідками, у якому кожне поле пароля
  (сховища, бази агента) замінено ознакою «задано / не задано», а кожен рядок підключення виводиться лише
  розібраною формою (вид, `File`/`Srvr`/`Ref`, ознака облікових даних) або ознакою «не розбирається» — сирим
  текстом ніколи: нерозбірний рядок (пропущена `;`) по компонентах не замаскувати. PowerShell-бік тест
  серіалізує тим самим правилом. JSON несе й базу агента кожного воркспейсу та перетини баз
  (`Resolve-KitAgentBase`, `Find-KitAgentBaseCollisions`) під тією самою маскою, тож паритет покриває і їх.
  Класи неправильних файлів паритет перевіряє на корпусі неправильних файлів: текст Rust дорівнює тексту
  PowerShell; класи, де PowerShell вклеює текст парсера YAML (відома відмінність §6), перевіряє Rust-тест форми
  повідомлення. Тест і підкоманда живуть, доки живе PowerShell-копія префлайту.

### 5.2 B2 Раннер і Уніка

- **Установлена Уніка** — з `~/.claude/plugins/installed_plugins.json` (запис `unica@…`): версія й `installPath`,
  як `Get-UnicaInstallation`. Тести передають інший реєстр явним параметром, не змінною оточення.
- **Раннер** — `<installPath>/bin/win-x64/v8-runner-windows-x86_64/v8-runner.exe`; запасного пошуку немає
  (кеш тримає кілька версій Уніки). Тести передають шлях фальшивого раннера явним параметром.
- **Вердикти версій**: Уніка — за мінором (протестований мінор задає код, як `Get-KitUnicaVersionVerdict`);
  раннер — `--version` → `v8-runner X.Y.Z`, вердикт за мінором (`Get-KitRunnerVerdict`). Протестовані мінори
  живуть в одному місці — модулі `unica`.
- **Запуск** (ADR-0019): аргументи передаються з лапкуванням за правилами `CommandLineToArgvW`;
  `--config <воркспейс>/v8project.yaml`, аргументи команди, `--json-message`; stdout — конверт раннера,
  stderr зберігається для тексту помилки; стеля часу задає викликач. Конверт, що не розбирається, —
  помилка з дослівним stdout і stderr. Код раннера й `error` конверта kit не перетлумачує.
- **Приховані підкоманди `kit.exe`** (не в `-Help`): запуск раннера для PowerShell (конверт і код без змін;
  шлях раннера — з Уніки або явним параметром) і вердикти інструментів одним JSON для `check-environment.ps1`.
  `Start-KitRunnerProcess` у `Runner.psm1` стає викликом першої; решта `Runner.psm1` — без змін логіки.
- **Запобіжник**: поза модулем `runner` Rust-код раннер не запускає — правило в `rust/tests/git_guard.rs` або
  поруч, тією самою лексичною схемою, з контролем, що вміє впасти.

### 5.3 B3 `kit check`

- **Параметри** як зараз: `-RepoRoot`, `-Workspace`, `-Source`, `-Quiet`, `-InstalledPluginsPath`, `-RunnerPath`;
  форма виклику й коди — ADR-0014 п. 4.
- **Перевірки** — той самий набір і ті самі ідентифікатори у виводі: `manifest`, `kit-version`, `overlay`, `workspace`, `source`,
  `unica-version`, `runner-version`, `agent-base-required`, `main-branch`, `unique-keys`, `overlay-ignored`,
  `overlay-connection`, `gitattributes`, `case-collision`, `gitignore`, `supply`, `storage-path`, `storage-branch`,
  `dump-from`, `config-name`, `undeclared-source`, `build-artifacts`, `local-ignored`, `local-audit`, `hooks`,
  `hook-shim`. Що кожна читає — git (через ядро), дерево, маніфест, накладка, `v8project(.local).yaml`, реєстр
  плагінів, раннер `--version`.
- **Інваріанти `storage/*`** (`storage-branch`): трейлери й версії комітів, колізії регістру дерева — читанням
  git, без запису.
- **`check` як функція** для B4: повертає знахідки без друку (`-Quiet`); `runner-version` і `unica-version`
  сигналів `session-check` не блокують (як `$MachineStateChecks`).
- **Вивід** звіряється з еталоном PowerShell побайтно, крім відомих відмінностей §6 (текст помилки розбору YAML).

### 5.4 B4 `kit session-check` і хук

- **Поведінка** — на цільовому коміті (§5.0): спершу `check` як функція; помилка `check` — код 1 без сигналів;
  далі на кожне джерело `truth: storage` — дзеркало `storage/<ключ>`, активність сховища (`1cv8ddb.1CD`,
  `data/objects`, `data/pack`), відбиток сховища, відставання від `origin` без мережі; дзеркало лише на `origin`
  (локальної гілки немає, `origin/<гілка>` є) — сигнал `remote-only` з кодом 4 і кроком відновлення гілки
  (`Get-KitRestoreMirrorStep`) незалежно від доступності сховища; коди 0/1/4, рядок `next:` за ADR-0014 п. 4. Параметри як зараз:
  `-RepoRoot`, `-Workspace`, `-Source`, `-AsJson`, `-InstalledPluginsPath`, `-RunnerPath`. `-AsJson` — одна форма
  верхнього рівня і на успіху, і на помилці; звіряється з еталоном розібраними значеннями (ADR-0014 п. 7),
  текстовий вивід — побайтно.
- **Відбиток сховища** — лише читання формату, який пише `sync` (`StorageImprint.psm1`, фаза 3); схема й версія
  відбитка не змінюються.
- **Хук `session-start`**: у репозиторії з маніфестом кличе `kit.exe session-check` дочірнім процесом з тією
  самою стелею часу (`V8KIT_SESSION_CHECK_TIMEOUT`, 15 с за умовчанням), убивством дерева на стелі й текстом
  «стан сховищ НЕВІДОМИЙ»; передачі PowerShell і `pwsh` у хуку більше немає.

## 6. Security and data integrity

- **Секрети.** Накладка й `v8project.local.yaml` містять паролі сховищ і бази агента, рядки підключення —
  облікові дані. Інваріант для тексту, який **формує сам kit** (вивід, знахідки, помилки, JSON), — той, що тримає
  PowerShell-версія зараз: (а) значення пароля не друкується ніколи; (б) рядок підключення не друкується сирим
  текстом — лише розібрані компоненти без облікових даних та імена його ключів (як `ConvertFrom-V8Connection`:
  «містить '=' у значенні ключа 'File'»); (в) ключ чи значення **YAML-мапи, що не пройшли перевірку** (невідомий
  ключ, запис без значення, дубль, рядок замість мапи, неправильна форма шляху сховища) — не друкуються: їх
  називають шляхом до мапи й номером запису, бо туди міг потрапити секрет. Законні імена й значення (джерело,
  воркспейс, дев-база, шлях сховища у знахідці `storage-path`) друкуються, як зараз. Тексти помилок `serde`/`serde_yaml`
  (вони цитують значення й ключі: `invalid type: string "…"`, `unknown field …`, `duplicate entry …`) у вивід не
  передаються — лише місце в файлі (рядок, колонка). Наявна PowerShell-версія так само ховає невідомий ключ, запис
  без значення й шлях сховища (`Manifest.psm1`), але текст помилки розбору YAML (`Read-KitYaml`) вклеює дослівно, і
  YamlDotNet на дублі друкує ім'я ключа — це відома відмінність за ADR-0014 п. 7 (виправлений дефект), еталон на
  таких фікстурах не звіряють побайтно. Розбір не панікує: паніка в `kit.exe` друкує текст у stderr, а хук вклеює
  stderr у контекст сесії.
  Перевірка — маркерні тести з маркером у позиції значення (пароль, значення компонента рядка підключення,
  значення чи ключ YAML-мапи, що не пройшли перевірку) у накладці та `v8project.local.yaml` для класів: рядок
  замість мапи, дубль ключа, невідомий ключ, запис без значення, неправильний рядок підключення; маркер не
  з'являється ні в stdout, ні в stderr. Хто тримає який канал — «готово,
  коли» B1 (модуль `config`, підкоманда префлайту), B3 (`check`), B4 (`session-check`, контекст хука). Наявний
  `Secrets.Tests.ps1` переходить на `kit.exe` для своїх `Describe` з підпроцесом.
- **Вивід раннера** kit передає дослівно (конверт, `error.message`, stderr) і не маскує: раннер сам читає
  `v8project.local.yaml` і відповідає за свій вивід (контракт — `docs/unica-contract.md`). Обіцянка інваріанта вище
  на нього не поширюється.
- **Межі довіри.** Маніфест, накладка й `v8project*.yaml` — вміст репозиторію; хук читає їх у кожній сесії. Збій
  розбору — знахідка чи помилка, не паніка; затяжний розбір обмежує стеля часу хука. `serde_yaml` 0.9.34 обмежує
  рекурсію й повторення якорів (`RecursionLimitExceeded`, `RepetitionLimitExceeded`); план B1 перевіряє це
  фікстурою з вкладеними якорями — розбір завершується помилкою, а не зависанням.
- **Раннер** береться з `installPath` установленої Уніки. Єдиний інший шлях — явний параметр командного рядка
  (`-RunnerPath` команд, параметр прихованої підкоманди) для тестів; з маніфесту, накладки й оточення шлях раннера
  не береться — тест: маніфест і змінна оточення з іншим шляхом раннера його не підміняють. Хук передає
  `session-check` закритий перелік аргументів без `-RunnerPath`; дочірній `kit.exe` хук бере з `current_exe`,
  не з `PATH`. Реєстр плагінів шукають у домашній теці користувача з оточення процесу, як зараз; хто керує
  оточенням процесу kit, той і без kit запускає що завгодно. Правила allow для `kit.exe` у `.claude/settings.json`
  kit і `templates/settings.json` — лише дослівні рядки без шаблонів (`:*`, `*`), тож форма з `-RunnerPath`,
  `-InstalledPluginsPath` чи змінною перед командою потребує запиту; тест у «готово, коли» B3.
- **Без запису** — §5.0; фаза не торкається сховища, бази агента й гілок `storage/*`.
- **Часткові дані.** Поблажливий префлайт збирає контекст частково; `check` і `session-check` друкують знахідки
  про відсутнє, а не мовчать про нього (як зараз), і жодна перевірка не стає зеленою на неповному контексті.
