# Глосарій v8storagekit

Один термін — одне значення в спеках, планах, скілах і коді. Колонка «Уникати» — слова, які
означали б те саме; їх не вживаємо. Нові терміни додає той, хто їх уводить, у тому ж коміті.

## Процес

| Термін | Значення | Уникати |
|---|---|---|
| **власник** | людина, що ухвалює продуктові й незворотні рішення; єдине джерело дозволу на зовнішні дії | користувач (у текстах процесу), замовник |
| **архітектор** | сесія, що веде напрям частини системи: спека, розвилки, брифи, приймання планів і PR, злиття. Коду й планів не пише | головна сесія, оркестратор (коли мова про роль) |
| **контролер** | сесія, що виконує прийнятий план скілом `execute`: роздає задачі виконавцям, кличе рецензентів, веде журнал. Коду сама не пише | оркестратор (коли мова про виконання плану) |
| **виконавець** | субагент `implementer`: одна задача плану — код, тести, коміти, звіт | імплементатор, розробник |
| **спека** | документ «що» (стан) з таблицею блоків і таблицею «інтерфейс → блок-власник»; «чому» — в ADR | специфікація, дизайн-документ |
| **ADR** | один файл на одне вагоме рішення: контекст, рішення, чому, відкинуте, наслідки, статус | реєстр рішень у спеці |
| **блок** | рядок таблиці блоків спеки: обсяг, «готово, коли», залежності. Один блок — одна гілка — один PR | етап, фаза |
| **план** | ескіз виконання одного блоку: рішення, інтерфейси, інваріанти, задачі з «готово, коли». Без коду | імплементаційний план (як синонім) |
| **задача** | один пункт плану блоку; ідентифікатор `sdd` (`3`, `1c`, `3.2`) | крок, таск |
| **бриф** | файл з роллю, межами й форматом звіту для сесії або субагента; повідомлення — один рядок з шляхом до брифу | промпт (коли мова про файл) |
| **журнал** | `progress.md` у робочій теці плану `.agents/sdd/<план>/`; лише дописується | леджер, прогрес |
| **вікно виконання** | відрізок історії між відкриттям (`dispatch`/`fix`/`resume`) і закриттям (`watch`/`done`); коміти задачі — об'єднання її вікон | діапазон задачі |
| **вага задачі** | `trivial` / `standard` / `risky`; задає модель виконавця, вид рецензії й доказ | складність |
| **раунд виправлень** | одна ітерація «знахідки → виправлення → повторна рецензія»; не більше двох на задачу | ітерація |
| **розвилка класу A / B** | A — не змінює спеку, контракт чи поведінку, вирішує контролер; B — змінює, вирішує архітектор або власник | — |
| **лінза** | одне незалежне джерело сигналу рецензії (`correctness`, `test-honesty`, …); один рецензент на лінзу | зріз, аспект |
| **верифікатор** | субагент `code-review-verifier`: пробує спростувати одну знахідку | скептик |
| **не перевірено** | результат скрипта з кодом виходу 3: перевірка не відбулась; ніколи не зелений | пропущено, ок (для такого стану) |
| **головний checkout** | робоча копія, чия тека `.git` — спільна для всіх worktree (батько `git-common-dir`); тут живе спільний стан процесу: журнали `sdd`, пакети рецензії, вивід `pr-gate` і `codex-audit` (ADR-0025) | основна копія, головне дерево |
| **еталон виводу** | вивід PowerShell-версії команди, знятий на фікстурах до видалення її модуля; Rust-версію звіряють з ним за ADR-0014 п. 7 і ADR-0021 п. 1 | golden, знімок (коли мова про цей вивід) |
| **цільовий стан** | поточні шаблони й правила kit, з якими онбординг звіряє репозиторій-споживач незалежно від версії, з якої той прийшов (ADR-0016) | ланцюжок версій (як спосіб онбордингу), міграція з версії X |

## Тести

| Термін | Значення | Уникати |
|---|---|---|
| **рівень тестів** | іменований спосіб прогону з профілю (`tests.levels.<ім'я>`): команда, вид звіту, межі | набір (коли мова про рівень) |
| **цільовий прогін** | прогін частини рівня: конкретний файл, модуль або лише зачеплене змінами | вибірковий прогін |
| **драбина перевірок** | упорядкований словник сходинок перевірки зміни 1С, від дешевої до дорогої; кожна задача плану називає свою найвищу сходинку (ADR-0012) | глибина перевірки, рівні перевірки |
| **сходинка** | один щабель драбини перевірок з ім'ям: `check`, `push`, `syntax`, `yaxunit`, `acceptance`. Не рівень тестів: рівень — спосіб прогону з профілю, сходинка — місце в драбині | рівень (коли мова про драбину) |
| **звіт прогону** | запис результату одного прогону сходинки у форматі kit, незалежному від того, хто запускав прогін (ADR-0009) | результат тестів, лог прогону |
| **адаптер прогону** | частина kit, що запускає прогін сходинки або приймає результат від Уніки й віддає звіт прогону | виконавець прогону (виконавець — субагент) |
| **доказ прогону** | звіт прогону, який kit прийняв для коміту: коміт = `HEAD` до й після прогону, дерево source-set-ів чисте, стан бази агента звірений; для `yaxunit` виконано більше нуля тестів, для `syntax` є базова лінія; зберігається в `.agents/evidence/` (ADR-0010) | evidence, артефакт прогону |

Політика тестів 1С — «лише ключове» (ADR-0010).

## 1С

| Термін | Значення | Уникати |
|---|---|---|
| **джерело** | запис під `sources:` воркспейсу в маніфесті `v8storagekit.yaml`: ключ, що збігається з `name:` source-set у `v8project.yaml`, і `truth` — звідки береться істина дерева | набір (коли мова про запис маніфесту) |
| **вимкнене джерело** | джерело з `enabled: false` і обов'язковим `reason:`: префлайт його пропускає, команди kit його не бачать, а source-set для нього у `v8project.yaml` не оголошують (ADR-0022) | закоментоване джерело |
| **похідний набір** | source-set з `truth: derived`: дерево готує скрипт проєкту з інших дерев, воно гітігнороване, і kit його не синхронізує, не звіряє й не вантажить (ADR-0022) | збірний набір, копія ядра (як термін) |
| **база агента** | інформаційна база воркспейсу (`infobases.origin` у `v8project.local.yaml`), яку агент збирає й тестує; територія раннера Уніки | тестова база, база розробника |
| **спільне дерево** | режим робочої копії, у якому кілька сесій працюють в одному checkout і одній базі агента | — |
| **раннер** | `v8-runner`, що постачається з установленою Унікою | — |
| **конверт раннера** | JSON-відповідь раннера на виклик з `--json-message`: `ok`, `command`, `data`, `warnings`, `error` (`code`, `kind`, `message`); kit читає раннер лише так | відповідь раннера (як формат), JSON раннера |
| **префлайт** | перевірка контексту до команди сховища: маніфест, накладка, воркспейси, звірка джерел із source-set-ами `v8project.yaml`; результат — контекст команди й знахідки | preflight, попередня перевірка |
| **відома відмінність** | дефект PowerShell-версії, який Rust-перенесення виправило: записується в шапці Rust-модуля й у закритому переліку тесту паритету, на який посилається кожна класова фікстура; паритет на такому класі — класом, не текстом (ADR-0014 п. 7, ADR-0021) | розбіжність, регресія (відмінність навмисна) |
| **дзеркало** | гілка `storage/<ключ>`: по коміту на версію сховища з трейлером `Storage-Version:`; пише лише `kit sync` | гілка сховища, mirror |
| **відбиток сховища** | файл `build/session-check/<ключ>.json`: версія зі звіту сховища, момент читання й знімок `data/objects`/`data/pack`; кеш, не стан — пише `sync`, читає `session-check` | стан сховища, кеш (без уточнення) |
| **безпечний робочий шлях** | шлях, який kit довів власною теці перед записом чи видаленням: власна підтека межі, без `..`, без посилань дорогою, крім власної теки (ADR-0023) | перевірений шлях |
| **фальшива платформа** | тестовий бінарник на місці `1cv8.exe`, що відповідає на команди Конфігуратора за сценарієм фікстури; потрапляє до kit лише через шлях платформи від фальшивого раннера чи явний параметр (ADR-0023) | мок платформи |
| **стан машини** | знахідки `check` про інструменти машини, а не репозиторію (`runner-version`, `unica-version`); не блокують сигналів `session-check` | знахідка репозиторію |
| **синтакс-контроль** | перевірка модулів Конфігуратором через `v8-runner check` з названим набором контекстів. Не `unica.check`: той — статичний аналізатор Уніки | синтаксична перевірка Уніки, компіляція |
| **базова лінія синтакс-контролю** | збережена мультимножина пар «модуль, повідомлення» без позицій; прогін зелений, коли нових пар немає | еталон помилок |
| **запобіжник бази агента** | перевірка kit до дії в базі агента, що зупиняє дію: замок бази агента вільний, дерево source-set-ів чисте, `push` лише названого source-set і ніколи `truth: vendor`, жодного неявного повного завантаження на серверній базі, ліцензія | гард, сторож |
| **замок бази агента** | файл-маркер машини з власником, метою й часом: поки він є, інша сесія не діє в цій базі агента (ADR-0011) | замок підтримки, блокування |
| **мовчазна відмова** | повідомлення платформи в лозі пакетного запуску, що означає відмову, хоча код виходу 0 | — |
| **замок підтримки** | стан об'єкта основної конфігурації на підтримці вендора, за якого редагування заборонене; записаний у `Ext/ParentConfigurations.bin`; знімає людина в Конфігураторі (ADR-0011) | замок бази агента, блокування (те — транзакції), захоплення (те — сховище) |
