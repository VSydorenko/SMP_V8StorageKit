# ADR-0011: Хуки kit — запис у код вендора блокується, мовчазні класи BSL лише попереджають

Status: accepted 2026-11-21
Decided by: owner
Spec: docs/superpowers/specs/2026-11-20-1c-specificity-design.md §5.3

## Context

Обидва зразки для 1С на GitHub (`Nikolay-Shirokov/cc-1c-skills`, `comol/ai_rules_1c`) мають хук
`support-guard`: `PreToolUse` на Edit/Write, що читає стан підтримки з `Ext/ParentConfigurations.bin`
і відмовляє в прямій правці об'єкта вендора. У kit такого хука немає. Джерела `truth: vendor` у git
не потрапляють, але лежать на диску для Уніки. На живому проєкті кілька класів дефектів BSL
проходили рев'ю, бо синтаксично коректні: `Свойство(Ключ, Змінна)` без умовчання, булеве значення
з JSON у голій умові, `ЗаписьЖурналаРегистрации` у клієнтському коді, нетипізований
`ФабрикаXDTO.ПрочитатьXML`, сигнатура `&После`, що не повторює базову, — такий перехоплювач
платформа мовчки не підключає (виміряно 2026-09-28, #23).

## Decision

1. Хук `PreToolUse` на запис файлів **відмовляє**:
   - завжди — у теках джерел `truth: vendor`;
   - для об'єкта основної конфігурації із замком підтримки.

   Об'єкт зі знятим замком хук пропускає.
2. Відмова називає два легітимні шляхи: запозичити об'єкт у розширення **або** зняти замок
   підтримки (дозволити редагування) і далі правити основну конфігурацію. Розробка може йти й в
   основній конфігурації зі знятим замком. Хто знімає замок — відкрите питання спеки (§7).
3. Pre-commit перевірка змінених `.bsl` на мовчазні класи з #23 лише **попереджає**: `[!]`, файл,
   рядок, клас. Шаблони класів налаштовуються, не вшиті.
4. Замок бази агента між сесіями (#19) — хук `PreToolUse` на `unica_run` і перевірка в командах kit.
5. Хуки — підкоманди `kit.exe` (Rust).

## Why

- Запис у код вендора поза розширенням і поза знятим замком завжди помилковий — відмова дешевша
  за втрачену при оновленні правку.
- Класи BSL мають хибні спрацювання (власні обгортки проєктів), тому блокування коміту коштувало б
  більше, ніж ловило.
- Уніка читає стан підтримки (`unica.view` → `props.support`) і має операцію `supportRule.set`
  (`<плагін Уніки 0.16>/skills/release-support/SKILL.md`), але хук MCP не кличе — він мусить читати
  `ParentConfigurations.bin` сам.
- Старт Rust ~12 мс (спайк 2026-11-20) робить хук на кожен запис дешевим, на відміну від `pwsh`.

## Rejected

- Обидва хуки лише попереджають — запис у код вендора пройде, якщо агент проігнорує попередження.
- Обидва блокують — хибне спрацювання класу BSL зупинятиме коміт і вимагатиме обходу.
- Без хуків, лише лінзи рев'ю — захист тримається на тому, чи прочитав агент правило.

## Consequences

- Хук мусить читати стан підтримки з `ParentConfigurations.bin`; формат міряється задачею 0 плану
  блоку хуків за специфікацією `<cc-1c-skills>/docs/1c-support-state-spec.md` (MIT, з атрибуцією).
- Хук бачить лише інструменти запису файлів. Чи відмовляє `unica.apply` сам на вузлі із замком
  (`can[].blocked` у відповіді Уніки), міряється тією самою задачею 0; якщо ні — хук отримує
  матчер і на `unica_apply`.
- Блок хуків залежить від входу `kit.exe` (#51).
