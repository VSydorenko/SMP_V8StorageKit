# ADR-0013: Авторство тестів YaXUnit — форк `astrizhachuk/yaxunit-test-writer` у скілі `1c-yaxunit`

Status: accepted 2026-11-21
Decided by: owner
Spec: docs/superpowers/specs/2026-11-20-1c-specificity-design.md §5.1.4

## Context

Спека віддавала авторство тестів (як написати тест YaXUnit) скілу `unica:test-authoring`, а він
про API YaXUnit майже нічого не містить (вереснева спека `feature/test-contour`, Р5). Скіл
`astrizhachuk/yaxunit-test-writer` (MIT, коміт `b60846f`, 2026-10-19) описує саме авторство:
процес, імена модулів, тестів і наборів, теги, структуру модуля, транзакції, Мокито й
перехоплювачі `&Вместо`, тестові дані, чекліст, шаблони метаданих тестового розширення. Запуску
тестів, політики обсягу й правил спільної бази агента в ньому немає; він припускає порожню базу й
спрацьовує на «покрой тестами».

## Decision

1. Частина авторства скілу `v8storagekit:1c-yaxunit` — форк `yaxunit-test-writer` з коміту
   `b60846f`. Кожен перенесений файл має шапку `Ported from astrizhachuk/yaxunit-test-writer
   b60846f <шлях>, modified`; текст ліцензії MIT і copyright автора лежать у теці скілу.
2. Текст перекладається українською (ADR-0008); код BSL, ідентифікатори й шаблони — як в оригіналі.
3. Адаптації під kit:
   - політика «Тести — лише ключове» (ADR-0010) і перелік тестів із плану мають перевагу; тригера
     «покрой тестами» в описі немає;
   - лише формат Designer XML і платформа гілки 8.3.27: частини й шаблони EDT і 8.3.16 не
     переносяться;
   - об'єкти метаданих тестового розширення створює Уніка (`unica.apply`); шаблони — довідка для
     звірки;
   - середовище (тестове розширення, платформа) — з розділу `## Тести YaXUnit` у
     `templates/CLAUDE.md`, який заповнює `onboarding`, без питань людині; проєктний тег — з ідентифікатора задачі плану, якщо він є, без питання;
   - припущення «порожня база» замінюють правила спільної бази агента (фікстури, транзакція на
     рівні тесту, #21).
4. Оновлення з оригіналу — вручну, за рішенням власника: diff оригіналу від записаного коміту.
5. **Зв'язок з ADR-0012 п. 4.** Авторство тестів YaXUnit — названий виняток із правила «у kit іде
   лише виміряне знання»: Уніка цього знання не покриває, тож kit її не дублює. Твердження форку про
   поведінку платформи (контексти компіляції, перехоплювачі) — виміряні на гілці 8.3.27 або
   позначені гіпотезою; шаблони XML — лише довідка, XML пише Уніка.
6. Шапка походження стоїть у кожному перенесеному файлі (`SKILL.md`, `references/`, шаблони); у
   XML — коментарем одразу після декларації `<?xml …?>`, щоб файл лишався дійсним.

## Why

- Рішення власника: одна установка для споживача й правила авторства, узгоджені з політикою й
  контуром kit.
- Шапка походження й записаний коміт роблять звірку з оригіналом механічною, як для форку
  agent-kit (ADR-0001).

## Rejected

- Зовнішній супутник (посилання на встановлений скіл) — рекомендація архітектора; власник обрав
  форк.
- Лишити авторство на `unica:test-authoring` — він не знає API YaXUnit.

## Consequences

- Kit супроводжує переклад і адаптацію; оновлення оригіналу самі не приходять.
- Скіл `1c-yaxunit` стає більшим за «тонкий»: тіло `SKILL.md` лишається коротким і маршрутизує,
  авторство живе в `references/`.
