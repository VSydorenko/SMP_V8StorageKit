# ADR-0001: Процес розробки — форк agent-kit 0.9.1 усередині v8storagekit

Status: accepted 2026-11-19
Decided by: owner
Source: agent-kit 0.9.1 (оригінал, `.agents/private/agent-kit` у ворктрі блоку); окремої спеки немає — рішення власника 2026-11-19

## Context

У 1С-проєктах на Windows процес вели скіли superpowers і ручні адаптації з пам'яті
(`superpowers:subagent-driven-development` «без worktree й паралельних імплементаторів»).
У веботоченні власника той самий процес уже замінено плагіном agent-kit
(`github.com/VSydorenko/agent-kit`, версія 0.9.1, 2026-11-19): скіли, агенти, скрипти, хуки,
профіль проєкту. Власник хоче той самий процес для 1С на Windows, у плагіні v8storagekit.

## Decision

Скіли, агенти й механізми agent-kit 0.9.1 копіюються у v8storagekit з тими самими назвами й
переробляються під 1С і Windows. Кожен файл із перенесеним текстом має шапку
`<!-- Ported from agent-kit 0.9.1 <шлях>, modified. -->`. Оновлення agent-kit переносяться
вручну, коли вони цінні; походження дає шапка.

## Why

- Власник обрав форк перед варіантом «agent-kit на Windows + 1С-пакет» 2026-11-19.
- Відмінності 1С не зводяться до значень профілю: немає CI, одна база агента на воркспейс,
  сховище конфігурацій. Вони змінюють самі правила скілів (`execute`, `plan`, `landed-review`).
  У спільному тексті вони стали б розгалуженнями «є CI / немає CI» і роздули б інструкції.
- Зміни під Windows не зачіпають Linux-оточення власника.

## Rejected

- agent-kit на Windows + 1С-пакет у v8storagekit — один процес, але розгалуження в текстах
  скілів і ризик для Linux-оточення.
- Писати процес з нуля — втрачаються виміряні уроки agent-kit (ліміти раундів, вікна
  виконання, верифікатор, «не перевірено» замість зеленого).

## Consequences

Дві копії процесу. Урок одного оточення в інше сам не потрапляє: скіл `retro` пропонує
перенос, коли знахідка загальна. superpowers після пілоту прибирається з машини (задача
власника).
