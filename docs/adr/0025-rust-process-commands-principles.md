# ADR-0025: Перенесення команд процесу в Rust — формати для інших, регулярні вирази, корінь `-C`, тести

Status: accepted 2026-11-28
Decided by: architect
Spec: docs/superpowers/specs/2026-11-28-rust-phase4-process-design.md §5
Supplements: ADR-0014, ADR-0021

## Context

Фаза 4 переносить у `kit.exe` команди процесу: `sdd`, `review-pack`, `pr-gate`, `doc`, `track`, `kit-setup`,
`kit-scan`, `session-cost`, `codex-audit` (#55). На відміну від `check`, вони **пишуть**: журнал `sdd`, пакет
рецензії, гілки й PR (`pr-gate`), issue (`track`), профіль (`kit-setup -SetVersion`). Їхній вивід і файли читають
інші — скіли, агенти, журнали, початі до переносу, тіла issue на GitHub. Логіка `doc` і `track` стоїть на
регулярних виразах .NET з lookbehind, `\p{L}` і Unicode-`\w`; `doc find` і `doc history -Only/-Ignore` приймають
вираз від людини. Команди процесу беруть корінь лише з поточної теки, команди сховища — з `-RepoRoot` (#93).
Тести цих команд — частково чорна скринька Pester, частково внутрішні функції PowerShell; у `session-cost` тестів
немає зовсім.

## Decision

1. **Принцип переносу — ADR-0021 п. 1** («краще, а не паритет», закритий перелік відомих відмінностей, еталон
   виводу PowerShell знято до видалення модуля). Діє без змін і на команди процесу.
2. **Формати, які читають інші, — побайтний паритет**, а не «краще»: рядки журналу `sdd` (`# SDD ledger — plan:`,
   `Task N:`, `Window (task N):`, `Ruling (task N):`, `# closed`), маркери `track` у тілах issue
   (`<!-- track:spec … -->`, `<!-- track:block … -->`, рядки `Depends on:`), формат `CHANGELOG.md`, stdout
   `pr-gate scratch add` (лише шлях), файли `land-<pr>.json` і `status.json`, рядок `next:`. Rust читає кожен
   наявний файл таких форматів, записаний PowerShell-версією. Виправити дефект такого формату можна лише так, щоб
   старі записи читались далі.
3. **Регулярні вирази — крейт `regex`** (лінійний час, без lookaround і зворотних посилань). Вбудовані шаблони з
   lookbehind чи lookahead переписують ручною перевіркою межі навколо збігу. Користувацький вираз (`doc find`,
   `doc history -Only/-Ignore`) — діалект `regex`: це **відома відмінність** від .NET; вираз, що не компілюється
   (зокрема з lookaround), — помилка виклику (код `2`) з текстом причини, без цитування вмісту файлів.
4. **Корінь — `-C <шлях>` для кожної команди kit** (#93). Опція стоїть першими двома токенами після імені команди
   (`kit sync -C <шлях> …`, `sdd -C <шлях> status`). `kit.exe` змінює поточну теку процесу на цей шлях до розбору
   решти аргументів — так само для перенесених команд і для тих, що ще йдуть диспетчеру PowerShell. Далі кожна
   команда шукає корінь так, як шукала від поточної теки; відносні шляхи інших аргументів розв'язуються від нової
   теки, як у `git -C`. Шлях, що не є наявною текою, — код `2`. `-RepoRoot` команд сховища лишається (фаза 3).
5. **Спільний стан процесу — у головному checkout** (батько `git-common-dir`): журнали `sdd`, пакети рецензії,
   вивід `pr-gate` і `codex-audit`. Обчислює його одна функція крейта.
6. **Тести.** Pester лишається чорною скринькою для розробки kit: приймальні тести команди запускають `bin/kit.exe`
   підпроцесом на синтетичному репозиторії; фальшиві `gh` і `codex` — лише виконувані файли в `PATH` чи в профілі.
   Тести внутрішніх функцій PowerShell зникають разом із модулями; логіку розбору (журнал `sdd`, Markdown, таблиця
   спеки `track`, `CHANGELOG.md`, транскрипти `session-cost`) тримають unit-тести Rust. `pwsh` після фаз 3 і 4 —
   залежність розробки kit (тести, скрипт збірки), не споживача.
7. **Зовнішні дії** (`git push`, `gh`, `codex`) — лише через модулі крейта `git` і `gh` та один запуск `codex` у
   модулі команди; запобіжник `rust/tests/git_guard.rs` перелічує кожен дозволений запуск. Інваріанти `pr-gate`
   («ніколи не пушить головну, базову й `storage/*` гілку», «ніколи force», «`pr.afterMerge` лише з профілю на
   origin») тримають тести чорної скриньки з контролем, що вміє впасти.

## Why

- Журнал `sdd`, почати під PowerShell-версією, контролер читає далі після оновлення плагіна; маркери `track` живуть
  в issue роками. «Краще» тут ламало б дані інших, тож правило ADR-0021 обмежено саме цим переліком.
- `fancy-regex` дає lookaround, але має бектрекінг: користувацький вираз над усім корпусом репозиторію міг би висіти.
  Лінійний `regex` прибирає цей клас; вбудованих шаблонів небагато, і межу збігу видно в коді прямо.
- `-C` за зразком git знайомий агенту; зміна поточної теки до розбору дає одне правило для команд у Rust і в
  PowerShell і не вимагає вчити кожну команду окремому параметру. Перші два токени після імені — бо обгортки
  `bin/<команда>` передають `kit.exe` ім'я команди першим.
- Тести внутрішніх функцій PowerShell не переживають видалення модуля; чорна скринька — переживає й саме вона
  доводить, що перенесена команда поводиться як та, яку замінила (ADR-0014 п. 7).

## Rejected

- `fancy-regex` для сумісності з .NET — бектрекінг на виразі людини; зайва залежність.
- Глобальна опція `--repo` перед ім'ям команди — граматика kit не приймає `--`-опцій (`rust/src/cli.rs`), а
  обгортки `bin/` ставлять ім'я команди першим.
- `-RepoRoot` для команд процесу — ім'я задає точний корінь, а команди процесу шукають його від будь-якої теки
  всередині; одна назва з двома значеннями гірша за дві різні.
- Переписати Pester-тести на Rust — дорого й без виграшу: чорна скринька однаково запускає процес.

## Consequences

- Вираз з lookaround у `doc find` перестає працювати; довідка `doc -Help find` називає діалект.
- `bin/kit.exe` росте на розмір `regex`; після першої збірки з ним — звичайна перевірка Defender (`CLAUDE.md`).
- Нова відмінність від PowerShell у форматі з п. 2 неможлива без читача старих записів і тесту на запис
  PowerShell-версії.
- Розділ «Команди kit для репозиторію поза текою сесії» скіла `1c-unica` зводиться до правила `-C`.
