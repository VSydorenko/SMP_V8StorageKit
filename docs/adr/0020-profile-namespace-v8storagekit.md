# ADR-0020: Профіль, спільний з agent-kit, — версія й зональні секції v8storagekit у власному просторі імен

Status: accepted 2026-11-23
Decided by: owner (окреме поле версії), architect (решта)
Supplements: ADR-0003

## Context

ADR-0003 узяв для профілю `.agents/kit.profile.json` ті самі імена полів, що й agent-kit. У репозиторії з двома
зонами (issue #107: munin-mcp — зона 1С на Windows з v8storagekit, зона шлюзу на Linux з agent-kit) обидва плагіни
читають один файл, і їхні версії незалежні (agent-kit на лінії 0.x, v8storagekit — 1.x). Одне поле `kit.version`
на двох означає, що запис версії одним плагіном глушить підказку оновлення іншого. Секція `tests` теж спільна:
`sdd` кладе в бриф виконавця **всі** `tests.levels`, тож виконавець 1С отримує команди vitest з Linux-зони. Команди
`pr.afterMerge` залежать від ОС. agent-kit невідомі ключі ігнорує (deepMerge без схеми).

## Decision

1. **Версія проєкту для v8storagekit — `v8storagekit.version`** (рішення власника). `kit.version` належить agent-kit:
   v8storagekit його не пише й не змінює (`kit-setup -SetVersion` пише лише новий ключ).
2. **Тимчасовий запасний шлях.** Немає `v8storagekit.version`, але є `kit.version` ≥ 1.0.0 — береться він (проєкт
   лише з v8storagekit, підключений до цього рішення). `kit.version` < 1.0.0 чи невалідний — чужий (agent-kit):
   «версію не задано», мовчки, без помилки; хук старту сесії тоді рахує від 0.1.0, як для будь-якого профілю без
   версії. `Bad` — лише невалідний `v8storagekit.version`. Крок оновлення 1.6.14 переносить поле; запасний шлях
   прибирає наступна версія, що змінює читання профілю.
3. **Простір імен секцій.** Наявна секція першого рівня `v8storagekit.<секція>` заміняє верхню `<секцію>` **цілком**,
   без злиття: `v8storagekit.tests` без `levels` не пропускає рівні верхнього `tests`. Потрібне для `tests` і `pr`
   (через `pr.afterMerge`); `workspace.mode` лишається на верхньому рівні — agent-kit його не читає. Решта секцій
   зі спільним змістом (`docs.*`, `worktrees.root`, …) — спільні.
4. **Порядок.** Спершу зливаються шари (машина → проєкт → локальний), потім на злитому результаті діє простір імен.
   Читачі одного шару застосовують те саме правило до свого шару: `pr.afterMerge` із профілю на коміті головної
   гілки origin, читання версії хуком (лише проєктний файл).
5. **Одна реалізація на мову.** Rust — `rust/src/profile.rs` (`apply_namespace`, `project_version`; хук
   `session_start` кличе їх). PowerShell — `Resolve-KitProfileNamespace` (`KitProfile.psm1`) і
   `Get-KitProjectVersion` (`KitVersion.psm1`); `sdd`, `pr-gate`, `kit-scan`, `kit-setup` кличуть їх.

## Why

- Незалежні версії двох плагінів не можуть жити в одному полі — це дефект сумісності, а не стиль.
- Межа 1.0.0 сьогодні точно розділяє дві лінії; без запасного шляху проєкти, підключені раніше, втратили б кроки
  оновлення 1.6.14 (зокрема сам крок перенесення).
- Заміна секції цілком, а не по листках, — єдиний спосіб гарантувати, що рівні тестів іншої зони не потрапять у бриф.
- PowerShell заморожено ADR-0014 п. 7; ця зміна — виняток за рішенням власника про дефект сумісності з agent-kit
  (у ній блокується онбординг munin-mcp), і Rust-порт фаз 2–4 переносить її як є.

## Rejected

- Зональні значення в `.agents/kit.profile.local.json` машини 1С — не в git; нова машина отримує їх лише вручну, а
  `pr-gate land` `pr.afterMerge` з локального шару не бере.
- Перекриття по шляху листка (`v8storagekit.tests.levels`, потім `tests.levels`) — `v8storagekit.tests` без `levels`
  пропустив би рівні Linux.
- Без запасного шляху для `kit.version` — проєкти лише з v8storagekit на 1.6.x втратили б чекліст оновлення.

## Consequences

- Коли agent-kit дійде до 1.0.0, запасний шлях має бути вже прибраний; до того крок 1.6.14 переносить версію.
- Нове поле, яке залежить від зони, додається в простір імен `v8storagekit` за тим самим правилом, без нового ADR.
