# ADR-0014: Rust і один вхід `kit.exe`

Status: accepted 2026-11-21
Decided by: owner
Source: doc docs/superpowers/specs/2026-11-20-single-entry-and-git-core-design.md §0, D1, D1а; рішення власника 2026-11-20 (обговорення #51)

Замінює частково ADR-0002: рішення про окремий вхід команд процесу `tools/kit-process.ps1`.
Решта ADR-0002 (команди kit на PowerShell, короткі обгортки в `bin/`) діє, доки команда не перенесена.

## Context

Плагін склеєно з двох інструментів, і з цього лишились три наслідки, усі про те, як kit запускає
процеси й каже про результат:

- дві точки входу: `tools/kit.ps1` з param-блоком, що перехоплює токени команд, і
  `tools/kit-process.ps1` без нього (ADR-0002);
- два контракти кодів виходу, де коди `2` і `3` означають різне;
- кілька обгорток запуску git з різними контрактами збою.

До цього додається вартість старту PowerShell: хук старту сесії запускає `pwsh` у кожній сесії
машини, навіть у проєкті без маніфесту й профілю, де він мусить лише мовчки вийти.

Окремий вимір (спека, D1а): `pwsh -File` сам переписує аргументи. `-Ім'я:значення` розщеплюється на
два токени, а `-X:false` стає `-X` плюс `False`. Проба: `-Apply:false` дійшов як `[-Apply] [False]`,
тобто `kit sync -Apply:false` застосував би зміни замість прев'ю. Той самий дефект живий на шляху
`bin/` → `kit-process.ps1` (`doc refs -Code:false` шукає шлях `False`).

## Decision

1. Код kit переходить з PowerShell 7 на Rust: один крейт `kit` у `rust/`, ціль
   `x86_64-pc-windows-msvc`. Залежності — мінімум, кожна з обґрунтуванням.
2. Єдиний вхід усіх команд — бінарник `kit.exe` у теці `bin/`. Перенесені команди виконує сам бінарник; решту він
   передає PowerShell-диспетчеру (один скрипт без param-блоку, що зливає `kit.ps1` і
   `kit-process.ps1`). Обгортки `bin/<команда>` кличуть `kit.exe <команда>`.
3. Передача диспетчеру — не аргументами `pwsh -File`, а точним каналом: JSON-масив рядків у змінній
   оточення `KIT_ARGV`. Диспетчер читає її замість `$args` і одразу прибирає з оточення, щоб її не
   успадкували git, раннер чи 1cv8. stdin, stdout, stderr і код виходу прозорі.
4. Один контракт кодів для всіх команд: `0` так, `1` зупинка, `2` помилка виклику, `3` не
   перевірено, `4` виконано з наступним кроком. Помилка — перший рядок stderr `<команда>: ERROR …`;
   рядок `next:` — лише за детермінованого наступного кроку.
5. Ядро git — модуль у Rust; поза ним Rust-код git не запускає. Хук старту сесії — підкоманда
   `kit.exe`, тож у проєкті без маніфесту й профілю `pwsh` не запускається.
6. Поставка: зібраний `kit.exe` у `bin/` (профіль `release`) комітиться; вбудований відбиток джерел `rust/`
   ловить бінарник, застарілий щодо джерела. Компілятор зафіксовано `rust-toolchain.toml`.
7. PowerShell-код заморожено: лише дефекти й зміни під цей перехід; команди переносяться по групах,
   порядок наступних фаз — окреме рішення.

## Why

Заміри спайку 2026-11-20: те саме завдання (ядро git, порт `session-board`, наявні Pester-тести як
чорна скринька, побайтний паритет git з PowerShell на кириличних і бінарних шляхах) на Go і Rust.
Обидві мови пройшли чорну скриньку й паритет із контролем, що вміє впасти, і обидві знайшли дефект
PowerShell-версії (`session-board -All` падає на detached worktree). Rust змусив обробити відсутню
гілку на етапі компіляції (`Option`). Rust — мова Уніки й раннера, на яких стоїть решта інфраструктури.

Умова виміру: машина під навантаженням 21–52 % CPU, заміри почергово, медіана 10 раундів.

| Вимір | Rust | PowerShell |
|---|---|---|
| Старт `kit --help` | 12 мс | 1 629 мс (процес команди), 2 152 мс (усі модулі) |
| `session-board` | 2,0 с | 4,0 с |
| Бінарник | 0,4 МБ | — |
| Інкрементальна збірка (`dev`) / з нуля (`release`) | 1,1 с / 15 с | — |

Канал передачі аргументів обрано за виміром D1а: `pwsh -File` не зберігає токени, а `KIT_ARGV`
передає JSON-масив без переписування.

## Rejected

- Go — на спайку пройшов перевірки не гірше; Rust змусив обробити відсутню гілку на етапі компіляції,
  і Rust — мова Уніки.
- Лишитись на PowerShell і лікувати старт — вартість старту `pwsh` у кожній сесії не зникає, а дефект
  розщеплення аргументів лишається в обох точках входу.
- Передача аргументів `pwsh -File` — проба показала, що токен `-Apply:false` не зберігається.
- Сумісність зі старими кодами виходу `2`/`3` — два значення одного коду в одному контракті гірші за
  одноразовий перехід усіх споживачів в одному PR.

## Consequences

- Розробнику потрібен тулчейн Rust для тестів. Поставлений `bin/kit.exe` — лише збірка поставки: лінкер
  MSVC `link.exe` і ресурс версії, одним рецептом `tools/build-kit-exe.ps1` — на машині з MSVC або на CI
  (там ще й атестація походження). Збірку `rust-lld` + xwin без ресурсу Defender видаляв як ML-детекцію
  (`docs/research/2026-11-21-defender-kit-exe.md`). Збірку іншої форми ловить запобіжник «збірка поставки»,
  забуте оновлення бінарника — запобіжник відбитку.
- У репозиторії kit `kit` з `PATH` — копія локального маркетплейсу, не дерево розробки: для розробки
  kit викликають бінарник чи `tools/kit.ps1` з дерева.
- Споживачі переходять на форму `kit <команда>` і нові коди через `CHANGELOG.md`, шаблони й скіли.
- Кросплатформна поставка бінарників — поза цим рішенням.
