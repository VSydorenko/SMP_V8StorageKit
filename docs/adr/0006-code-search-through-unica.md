# ADR-0006: Пошук коду 1С — через Уніку; `orient`, `pkg-src` і `codex-audit` не переносяться

Status: accepted 2026-11-19
Decided by: architect
Source: agent-kit 0.9.1 (оригінал, `.agents/private/agent-kit` у ворктрі блоку); окремої спеки немає — рішення власника 2026-11-19

## Context

agent-kit шукає код через `orient` (граф codebase-memory + звірка `git grep`), читає
опублікований код бібліотек через `pkg-src` (npm), а незалежний аудит робить через
`codex-audit` (Linux-внутрішності: `/proc`, групи процесів). Агенти agent-kit не мають MCP.
У 1С пошук і читання коду по логічних адресах дає Уніка (`unica.search`, `unica.view`,
`unica.resolve`); код вендора лежить у дампі конфігурації-власника (`truth: vendor|dump`);
поведінку платформи пояснює `unica:platform-help`. Codex на машині кличе користувацький скіл
`codex-companion` із власним ранбуком.

## Decision

- `orient` не переноситься. Агенти отримують читальні MCP-інструменти Уніки
  (`unica_view`, `unica_search`, `unica_resolve`, `unica_docs`, `unica_check`, `unica_diff`);
  пошук по документах — `doc find`.
- `pkg-src` не переноситься. Правило «поведінку перевіряй у коді закріпленої версії» стає
  «у коді дампу конфігурації-власника цього воркспейсу».
- `codex-audit` не переноситься. Незалежний аудит — скіл `codex-companion`, якщо він є на
  машині; знахідки звіряє той, хто його запустив.

  **Змінено 2026-11-20 (issue #48, рішення власника):** `codex-audit` перенесено як команду процесу
  на PowerShell, без Linux-внутрішностей: процес Codex з тайм-аутом і вбивством дерева процесів через
  .NET, замок на машину — файлом. Скіл — `v8storagekit:codex-audit`; `codex-companion` прибрано.
  Причина: стара обгортка не перевіряла, що Codex прочитав репозиторій, а на Windows без явного
  `windows.sandbox` пісочниця read-only мовчки відмовляє кожному читанню (виміряно на codex-cli 0.170).

## Why

- codebase-memory не має граматики BSL; Уніка вже індексує BSL і метадані.
- Скрипт не може кликати MCP (контракт kit і Уніки); інструмент лишається в агента.

## Rejected

- Перенести `orient` на `git grep` з регулярними виразами `Процедура|Функция` — гірше за
  Уніку й дублює її.

## Consequences

Агенти процесу мають у `tools:` читальні MCP Уніки; мутуючі (`unica_apply`, `unica_run`) —
серед субагентів лише виконавець, і лише в межах брифу. Основна сесія кличе їх у присутності
людини, коли так каже скіл (`task-finish`, кроки, надруковані командою kit).

У `tools:` агента — лише точні імена інструментів (`mcp__plugin_unica_unica__unica_view` тощо),
ніколи ім'я сервера без інструмента. Вимір 2026-11-19 (Claude Code 2.1.328, `claude -p
--plugin-dir`, агент плагіна на haiku): точні імена агент бачить і кличе; `mcp__plugin_unica_unica`
без інструмента дає агенту **всі** інструменти Уніки, включно з `unica_apply` і `unica_run`, тобто
читальний агент тихо отримав би право змінювати вихідники й базу.
