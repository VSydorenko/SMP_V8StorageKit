# ADR-0026: `kit run-tests` — рівні тестів профілю і цільовий прогін за зміною

Status: proposed
Decided by: architect
Spec: docs/superpowers/specs/2026-11-28-rust-phase4-process-design.md §5.8
Supplements: ADR-0020 (простір імен `v8storagekit.tests`)

## Context

Правило «перевірка відповідає зміні» в розробці kit тримає `tools/tests/Run-Tests.ps1` (#88): голий виклик
класифікує зміни від `origin/main` (`tools/tests/lib/TestChanges.psm1`, класифікатор `isCode` agent-kit 0.11) і
відмовляє кодом `3`, коли змінено код без цільового прогону. У проєктах-споживачах цього правила не тримає ніщо:
`sdd` кладе в бриф виконавця сирі команди `tests.levels`, і виконавець сам вирішує, що запускати (#89). agent-kit 0.11
має `run-tests <рівень> --changed`; його вихідного коду на машині розробки немає, тож поля нижче звірено з описом
#89, а не з кодом agent-kit.

## Decision

1. `kit run-tests <рівень> [-Changed] [-Since <ref>] [-Local]` запускає рівень тестів із профілю
   (`tests.levels.<рівень>`, з простором імен ADR-0020) — лише з машинного й проєктного шару; рівень у локальному
   шарі ігнорується з повідомленням, а перед запуском kit друкує argv і шар-джерело. Рівень проєктного шару, що
   відрізняється від перевіреного профілю — `.agents/kit.profile.json` на коміті головної гілки origin, прочитаного
   тією самою функцією, що `pr.afterMerge`, — код `3`, доки не передано `-AllowProfileChange` (прапорець видно в
   запиті дозволу). Код виходу — контракт kit: `0` зелено; `1` команда рівня
   впала; `2` помилка виклику чи профілю; `3` не перевірено (таймаут, замок зайнято, змінено код без цільового
   прогону, рівень `ci` без `-Local`).
2. Рівень: `command` — масив argv без оболонки (рядок — помилка профілю, код `2`, з порадою масиву);
   `args` — хвіст повного прогону; `changedArgs` — хвіст цільового прогону: токен `{files}` розгортається в змінені
   файли коду по аргументу на файл, `{files,}` — в один аргумент через кому (шлях від кореня з `/`); `ci` — повний
   прогін лише з `-Local`; `timeout` — секунди, понад них дерево процесів вбивається і код `3`; `lock` — ім'я замка
   машини (`^[A-Za-z0-9][A-Za-z0-9_-]*$`): файл `.agents/out/locks/<ім'я>.lock` головного checkout, відкритий без
   спільного доступу на весь час процесу `kit.exe`; зайнятий — код `3` без очікування; звільняє ОС, коли процес
   завершується чи його вбито (спека §5.8).
3. `-Changed`: зміни — від `BASE` відкритої задачі `sdd` у цьому checkout (кількох — від того `BASE`, що є
   предком усіх інших; такого немає — код `3`), інакше від `merge-base HEAD origin/<pr.base>`, або від `-Since`. Закомічені, застейджені, незакомічені й нові неігноровані файли,
   перейменування — обидва шляхи. Класифікатор — `isCode` agent-kit 0.11 плюс `tests.codePaths` профілю (префікси,
   де будь-який файл — код; у kit — `tools/`, `rust/`, `bin/`). Змін немає — код `0` без запуску. Лише не код —
   рівень `tests.docsLevel` повним прогоном, якщо задано, інакше код `0` з рядком `PASS 0 (no code changed …)`.
   Є код і `changedArgs` — цільовий прогін; є код без `changedArgs` — код `3`.
4. `sdd brief` кладе в розділ «Команди» `kit run-tests <рівень>` і `kit run-tests <рівень> -Changed` замість сирих
   команд, коли профіль має `tests.levels`.
5. Kit сам — споживач: його профіль має рівень Pester над `Run-Tests.ps1` (повний прогін `-Full`, цільовий — новий
   параметр `-Files`, що бере кандидатів `Get-KitAffectedTestNames`) і `docsLevel` — рівень з новим параметром
   `-Docs` (файли тестів з тегом `Docs`).
6. Поза рішенням: рівні 1С (`syntax`, `yaxunit` — драбина перевірок, ADR-0012), поле `reporter`, `--at`, `--last`,
   `ci.docsOnly` agent-kit.

## Why

- Правило в коді, а не в тексті скіла, однакове в kit і в споживача; виконавець не вирішує сам, що «досить».
- argv без оболонки прибирає цитування й ін'єкцію через значення профілю; рядкова форма була б двозначною.
- Локальний шар гітігнорований: його зміни не видно в git ніколи. Проєктний шар робочого дерева агент теж може
  змінити до виклику, а запит дозволу показує людині лише `kit run-tests <рівень>`, не argv. Звірка з перевіреним
  профілем — одна функція з `pr.afterMerge`, тож друге «джерело правди» про перевірений профіль не з'являється, і
  жодне значення профілю (як `pr.base`) не обирає еталон; прапорець `-AllowProfileChange` робить відхилення видимим
  у запиті. Звірка тримає лише argv: код робочого дерева, який рівень виконує, вона не перевіряє — свідомо.
  Машинний шар — налаштування машини поза репозиторієм, прийнятий ризик.
- `pwsh -File` не збирає кілька токенів після одного параметра-масиву (`[CmdletBinding()]` дає помилку
  позиційного параметра), тож потрібна форма через кому — вона вже діє для `Run-Tests.ps1 -Only`.
- Замок без очікування: чекати незнайомий процес довше за стелю задачі гірше, ніж сказати, що замок зайнято.
- Замок — ексклюзивно відкритий файл, а не тека з PID: Claude Code вбиває дерево процесів на стелі інструмента, і
  замок-тека лишався б без власника; перехоплення такого замка чотири раунди аудиту спеки давало нові гонки. Файл,
  який звільняє ОС, не має ні застарілого стану, ні перехоплення.
- Окремі `args` і `changedArgs`: повний і цільовий прогін часто різняться не лише хвостом файлів (`-Full` проти
  `-Only` у kit).

## Rejected

- Рядок `command` через `cmd /c` чи `bash -c` — залежність від оболонки й цитування.
- `--changed` за замовчуванням — повний прогін тоді неможливо назвати однією формою.
- Чекати зайнятий замок — сесія висить без видимої причини.

## Consequences

- Поля рівня можуть розійтись з agent-kit; спільний профіль двох плагінів розводить секцію `v8storagekit.tests`
  (ADR-0020 п. 3).
- Правил allow для `kit run-tests` немає ні в kit, ні в `templates/settings.json`; змінити це — рішення власника.
