# ADR-0017: Споживачі kit — push гілки задачі й PR без запиту, як у репозиторіях власника

Status: accepted 2026-11-23
Decided by: owner
Spec: docs/superpowers/specs/2026-11-23-onboarding-target-state-design.md §5.3

## Context

`templates/settings.json`, який kit роздає споживачам, тримає `git push` і `gh pr create` у `ask`, а
`templates/CLAUDE.md` каже «`git push`, `gh pr create` — лише за явним проханням». У репозиторіях
`github.com/VSydorenko/*` діє інше правило власника (2026-11-18): сесія сама пушить гілку задачі, створює PR
і зливає його після перевірки й рев'ю; питають лише про force push, переписування історії, реліз і прямий
коміт у `main` без PR. Клієнтські репозиторії (напр. `simplySOFTua/*`) під те правило не підпадали, тож
шаблон був суворіший без рішення. Issue #43.

## Decision

Шаблон споживача працює за тим самим правилом, що й репозиторії власника: push гілки задачі, створення PR і
злиття PR після перевірки й рев'ю — без запиту; force push, переписування історії, реліз і прямий коміт у
головну гілку без PR — з запитом.

## Why

Власник і колеги часто не стежать за сесією й розраховують, що робота не стоїть на підтвердженнях; межа
безпеки — не push гілки, а незворотні дії, і вони лишаються з запитом.

## Rejected

- Push і PR без запиту, злиття лише людиною — дає ще одну точку очікування без захисту, якого не дає рев'ю.
- Лишити як є — суперечить способу роботи власника й колег.

## Consequences

Споживач, підключений раніше, отримує нові дозволи лише через злиття `settings.json` з шаблоном (`kit-setup`,
спека §5.2). Захисні гілки `storage/*` тримають хуки git, а не дозволи (правило 5 `CLAUDE.md` kit).
