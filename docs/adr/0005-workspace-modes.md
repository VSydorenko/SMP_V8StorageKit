# ADR-0005: Два режими робочої копії — спільне дерево (1С) і worktree (лише файли)

Status: accepted 2026-11-19
Decided by: architect
Source: agent-kit 0.9.1 (оригінал, `.agents/private/agent-kit` у ворктрі блоку); окремої спеки немає — рішення власника 2026-11-19

## Context

agent-kit дає кожному блоку власний worktree (`pr-gate start`). У 1С-репозиторії база агента
прив'язана до воркспейсу, а `test`/`push` збирають з робочого дерева. Другий worktree без
власної бази нічого не дає, а власна база — хвилини збирання й місце на диску. Правило
власника для 1С: «без ізоляції worktree, без паралельних імплементаторів, що самі
білдять/тестують». Репозиторій самого плагіна бази не має і вже працює з worktree
(`<repo>-wt-*`).

## Decision

Профіль задає `workspace.mode`:

- `shared` — типово для 1С: одна робоча копія, одна база агента; один виконавець, що
  збирає чи тестує, у кожен момент; коміти — точкові (`git add <перелік>` +
  `git commit --only`); команди, що відкидають зміни, заборонені завжди.
- `worktree` — для репозиторіїв без бази: блок отримує worktree через `pr-gate start`.

Гіпотеза для окремого виміру (не входить у цю спеку): worktree з власною копією бази агента
(`--infobase`, копіювання бази раннером).

## Why

- Ізоляція без власної бази — фікція: прогін бачить дерево, а не гілку.
- Режим — властивість репозиторію, а не сесії: його читає і сторож git, і `run-tests`.

## Rejected

- Лише worktree — у 1С потребує бази на кожну копію.
- Лише спільне дерево — втрачає ізоляцію там, де вона безкоштовна.

## Consequences

У режимі `shared` паралельні сесії можливі лише на різних воркспейсах або на роботі без
збирання (документи, план, рецензія).
